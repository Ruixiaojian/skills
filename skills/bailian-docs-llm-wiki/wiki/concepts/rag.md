# 检索增强生成

检索增强生成（Retrieval-Augmented Generation，RAG）是一种将大语言模型（LLM）的生成能力与外部知识源的精准检索能力深度融合的技术范式。它通过在模型推理前动态检索相关上下文片段，并将其作为提示的一部分注入生成过程，从而显著提升回答的事实准确性、领域专业性与可追溯性，同时降低幻觉风险。

## 在百炼平台的不同场景中，这个概念如何使用

在百炼平台中，RAG 不是抽象概念，而是已深度产品化的端到端能力，贯穿知识管理、应用构建与效果评估全链路：

- **知识库（Knowledge Base）**：是 RAG 的核心基础设施。开发者上传私有文档（PDF/DOCX/TXT/图片等），平台自动完成解析、智能切分、向量化与索引构建；后续所有 RAG 调用均基于该结构化知识底座进行。
- **知识检索（`/search`）与知识问答（`/chat`）API**：提供开箱即用的 RAG 服务接口。`/search` 返回原始语义匹配的文本切片（chunk），供开发者自定义下游逻辑；`/chat` 则封装完整 RAG 流程（检索 → 重排 → 规划 → 生成），直接返回带引用溯源的自然语言回答，支持流式响应。
- **智能体（Agent）与工作流应用**：可在应用配置中直接绑定一个或多个知识库，启用 RAG 增强。平台自动处理多轮对话中的指代消解与查询改写，使模型在生成时始终“看得见”最新、最相关的私域知识。
- **框架集成（LlamaIndex / Spring AI Alibaba）**：提供标准化 SDK，让 Python 或 Java 开发者无需重复造轮子，即可将百炼知识库无缝接入本地 RAG 应用，复用其向量检索、重排与生成能力。
- **应用评测（Application Evaluation）**：支持对 RAG 效果进行归因分析，自动识别 BadCase 类型（如“检索无效”“切片不完整”“生成未引用”），并给出针对性调优建议，形成“构建 → 部署 → 评测 → 优化”的闭环。

## 关键参数和配置

RAG 效果高度依赖以下可调参数，需根据业务精度与性能要求权衡设置：

| 参数名 | 作用 | 典型取值范围 | 配置位置 | 说明 |
|--------|------|--------------|----------|------|
| `top_k`（召回数） | 控制最终送入大模型的上下文片段数量 | `1–20`（默认 `3` 或 `5`） | `/search` 请求体、知识库配置页、AppFlow 节点、LlamaIndex `similarity_top_k` | 值过小易遗漏关键信息，过大增加 [Token](token.md) 消耗与噪声干扰；复杂任务（如对比、总结）建议设为 `5–10`。 |
| `similarity_threshold`（相似度阈值） | 过滤低相关性检索结果 | `0.01–1.0`（默认 `0.4` 左右） | 知识库配置页、AppFlow 节点、LlamaIndex `similarity_cutoff` | 值过高导致召回不足，过低引入无关噪声；建议通过真实 query 测试命中率后确定。 |
| `retrieval_top_k`（初步召回数） | 控制向量/关键词初检阶段返回的切片数（影响 Rerank 费用） | `1–100` | 知识库高级设置页 | 此值决定 Rerank 模型调用量，直接影响费用；通常设为 `top_k × 2–5` 以保障重排质量。 |
| `metadata` / 标签过滤 | 结构化约束检索范围（如按部门、产品线、时间范围筛选） | 自定义键值对 | 创建知识库时配置元数据 Schema，上传文件时打标 | 是解决“召回不相关”的最有效手段，优于纯语义匹配。 |
| 多轮对话改写 | 自动补全用户 query 中的指代与省略（如“它”“上一个问题”） | 开/关 | 知识库索引设置中启用 | 对话类应用强烈推荐开启，显著提升多轮检索准确率。 |

> ⚠️ 注意：百炼 RAG 服务**不暴露底层嵌入模型或重排模型名称**，也**不支持自定义切分规则或本地嵌入模型**。所有向量化、检索、重排均由平台统一调度优化，开发者只需关注业务参数与知识质量。

## 面向开发者，简洁实用

- ✅ **快速启动**：控制台创建知识库 → 上传文档 → 发布 → 调用 `/chat` 接口，5 分钟内跑通端到端 RAG。
- ✅ **灵活集成**：  
  - 直接 API：用 `workspaceId` + `API Key` 调用 `/api/v2/apps/knowledge/chat`；  
  - 框架接入：Python 用 LlamaIndex，Java 用 Spring AI Alibaba，一行代码接入云端知识库；  
  - 应用编排：在智能体/工作流中拖入“知识库”节点，配置 `top_k` 和 `similarity_threshold` 即可。
- ✅ **效果可测可控**：用 Application Evaluation 自动生成评测集，定位是“检索弱”还是“生成差”，再针对性调整 `top_k` 或优化文档切分质量。
- ❌ **避免踩坑**：  
  - 不要尝试传入 `model` 字段到 `/chat` 接口——模型由平台隐式调度；  
  - 不要忽略地域限制——所有知识库与 RAG API 仅支持 `cn-beijing`；  
  - 不要跳过元数据配置——它是精准召回的基石，比调参更治本。
