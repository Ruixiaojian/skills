# 检索增强生成（RAG）

检索增强生成（Retrieval-Augmented Generation，RAG）是一种在大模型生成回答前，先从外部知识源中检索相关内容并注入上下文的技术，用于为大模型补充私有数据和最新信息，从而提升特定领域问答的准确性和可靠性。

## 工作原理

百炼平台上的 RAG 流程分为三个核心阶段：

1. **建立索引**：对文档进行解析、切片与向量化处理，将内容转换为可检索的向量表示。
2. **检索召回**：根据用户查询，从向量存储中匹配并召回语义相关的知识片段。即使查询关键词与实际答案完全不同，语义检索也能找到相关内容。
3. **生成答案**：大模型根据召回的知识片段和用户查询，综合生成最终回答。

可选地，在检索与生成之间可插入 **Rerank（文本排序）** 步骤，对召回结果进行二次精排，进一步提升准确率。

## 在百炼平台中的使用场景

### 知识库（云端 RAG）

知识库是百炼平台基于 RAG 技术的核心组件。开发者通过控制台上传文档，平台自动完成解析、切片、向量化。知识库支持多种类型：文档搜索（基础问答、图文回复、视觉理解、极速问答）、数据查询、图片问答、音视频搜索。

集成方式包括：
- **智能体应用**：在应用配置中关联知识库。Agent 2.0 中知识库作为工具由智能体自主规划调用；Agent 1.0 中知识库检索先行。
- **工作流应用**：通过「知识库」节点集成，支持固定选择或动态引入。
- **API 调用**：通过百炼 SDK 调用 `Retrieve` 接口直接检索知识库。

### 本地 RAG

开发者也可基于本地文件系统构建 RAG 应用，通过 Python 环境 + LlamaIndex 框架实现。与云端 RAG 相比，本地 RAG 支持自定义切分策略和嵌入模型，适合需要灵活控制检索流程的场景。

### 框架集成

- **LlamaIndex（Python）**：通过 `DashScopeCloudIndex` 创建云端知识库，`DashScopeRerank` 进行语义重排，构建完整 RAG 流水线。
- **Spring AI Alibaba（Java）**：通过 `DashScopeDocumentRetriever` 检索百炼知识库，结合 `DocumentRetrievalAdvisor` 自动将检索结果注入模型上下文。

## 关键参数与配置

### 索引阶段（创建时设定，不可更改）

| 参数 | 说明 |
|------|------|
| **切片方式** | 推荐「智能切分」，基于语义相关性自适应切分；也可选「按长度切分」 |
| **向量模型（Embedding）** | 文档类支持 `text-embedding-v4`（推荐）/ `v3`（512 维）；图片类使用 `multimodal-embedding-v1`（1024 维） |
| **Meta 信息抽取** | 为切片附加元数据（常量、变量、大模型提取、正则、关键词），提升检索精度 |
| **[多轮对话](multi-turn-conversation.md)改写** | 根据历史对话自动补全用户查询，创建后不可追加开启 |

> **注意**：切片方式、向量模型和 Meta 信息抽取在知识库创建后**无法更改**，请在创建时慎重配置。

### 检索阶段（可动态调整）

| 参数 | 说明 |
|------|------|
| **相似度阈值** | 仅语义相似度高于此阈值的切片才会被召回，设置过高会丢弃相关内容。为 0 时不做剔除 |
| **召回片段数（TopK）** | 最终返回的切片数量，上限 20。增大可提升回答完整性，但增加 Token 消耗和成本 |
| **权重** | 多知识库场景下按重要程度分配，仅在同类型知识库之间生效 |
| **标签过滤** | 通过文件标签在向量检索前筛选目标文件，缩小检索范围 |

### 排序阶段（可选）

通过 Rerank 模型对检索结果进行二次精排：

| 参数 | 说明 |
|------|------|
| **top_n** | 重排后返回前 N 个文档 |
| **return_documents** | 是否返回文档原文，默认 `false` |
| **instruct** | 自定义排序策略（仅 `qwen3-rerank` 支持） |

推荐使用 `qwen3-rerank` 模型（文本场景）或 `qwen3-vl-rerank`（跨模态场景）。

### 生成阶段

| 参数 | 说明 |
|------|------|
| **temperature** | 控制生成随机性，数值越高随机性越强 |
| **最长回复长度** | 模型生成的 Token 长度限制 |
| **携带上下文轮数** | [多轮对话](multi-turn-conversation.md)中参考的历史对话轮数 |
