# 工具集成

工具集成是百炼平台中将外部能力（如 API、脚本、服务）安全、可控地接入大模型推理链路的核心机制，使模型能突破自身能力边界，执行代码、搜索信息、生成图像、操作文件或调用业务系统。它不改变模型本身，而是通过标准化协议与运行时沙箱，在推理过程中动态调度外部工具并结构化处理其输入/输出。

## 在百炼平台的不同场景中，这个概念如何使用

工具集成在百炼中并非单一技术，而是覆盖多种抽象层级和运行模式的统一能力范式，按使用方式可分为三类：

- **插件（Plug-in）**：面向轻量、原子化能力（如计算器、网页搜索、二维码生成），以声明式 `tools` 数组注入 Assistant API 或智能体应用。调用由大模型自主规划（`auto` 模式）或显式指定（`specific` 模式），适用于实时性要求高、输入输出结构简单的场景。  
- **Skill**：面向端到端任务流程（如“解析 PDF 表格”“清洗 CSV 数据”），以 ZIP 包封装完整逻辑（含 `SKILL.md` 描述 + Python 脚本）。由智能体根据自然语言描述语义匹配触发，强调复用性与开箱即用，适合需多步协调、依赖本地文件或私有格式的业务能力。  
- **MCP（Model Context Protocol）服务**：面向标准化、可扩展的外部系统集成（如地图、天气、数据库），基于 Streamable HTTP 协议对接远程服务。支持智能体自动调用或工作流显式编排，适用于需要长期维护、多租户隔离、或对接阿里云/三方 OpenAPI 的生产级集成。

此外，**Managed Agents** 提供内置工具集（`bash`、`read`、`download_file` 等）与沙箱环境，本质是平台托管的“原生工具集成运行时”，所有工具均在隔离容器中执行，天然支持文件挂载、依赖安装与状态保持，适合长时、多步、需上下文延续的复杂任务。

> ✅ 关键区别：  
> - 插件 → 原子能力，模型驱动，控制台/API 快速启用；  
> - Skill → 任务能力，语义触发，ZIP 包交付，强业务定制；  
> - MCP → 协议标准，服务对接，支持自建/官方/三方，适合跨系统集成；  
> - Managed Agents 内置工具 → 运行时能力，沙箱保障，无需部署即用。

## 关键参数和配置

工具集成的通用配置要素如下（具体字段依类型略有差异）：

| 类别 | 参数名 | 说明 | 开发者须知 |
|--------|---------|------|-------------|
| **标识与发现** | `tool_id` / `name` / `service_id` | 工具全局唯一标识符，用于请求中引用 | 必须从控制台复制或严格按文档命名（如 `calculator`、`invoice-parser`），大小写敏感，仅允许小写字母、数字、连字符 |
| **能力定义** | `description`（必填） | 自然语言描述，明确输入类型、支持操作、典型触发词及**排除场景** | 直接影响模型是否调用——避免模糊表述（如“处理数据”），应写为：“解析用户上传的 PDF 文件，提取表格内容并返回 Excel 格式；不支持扫描件或图片型 PDF” |
| **输入控制** | `parameters`（JSON Schema） | 定义工具所需参数名、类型（`string`/`number`/`boolean`/`object`）、是否必填 | `object` 类型下所有子属性必须显式声明（不可为空），否则发布失败（错误码 130022）；业务透传参数请通过 `biz_params` 注入 |
| **输出提取** | `output_parameters`（数组） | 指定 API 返回 JSON 中需提取并送入模型上下文的字段路径（如 `["result.data", "summary"]`） | 所有字段均为必填项，路径需精确，层级尽量扁平；未声明字段不会进入上下文 |
| **鉴权与安全** | `auth.type` + `auth.token` / `env` | 鉴权方式（`bearer`/`basic`/`appcode`）及凭证；或环境变量（如 `{"AMAP_MAPS_API_KEY": "xxx"}`） | 敏感 [Token](token.md) **禁止硬编码**，应通过 KMS 凭据或 `biz_params` 动态注入；自定义插件/MCP 服务需配置 Header 或 Query 位置 |
| **运行约束** | `tools` 数组（API 请求体） / `tools` 配置（Agent 创建） | 显式声明本次会话可用的工具列表 | 智能体模式最多 10 个工具；工作流无数量限制但需手动编排；空数组表示禁用全部工具 |

## 面向开发者，简洁实用

- ✅ **快速验证**：优先用控制台「插件市场」或「MCP 广场」添加官方工具，5 分钟完成测试；Skill 上传 ZIP 后对话窗实时生效，无需部署。  
- ✅ **调试要点**：  
  - 若工具未被调用 → 检查 `description` 是否匹配用户输入语义，或 `parameters` 是否缺失必填项；  
  - 若调用失败 → 查看 `tool_output` 事件中的错误详情，确认网络可达性、鉴权凭证有效性、参数类型/格式是否合规；  
  - 若结果未进入上下文 → 核对 `output_parameters` 字段路径是否准确，响应体是否含对应 key。  
- ✅ **生产建议**：  
  - 复杂业务逻辑优先封装为 Skill（ZIP 包），便于版本管理与灰度升级；  
  - 对接外部 SaaS 或内部微服务，首选 MCP（Streamable HTTP），协议稳定、可观测性强；  
  - 需沙箱执行、文件读写、多轮状态保持的任务，直接选用 Managed Agents 并启用内置工具；  
  - 所有工具上线前，务必通过「测试工具」功能验证成功，草稿状态无法调用。  
- ⚠️ **避坑提醒**：  
  - `enable_search` 是模型参数，非插件，勿与 `quark_search` 混淆；  
  - 官方插件仅支持同业务空间内关联，跨空间需走 MCP；  
  - MCP 自定义服务无固定公网 IP，访问 VPC 内资源需配置白名单或 VPC 打通；  
  - Tool 输出内容计入输入 [Token](token.md)，响应过大将显著增加计费成本，请精简 `output_parameters`。
