# 地域与可用性限制

阿里云百炼平台按"地域（Region）"隔离资源、配额与功能可用性。地域是百炼资源调度与计费的基本单位，决定了某项能力是否可用、调用端点的域名、业务空间（Workspace）归属，以及账号、API Key、模型部署、数据集等资源能否被访问。**绝大多数高级能力（模型调优、模型部署、模型数据、Prompt 工程、应用调用 API 等）目前仅在"中国大陆版（北京地域）"开放**；其他地域（如新加坡、德国法兰克福、日本东京等）通常仅支持基础推理调用，调用方式与凭证要求以对应地域文档为准。

## 在百炼平台的核心约束

### 1. 大量功能仅限"中国大陆版（北京地域）"

下列功能在跨地域使用时会**直接不可用**或返回错误：

| 子系统 | 受限范围 | 说明 |
| --- | --- | --- |
| Prompt 工程 | 预置/自定义模板、自动优化、样例库、反馈优化 | 整套 Prompt 工具链仅在北京地域生效 |
| 应用调用 API | DashScope `apps/{APP_ID}/completion`、OpenAI 兼容 Responses API | 其他地域需走当地端点与文档 |
| 模型调优（fine-tuning） | CPT / SFT / DPO 文本调优，VL、万相图/视频、CosyVoice 多模态调优 | 所有训练任务仅在北京地域；产出模型不支持下载 |
| 模型部署（PTU / MU / Token 用量 / cu） | 全部三种计费方式 + 自定义 LoRA 导入 | 仅"中国内地（北京）"地域 |
| 模型数据 | 训练集、评测集、数据清洗、数据增强 | 仅北京地域 |

> 这些功能在控制台和 API 上都遵循同一规则：选择/切换到非北京地域后，相关入口会隐藏或调用失败。

### 2. 业务空间（Workspace）受地域绑定

- 单个业务空间**不能跨地域存在**，业务空间按地理区域划分。
- 切换地域 = 切换可见的业务空间集合，模型清单、限流配额、API Key 都会随之变化。
- API Key 与业务空间一一绑定：**单个 API Key 只能归属一个地域内的一个业务空间和一个用户**，无法转移。在 A 地域创建的 API Key 不能用于 B 地域的服务。
- 自 2026 年 3 月 25 日起，**华北 2（北京）地域**所有新创建的 API Key 均归属主账号。

### 3. 调用端点（Endpoint）随地域不同

- 中国大陆版统一使用 `dashscope.aliyuncs.com` 域名（应用调用、模型调优、模型部署、MCP 等接口均挂在该域名下）。
- 国际版（新加坡 / 德国法兰克福等）使用对应的地域域名与文档；调用时请以对应地域的 API 参考为准，不要硬编码中国大陆域名。

### 4. Workspace ID 在跨地域时变为强约束

调用应用 API 时：

- 应用位于**默认业务空间**且为中国大陆地域，可不传 `Workspace ID`。
- 应用位于**子业务空间**，或调用**德国（法兰克福）地域**下的模型时，请求中**必须**携带 `Workspace ID`。

否则会因找不到资源或权限不匹配而调用失败。

## 关键配置与参数

### 凭证 / 标识类

| 参数 | 作用 | 地域相关性 |
| --- | --- | --- |
| `DASHSCOPE_API_KEY` | 鉴权 | 与所在地域的业务空间绑定，不可跨地域使用 |
| `APP_ID` | 应用唯一标识 | 仅在创建该应用的地域可用 |
| `Workspace ID` | 业务空间标识 | 跨业务空间或调用法兰克福地域模型时必填 |

### 部署 / 调优 / 数据类

- **模型部署**：PTU / MU / Token 用量 / cu 四种计费方式均**仅北京地域**，且创建后无法更改计费方式。
- **自定义 LoRA 模型导入**：OSS Bucket 与百炼平台应在可访问的同区域（北京）规划，Bucket 不能为归档/冷归档存储类型，需添加标签 `bailian-datahub-access=read`。
- **模型调优任务**：所有训练任务在北京地域提交；产出的模型**不支持下载**，只能在同地域部署或调用。

### 应用功能开关

- **MCP 服务**：MCP 接入地址 `https://dashscope.aliyuncs.com/api/v1/mcps/<service-name>/mcp` 与百炼应用绑定，遵循应用所在地域规则；外部调用同样需要使用对应地域的 API Key。
- **Prompt 样例库 / 反馈优化 / 自动优化**：整套能力仅在北京地域控制台和 API 中暴露。

## 给开发者的实践建议

1. **新接入项目优先选择"中国大陆版（北京）"地域**，以避免高级功能（调优、部署、Prompt 工程、模型数据等）不可用造成的返工。
2. **环境变量 / 配置文件中显式标注地域**（如 `BAILIAN_REGION=cn-beijing`），避免不同环境复用同一 API Key 时调错端点。
3. **多业务空间或跨地域调用时始终传 `Workspace ID`**，作为防御性默认值，可降低后续迁移成本。
4. **API Key 治理按"地域 × 业务空间 × 用户"三维管理**，不要尝试复用跨地域的 Key；账号被移出业务空间后对应 Key 立即失效。
5. **资源（OSS、数据库、网络）尽量与百炼部署所在地域同区**，自定义 MCP 与模型部署托管在函数计算上、无固定出口 IP，跨地域访问需提前规划 VPC 打通或 IP 白名单。
6. **国际地域只做基础推理调用**，调优、部署、模型数据等需求请回到北京地域执行；调用代码中按地域分支处理端点和必填字段差异。
