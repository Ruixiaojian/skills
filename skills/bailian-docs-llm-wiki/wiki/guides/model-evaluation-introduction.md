# model evaluation introduction

模型评测是百炼平台提供的模型能力量化评估功能，支持通过自定义或基线方式对文本生成类模型的推理结果进行多维度打分与对比。它覆盖从模型选型、调优验证到持续质量监控的全生命周期场景，核心能力包括 AI 自动评分、规则指标计算和人工标注三种评估范式。所有评测均需基于明确的评分标准（即评测维度）执行，且当前仅支持文本生成类模型。

## 支持的模型与功能

- **支持模型类型**：仅限文本生成类模型（如 Qwen 系列、Llama 等），不支持多模态、语音或结构化输出模型。预置模型与已调优模型均可作为被评测对象，详见[预置模型列表](https://help.aliyun.com/zh/model-studio/model-deployment-introduction)。  
- **核心功能**：  
  - **自定义评测**：用户上传评测数据集（EvaluationSet 类型）或提供推理结果集，自主创建评测维度并关联执行；支持排行榜横向对比。  
  - **基线评测**：使用平台预置公开数据集（如 C-Eval、GSM8K、BBH）快速获取基础能力基准分，但**仅北京地域可用**，且不支持结果下载与维度配置 [模型评测产品概览](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。  
- **评估范式**：  
  - *大模型评估*（AI 自动评分）：依赖裁判模型（如千问-Max）进行语义级判断，支持数值型（0–5 分）与分类型（Pass/Fail）输出；  
  - *规则评估*（无裁判模型）：基于算法（ROUGE/BLEU/Cosine/字符串匹配）计算确定性指标，适用于翻译、摘要、Function Calling 等场景；  
  - *人工评估*：由人工逐条标注，适用于创意写作、合规审核等主观性强的任务 [评测维度](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md)。

> **注意**：文档 1 中称“基线评测仅北京地域可用”，而文档 2 未提及地域限制，但未否定该约束。以文档 1 为准，此为平台实际部署限制，非过时信息。

## 关键参数

| 参数类别 | 参数名 | 说明 | 必填性 | 取值示例 |
|----------|--------|------|--------|----------|
| **评测维度** | 维度类型 | 决定评估方式，创建后不可修改 | 是 | `大模型评估-数值型`、`规则评估-字符串匹配` |
| | 裁判模型 | 仅大模型评估类型需指定 | 大模型类型必填 | `qwen-max` |
| | 评分器 Prompt | 指导裁判模型打分的提示词，须含 `${prompt}`/`${output}`/`${completion}` 至少一个变量 | 大模型类型必填 | `"请评估${output}是否准确回答${prompt}，参考${completion}，仅输出0-5整数"` |
| | 评分范围 | 数值型维度的最小/最大分值 | 数值型必填 | `0–5`（整数） |
| | 通过阈值 | 判定 Pass 的最低分（数值型）或相似度（规则型） | 数值型/相似度型必填 | `3.0`（步长 0.1）、`0.75`（步长 0.01） |
| **评测任务** | 数据来源 | 决定是否触发被评测模型推理 | 是 | `评测数据集`（产生推理费）或 `推理结果集`（无推理费） |
| | System Prompt | 作用于被评测模型的角色设定，非评分器 Prompt | 否 | 通常留空 |
| | 排行榜绑定 | 开启后需指定已创建的排行榜，且该排行榜必须绑定相同维度 | 参与排行时必填 | — |

## 使用方式

1. **准备数据**：在数据管理模块上传 `EvaluationSet` 类型数据集（含 `Prompt` 和 `Completion` 列），或整理含 `Prompt`/`Output`/`Completion` 的推理结果集 CSV 文件。  
2. **创建维度**：在控制台「模型评测 > 评测维度」中创建至少一个维度模板。推荐先用预置模板（如“综合评测”）快速验证，再按需自定义 Prompt [评测维度](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md)。  
3. **创建任务**：在「评测任务」页选择「自定义评测」，关联目标模型、数据源及已创建维度；若需对比，开启「参与排行」并选择对应排行榜。  
4. **查看结果**：任务状态变为「评测完成」后，在详情页的「指标统计」Tab 查看综合得分、通过率与分数分布；「数据明细」Tab 查看每条样本的逐项评分。  

> **注意**：文档 1 明确指出“模型评测当前仅支持控制台操作，不提供公开 API/SDK”，而文档 2 未提及其接口能力。因此自动化集成需依赖 PAI Judge Model API 等替代方案，此为功能现状，非矛盾信息。

## 限制和注意事项

- **地域限制**：基线评测功能仅在北京地域可用，其他地域控制台不显示该选项，属正常行为 [模型评测产品概览](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。  
- **模型限制**：仅支持文本生成类模型；多模态、语音、代码生成等模型暂不支持。  
- **维度不可变**：评测维度类型创建后不可修改，选错需删除重建；已关联任务不受影响，但排行榜绑定维度为空将阻止新任务提交。  
- **费用说明**：  
  - 使用 `评测数据集` 作为数据源时，产生被评测模型的推理费用；  
  - 大模型评估维度（数值型/分类型）额外产生裁判模型评分费用；  
  - 规则评估与人工评估无裁判模型费用，成本更低。  
- **数据量建议**：小规模验证用 50–100 条，正式评测建议 200–500 条，全面评估可超 500 条。  
- **结果解读**：避免仅依赖综合得分——需结合分数分布图识别维度短板；1–3% 的分差通常属评测噪声，不宜作为决策依据。
