# model evaluation introduction

模型评测是百炼平台提供的模型能力量化评估功能，支持通过自定义或基线方式对文本生成类模型进行多维度打分与横向对比。它覆盖从数据准备、维度配置、任务执行到结果分析的完整闭环，适用于模型选型、调优验证、能力归因和持续质量监控等核心场景。该功能当前仅支持文本生成类模型，不支持多模态或语音类模型。

## 支持的模型/功能

- **被评测模型**：支持所有百炼平台预置模型及用户调优后的模型（如 Qwen-Max、Qwen-Plus 等），具体列表见[预置模型列表](https://help.aliyun.com/zh/model-studio/model-deployment-introduction)；已部署的调优模型评测不额外收取推理费用，费用已包含在部署算力中。  
- **裁判模型**：大模型评估维度依赖裁判模型（推荐千问-Max）进行语义评分，支持数值型（0–5 整数分）与分类型（Pass/Fail）输出；规则评估与人工评估不调用裁判模型。  
- **评测范式**：  
  - **自定义评测**：完全由用户控制——可上传自有评测数据集（EvaluationSet 类型）、自定义评分维度（5 种类型）、选择数据来源（评测数据集 or 推理结果集）；支持结果下载与排行榜集成。  
  - **基线评测**：仅限北京地域可用，使用平台预设公开数据集（如 C-Eval、GSM8K、BBH），系统自动完成评分，不支持维度配置、结果下载或人工标注；详见[创建基线评测任务](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。  
> **注意**：文档 1 中称“基线评测仅北京地域可用”，而文档 2 未提及地域限制，此处以文档 1 的明确声明为准。

## 关键参数

| 参数类别 | 参数名 | 说明 | 约束与建议 |
|----------|--------|------|------------|
| **通用** | 维度名称 | 评测维度模板标识符 | ≤20 字符；建议采用“评估方面+评估方式”命名，如`回答准确性-LLM评分` |
| | 描述 | 补充说明 | ≤100 字符，非必填 |
| **大模型评估** | 裁判模型 | 执行评分的 LLM | 必填；推荐千问-Max，推理能力强；费用按 [Token](../concepts/token.md) 计费 |
| | 评分器 Prompt | 指导裁判模型打分的提示词 | 必含至少一个变量：`${prompt}`、`${output}` 或 `${completion}`；≤50000 字符；详见[配置评分器Prompt](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md) |
| | 评分范围（数值型） | 裁判模型输出整数分区间 | 如 `0–5`，最小值 ≥0，最大值 ≥1；范围过宽（如 >10）会降低评分一致性 |
| | 通过阈值 | 判定 Pass 的最低分（数值型）或相似度（规则型） | 步长 0.1（数值型）或 0.01（相似度型）；默认 3.0，需结合业务容忍度设定 |
| | Pass/Fail 标签（分类型） | 分类判定标签 | 互斥且穷尽；不可重复；各标签 ≤20 字符 |
| **规则评估** | 匹配规则 / 相似度算法 | 字符串匹配（相等/不相等/包含）或算法（ROUGE/BLEU/Cosine 等） | 7 种算法按场景选择：翻译用 BLEU，摘要用 ROUGE-L，语义相关用 Cosine |

## 使用方式

1. **前置准备**：  
   - 开通百炼账号并访问[模型评测控制台](https://bailian.console.aliyun.com/#/efm/model_evaluate/task/creation)；  
   - 在**数据管理模块**上传评测数据集（类型为 `EvaluationSet`，须含 `Prompt` 和 `Completion` 两列），并发布版本；  

2. **创建评测维度**（必选）：  
   - 进入**评测维度** Tab → **创建评测维度**；  
   - 选择类型（5 种之一），按类型填写专属参数（如裁判模型、评分范围、匹配规则等）；  
   - 维度类型创建后不可修改，选错需删除重建（已有任务引用不受影响）；详情参见[评测维度](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md)；  

3. **创建评测任务**：  
   - 进入**评测任务** Tab → **创建评测任务**；  
   - 选择**自定义评测**（或北京地域的**基线评测**）；  
   - 配置：  
     - *被评测模型*：从列表选择；  
     - *数据来源*：选 `评测数据集`（产生推理费用）或 `推理结果集`（零推理费用，需已含 `Output` 列）；  
     - *关联维度*：至少选择 1 个已创建维度；  
     - *System Prompt*：为被测模型设定角色（通常留空）；  
   - 提交后状态流转为：待执行 → 进行中 → 评测完成/失败/终止；  

4. **查看与分析结果**：  
   - 任务完成后，进入详情页 → **指标统计** Tab 查看综合得分、通过率、分数分布；  
   - **数据明细** Tab 查看每条样本的 `Prompt`、`Output`、`Completion` 及各维度评分；  
   - 建议关注分数分布而非仅综合得分，避免掩盖维度间差异；微小分差（1–3%）多属评测噪声，不宜作为决策依据。

## 限制和注意事项

- **模型限制**：仅支持文本生成类模型，不支持图像、语音、多模态模型；基线评测仅在北京地域可用，其他地域控制台不显示该选项。  
- **维度限制**：维度类型创建后不可更改；已被排行榜绑定的维度删除后，将导致排行榜无法新建任务（绑定维度为空）。  
- **数据要求**：  
  - 评测数据集必须为 `EvaluationSet` 类型且已发布版本；训练集不可用于评测；  
  - 数据量建议：小规模验证 50–100 条，正式评测 200–500 条，全面评估 ≥500 条；  
- **费用说明**：  
  - 费用 = 被评测模型推理费 + 裁判模型评分费（仅大模型评估维度产生）；  
  - 规则评估与人工评估无裁判模型费用；使用推理结果集可规避被评测模型推理费；  
  - 成本优化策略：先小规模验证配置、复用推理结果集、优先选用规则评估；  
- **API 支持**：当前模型评测功能**仅支持控制台操作，不提供公开 API/SDK**；如需编程化评测，可参考 PAI Judge Model API 替代；详见[常见问题](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。
