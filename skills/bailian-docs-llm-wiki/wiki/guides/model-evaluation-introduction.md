# model evaluation introduction

模型评测是百炼平台提供的模型质量验证功能，支持基于数据集对模型进行多维度评测，帮助开发者全面了解模型表现。通过评测，开发者可以从候选模型中选出最优者、检验调优效果、以及预防模型输出中的潜在风险。该功能目前仅适用于中国大陆版（北京地域）。

## 适用场景

根据[模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)文档，模型评测主要解决以下三类问题：

- **模型选型**：在多个可用模型中快速对比表现，确定最适合特定业务需求的模型。
- **调优验证**：检验模型调优和迭代后的能力变化，依据评测结果调整后续调优策略。
- **风险预防**：提前发现模型可能产生的政治敏感、违法犯罪、歧视偏见等风险，并采取过滤、屏蔽等措施规避。

## 支持的模型

评测功能支持以下预置模型及基于它们调优后的模型：

| 模型系列 | 具体型号 |
|---------|---------|
| 通义千问商业版 | QwQ / Max / Plus / Turbo / Coder / Math |
| 通义千问开源版 | Qwen3、Qwen2.5、Qwen2、Qwen1.5 |
| 垂直领域 | 通义法睿 |
| 第三方模型 | abab6.5g、abab6.5t 等 |

> **注意**：上述列表可能随时变化，请以[创建评测任务](https://bailian.console.aliyun.com/?tab=model#/efm/model_evaluate/task/creation)页面中**评测模型**的实际列表为准。灰色字体且无"申请"按钮的模型暂不支持评测。

## 评测方式

百炼提供两种评测方式，详见[模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)原文：

### 自定义评测

通过用户定义的评测维度，将模型输出与预设答案对照评估。支持两种执行模式：

| 模式 | 说明 | 优势 | 局限 |
|------|------|------|------|
| **人工评估** | 评分员（本人或业务专家）人工评价模型输出 | 可验证输出中每个细节和步骤的正确性 | 成本高、效率低，多人评测易受主观干扰 |
| **自动评估** | 系统基于评测维度自动评分，无需人工参与 | 高效且公正 | 依赖初始设定的维度和标准，无法验证细节 |

### 基线评测

基于预置的主流榜单评测集（C-Eval、CMMLU 等）对模型基础通用能力进行自动评测。主要用于调优后的回归测试——确保调优提升特定任务效果的同时，模型通用能力没有明显下降。

> **最佳实践**：先通过人工评估确定评测维度和评分标准，再将其应用于自动评估快速筛选候选模型，最后用人工评估对比细微差异。如做过领域调优，建议同时进行基线评测。

## 评测维度类型

自定义评测支持以下几类评测维度：

### 自动评估维度

- **大模型评估 - 分类型**：裁判模型对输出进行分类判断（Pass/Fail）。适用于评测维度明确但难以量化的开放任务，如安全合规检查。需配置 Prompt 模板和标签映射，支持 `${prompt}`、`${completion}`、`${output}` 变量注入。
- **大模型评估 - 数值型**：裁判模型按预设标准打分（如 1-3 分），根据阈值判定通过/未通过。适用于客观评分任务，如事实准确性评估。
- **规则评估 - 字符串匹配**：通过相等、不相等、包含、开头/结尾包含等规则判断对错。适用于 Function Calling 精准度、NL2SQL 等答案固定的场景。
- **规则评估 - 文本相似度**：支持 ROUGE-L、BLEU、Cosine、Fuzzy Match、Accuracy 等算法，适用于文本摘要、机器翻译、开放问答等场景。

### 人工评估维度

- **人工评估 - 分类型**：评分员对每条样本手动打标签（如优秀/良好/不达标），适用于评价创意性、幽默感等难以自动量化的主观能力。

## 关键参数与配置

创建自定义评测任务时需关注以下配置项：

- **评测模型**：选择参评模型，配置 System Prompt 和推理参数（`top_p`、`temperature` 等）。
- **数据来源**：支持两种类型：
  - **评测数据集**：参评模型基于数据集在线推理后评分。
  - **推理结果集**：直接上传模型推理结果，跳过在线推理步骤，可降低推理成本。
- **评测维度**：根据评测目标选择或创建评测维度。
- **裁判模型**（自动评估时）：推荐选择推理能力强的模型（如通义千问3-Max）。

## 评测流程

如[模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)所述，完整流程分三个阶段：

1. **创建评测任务**：选择评测方式，配置模型、数据集和评测维度。基线评测使用内置评测集，无需额外准备。
2. **执行评测任务**：人工评估需评分员手动评价；自动评估和基线评测由系统自动执行。
3. **查看评测结果**：评测结果为数据驱动决策和模型优化提供方向。

## 限制和注意事项

- 该功能**仅适用于中国大陆版（北京地域）**。
- 调优后的模型如未在评测模型列表中出现，可能是因为模型尚未完成部署，需先完成模型部署。
- 评测集建议使用线上真实业务数据（如业务日志）或使用大模型模拟生成特定场景数据，以更准确地模拟实际业务场景。
- 自动评估中裁判模型的分类/评分结果建议定期人工抽查，确保准确性。
- 人工评估建议多名评分员独立标注相同样本以验证一致性，并定期组织培训统一标准。
