# model evaluation introduction

模型评测是百炼平台提供的核心能力评估功能，用于对文本生成类模型的推理结果进行结构化打分与对比分析。它通过可复用的评测维度定义评分规则，支持自动（大模型/规则）与人工两种评估范式，帮助开发者量化模型表现、验证调优效果或完成选型决策。所有评测均基于明确的输入-输出-参考三元组（${[prompt](prompt.md)}、${output}、${completion}）执行。

## 支持的模型与功能

百炼模型评测当前**仅支持文本生成类模型**（如 Qwen 系列、Llama 衍生模型等），不支持多模态或语音模型。评测功能分为两类：

- **自定义评测**：完全由用户控制，需自行准备评测数据集（EvaluationSet 类型，含 `Prompt` 和 `Completion` 列）并创建评测维度，支持大模型评估、规则评估和人工评估三种评分方式。  
- **基线评测**：使用平台预置的公开标准数据集（如 C-Eval、GSM8K、BBH），仅在北京地域可用，无需配置维度或数据集，但不支持结果下载与维度定制 [模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。

五种评测维度类型覆盖不同评估需求：
- **大模型评估-分类型/数值型**：依赖裁判模型（如千问-Max）进行语义级判断，适用于无确定答案但需理解的场景（如内容安全、问答质量）；
- **规则评估-字符串匹配/文本相似度**：纯算法计算，零裁判模型费用，适用于有标准答案的场景（如 Function Calling、NL2SQL、翻译、摘要）；
- **人工评估-分类型**：由人工标注 Pass/Fail，适用于主观性强的创意或专业判断场景。

> **注意**：文档 1 中称“人工评估-分类型”需配置 Pass/Fail 标签，而文档 2 明确说明该类型“不涉及裁判模型，由人工逐条标注”，且标签设计目标是“覆盖所有可能的评判结果”。二者一致，但文档 1 的表格中“需要参考答案”列为“否”易引发歧义——人工评估虽不强制要求 `Completion` 参考答案，但实际标注时仍需依据业务标准（可能隐含在 Prompt 或评审指南中），建议始终提供参考以保障一致性 [评测维度](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md)。

## 关键参数

创建评测维度时，以下参数为通用或类型专属必填项：

| 参数 | 说明 | 是否必填 | 备注 |
|------|------|----------|------|
| 维度名称 | 模板标识名 | 是 | ≤20 字符，建议采用“评估方面+评估方式”命名（如“回答准确性-LLM评分”） |
| 类型 | 5 种评分器之一 | 是 | **创建后不可更改**，选错需删除重建 [评测维度](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md) |
| 裁判模型 | 执行评判的 LLM | 大模型评估类型必填 | 推荐千问-Max；费用按 [Token](../concepts/token.md) 计费 |
| 评分器 Prompt | 指导裁判模型的提示词 | 大模型评估类型必填 | 必须包含至少一个变量：`${prompt}`、`${output}` 或 `${completion}` |
| 评分范围 | 数值型维度的整数区间 | 数值型必填 | 默认 `0~5`，建议不超过 10 以保障 LLM 评分一致性 |
| 通过阈值 | 判定 Pass 的最低分/相似度 | 数值型/相似度型必填 | 步长 0.1（数值型）或 0.01（相似度型）；与评分范围独立配置 |

其他关键参数包括：
- **Pass/Fail 标签**：分类型维度必填，标签间不可重复，应互斥且穷尽；
- **比较操作符**（字符串匹配）：`相等`/`不相等`/`包含`；
- **评估指标**（文本相似度）：支持 ROUGE-1/2/L、BLEU、余弦相似度、Fuzzy Match、Accuracy 等 7 种算法，需按任务类型选择（如摘要用 ROUGE-L，翻译用 BLEU）。

## 使用方式

完整评测流程为四步闭环：  
1. **准备数据集**：在数据管理模块上传 `EvaluationSet` 类型数据（含 `Prompt` 和 `Completion` 列），或复用已有 `InferenceResultSet`（含 `Output`）；  
2. **创建评测维度**：在控制台 **模型评测 > 评测维度** 创建模板，选择类型并配置参数；  
3. **创建评测任务**：在 **模型评测 > 评测任务** 选择自定义/基线方式，关联模型、数据源及维度；  
4. **查看结果**：在任务详情页的 **指标统计** Tab 查看综合得分、通过率与分布图，在 **数据明细** Tab 查看逐条评分 [模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。

快速入门最小配置示例（自定义评测）：
- 维度：大模型评估-数值型，裁判模型选千问-Max，模板选“综合评测”，评分范围 `0~5`，通过阈值 `3.0`；  
- 任务：数据来源选已发布的评测数据集，关联上述维度，开启“开始评测”。

## 限制和注意事项

- **地域限制**：基线评测仅限北京地域可用，其他地域控制台不显示该选项；  
- **类型锁定**：评测维度类型创建后不可修改，误选需删除重建；若已被任务引用，则需先解除关联 [评测维度](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md)；  
- **费用说明**：  
  - 使用评测数据集 → 产生被评测模型推理费用；  
  - 大模型评估维度 → 产生裁判模型评分费用；  
  - 规则评估与人工评估 → 无裁判模型费用；  
  - 推理结果集作为数据源 → 无被评测模型推理费用；  
- **数据要求**：评测数据集必须为 `EvaluationSet` 类型且已发布版本；训练集不可用于评测；  
- **成本优化建议**：优先用规则评估验证确定性场景；小规模（50–100 条）先行验证配置；保存推理结果集复用以避免重复推理；  
- **结果解读**：综合得分是各维度平均分，可能掩盖维度差异，务必结合分数分布与明细逐条分析；1–3% 分差通常属评测噪声，不宜作为决策依据。
