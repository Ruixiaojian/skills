# model evaluation introduction

模型评测是百炼平台提供的模型能力量化评估功能，支持通过自定义或基线方式对文本生成类模型进行多维度打分与对比。它面向开发者提供可复用的评测维度、灵活的数据源选择及结构化结果分析能力，核心目标是辅助模型选型、调优验证与质量监控。当前功能仅支持文本生成类模型，不支持[多模态](../concepts/multi-modal.md)或语音模型。

## 支持的模型与功能

- **支持的模型类型**：预置模型（如千问系列）及用户调优后的文本生成模型，详见[预置模型列表](#)；不支持非文本生成类模型（如图像生成、语音合成）。  
- **评测方式**：  
  - **自定义评测**：使用用户上传的评测数据集（EvaluationSet 类型）或已有推理结果集，配合自定义创建的评测维度执行；支持大模型评估、规则评估、人工评估三种评分范式。  
  - **基线评测**：基于平台预置的公开标准数据集（如 C-Eval、GSM8K、BBH）快速获取基准分数，仅限北京地域可用，详见[创建基线评测任务](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md#sec-baseline)。  
- **核心功能模块**：评测维度模板（可复用）、评测任务（绑定模型/数据/维度）、排行榜（同维度下多模型横向对比）、人工标注工作台（仅限人工评估维度）。

> **注意**：文档 1 中称“当前仅支持文本生成类模型评测”，而文档 2 未明确限定模型类型，但其所有示例与参数说明均围绕文本生成场景展开，且文档 1 的“使用场景”和“计费说明”均默认被评测模型为文本生成模型。因此以文档 1 的表述为准，该限制为硬性约束。

## 关键参数

| 参数类别 | 参数名 | 说明 | 必填性 | 取值范围/约束 |
|----------|--------|------|--------|----------------|
| **评测维度** | 维度类型 | 决定评分逻辑，创建后不可修改 | 是 | 5 种：大模型评估-数值型/分类型、规则评估-字符串匹配/文本相似度、人工评估-分类型 |
| | 裁判模型 | 仅大模型评估类型需指定 | 大模型评估必填 | 如千问-Max（推荐），影响评分质量与费用 |
| | 评分器 Prompt | 指导裁判模型评判的提示词 | 大模型评估必填 | 必须含至少一个变量：`${prompt}`、`${output}` 或 `${completion}`；长度 ≤ 50000 字符 |
| | 评分范围 | 仅数值型维度需配置 | 数值型必填 | 整数区间，最小值 ≥ 0，最大值 ≥ 1，默认 `0–5` |
| | 通过阈值 | 判定 Pass/Fail 的分界线 | 数值型/相似度型必填 | 数值型：步长 0.1，范围随评分范围联动；相似度型：0–1，步长 0.01 |
| | Pass/Fail 标签 | 仅分类型维度需配置 | 分类型必填 | 各标签 ≤ 20 字符；Pass 与 Fail 标签集合互斥无重复 |
| **评测任务** | 数据来源 | 决定是否触发被评测模型推理 | 是 | “评测数据集”（产生推理费用）或“推理结果集”（无推理费用） |
| | System Prompt | 为被评测模型设定角色或行为规范 | 否 | 多数场景可留空；与评分器 Prompt 作用对象不同，详见[模型评测概述](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md) |
| | 排行榜参与 | 控制结果是否加入排行榜 | 否（默认关闭） | 开启时须绑定已创建的排行榜，且排行榜绑定维度必须与当前任务一致 |

## 使用方式

1. **准备数据**：在数据管理模块上传类型为 `EvaluationSet` 的评测数据集（含 `Prompt` 和 `Completion` 列），或准备已含 `Output` 的推理结果集文件。  
2. **创建维度**：在控制台 **模型评测 > 评测维度** 页面创建至少一个维度模板。推荐从预置模板（如“综合评测”“标准匹配”）起步，小样本验证后再迭代自定义 Prompt —— 具体配置指南见[评测维度](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md)。  
3. **创建任务**：在 **模型评测 > 评测任务** 页面选择“自定义评测”，关联目标模型、数据源及已创建维度；若需对比，开启“参与排行”并选择对应排行榜。  
4. **查看结果**：任务状态变为“评测完成”后，在详情页的 **指标统计** Tab 查看综合得分、通过率与分数分布；在 **数据明细** Tab 查看逐条评分。结果支持下载（基线评测不支持）。  

> **注意**：文档 1 的“快速入门”步骤中要求“数据来源选择评测数据集并指定已上传的数据集”，而文档 2 在“创建评测维度模板”章节未提及数据准备前置条件。实际流程以文档 1 的端到端流程为准，数据准备是任务创建前的强制前提。

## 限制和注意事项

- **地域限制**：基线评测功能仅在北京地域可用，其他地域控制台不显示该选项，属正常设计，详见[创建基线评测任务](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md#sec-baseline)。  
- **模型与维度约束**：  
  - 维度类型创建后不可修改，选错需删除重建；删除维度前须确保无排行榜绑定（否则阻止删除），且已关联任务不受影响。  
  - 评测任务提交后不可更换被评测模型或修改维度，错误配置需删除任务后重建。  
- **费用相关**：  
  - 使用“评测数据集”作为数据源时，产生被评测模型的推理费用；使用“推理结果集”则无此费用。  
  - 仅大模型评估维度（数值型/分类型）产生裁判模型评分费用；规则评估与人工评估无裁判模型费用。详细计费规则见[计费说明](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。  
- **结果解读**：综合得分是各维度平均分，可能掩盖维度间差异；建议结合分数分布图与逐维度分析定位短板。1–3% 的分数差异通常属评测噪声，不宜作为决策依据。  
- **API 支持**：当前模型评测功能**仅支持控制台操作**，不提供公开 API 或 SDK；如需自动化，可参考 PAI Judge Model API 替代，详见[常见问题](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。
