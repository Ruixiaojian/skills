# model evaluation introduction

模型评测是百炼平台提供的模型能力量化评估功能，支持通过自定义或基线方式对文本生成类模型进行多维度打分与对比。它面向开发者提供可复用的评测维度、灵活的数据源选择及结构化结果分析能力，核心目标是辅助模型选型、调优验证与持续质量监控。当前功能仅支持文本生成类模型，不支持[多模态](../concepts/multi-modal.md)或语音模型。

## 支持的模型/功能

- **支持模型类型**：预置模型（如千问系列）及用户调优后的模型，具体列表参见[预置模型列表](https://help.aliyun.com/zh/model-studio/model-deployment-introduction)；**注意**：文档 1 中“当前仅支持文本生成类模型评测”与文档 2 未明确限定模型类型，但两处均未提及非文本类支持，故以文档 1 为准，确认不支持图像、音频等模态模型。
- **评测方式**：
  - **自定义评测**：使用用户上传的评测数据集（EvaluationSet 类型）或已有推理结果集，配合自定义创建的评测维度执行评分；
  - **基线评测**：基于平台预置公开数据集（如 C-Eval、GSM8K、BBH 等），仅在北京地域可用，详见[创建基线评测任务](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。
- **评分器类型**：共五种，分为三大类：
  - *大模型评估*（数值型/分类型）：依赖裁判模型（如千问-Max）进行语义级评判，适用于问答质量、内容安全等场景；
  - *规则评估*（字符串匹配/文本相似度）：基于算法（ROUGE/BLEU/Cosine/Fuzzy Match 等）或精确匹配逻辑，适用于翻译、摘要、Function Calling 等有确定性标准的场景；
  - *人工评估-分类型*：由人工标注 Pass/Fail，适用于创意写作、合规审核等主观性强的场景。  
  详细分类与适用场景说明请参见[评测维度](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md)。

## 关键参数

| 参数 | 说明 | 必填性 | 取值约束 | 备注 |
|------|------|--------|-----------|------|
| **维度类型** | 决定评分机制，创建后不可修改 | 是 | 5 种类型之一 | 选错需删除重建，已关联任务不受影响 |
| **裁判模型** | 仅大模型评估类型需配置 | 大模型评估类型必填 | 千问-Max 等预置模型 | 推荐千问-Max，推理能力强；费用按 [Token](../concepts/token.md) 计费 |
| **评分器 Prompt** | 指导裁判模型打分的提示词 | 大模型评估类型必填 | ≥1 个变量（`${prompt}`/`${output}`/`${completion}`），≤50000 字符 | 变量引用错误或缺失将导致提交失败；详见[配置评分器Prompt](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md) |
| **评分范围** | 数值型维度的整数区间 | 数值型必填 | 最小值 ≥ 0，最大值 ≥ 1，默认 `0-5` | 范围过宽（如 >10）会降低 LLM 评分一致性 |
| **通过阈值** | 判定 Pass 的最低分/相似度 | 数值型/相似度型必填 | 数值型：步长 0.1；相似度型：0–1，步长 0.01 | 与评分范围联动，用于统计通过率 |
| **Pass/Fail 标签** | 分类型维度的判定输出 | 分类型必填 | 各标签 ≤20 字符，Pass 与 Fail 标签互斥且无重复 | 标签设计应穷尽所有可能输出 |

## 使用方式

1. **准备数据**：在数据管理模块上传评测集（EvaluationSet 类型），至少包含 `Prompt` 和 `Completion` 两列；或准备已含 `Output` 的推理结果集文件。
2. **创建评测维度**：在控制台「模型评测 > 评测维度」中创建，选择类型并完成对应参数配置（如裁判模型、Prompt、标签等）；推荐先用预置模板快速启动，再迭代优化。
3. **创建评测任务**：
   - 自定义评测：选择被评测模型、数据来源（评测数据集或推理结果集）、关联至少一个已创建维度；
   - 基线评测：仅北京地域可见，选择模型与预设数据集（如 MMLU、HellaSwag），无需配置维度；
   - 注意：`System Prompt` 配置于任务级，作用于被评测模型；`评分器 Prompt` 配置于维度级，作用于裁判模型。
4. **查看结果**：任务状态为「评测完成」后，进入详情页查看「指标统计」（综合得分、通过率、分数分布）和「数据明细」（逐条评分）；支持结果下载（基线评测不支持）。

## 限制和注意事项

- **地域限制**：基线评测仅在北京地域可用，其他地域控制台不显示该选项，属正常行为；自定义评测全地域可用。
- **模型限制**：仅支持文本生成类模型，不支持[多模态](../concepts/multi-modal.md)、语音等模型；调优模型评测不额外计费（推理费用已含在部署算力中）。
- **维度限制**：维度类型创建后不可修改；已被排行榜绑定的维度删除后，将导致排行榜无法新建任务。
- **费用说明**：
  - 使用评测数据集 → 产生被评测模型推理费用（按 [Token](../concepts/token.md) 计费）；
  - 大模型评估维度 → 产生裁判模型评分费用（按 [Token](../concepts/token.md) 计费）；
  - 规则评估与人工评估 → 无裁判模型费用；
  - 使用推理结果集 → 不产生被评测模型推理费用。
- **成本优化建议**：
  - 先用 50–100 条数据小规模验证配置正确性；
  - 首次评测后下载结果复用为推理结果集，避免重复推理；
  - 有确定性标准的场景优先选用规则评估（零裁判模型费用）。
- **结果解读注意**：综合得分是各维度平均分，可能掩盖维度间差异；建议结合分数分布图逐维度分析；1–3% 的分差通常属评测噪声，不宜作为决策依据。
