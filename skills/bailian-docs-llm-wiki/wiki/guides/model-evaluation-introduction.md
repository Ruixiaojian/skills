# model evaluation introduction

模型评测是百炼平台提供的模型能力量化评估功能，支持通过自定义或基线方式对文本生成类模型进行多维度打分与对比。它面向模型选型、调优验证、能力归因和持续监控等核心场景，提供 AI 自动评分、规则算法计算和人工标注三种评估范式，并可生成结构化报告与排行榜。该功能当前仅支持文本生成类模型，不适用于[多模态](../concepts/multimodal.md)或语音模型。

## 支持的模型/功能

- **被评测模型**：支持所有百炼平台预置模型及用户调优后的模型（详见[预置模型列表](https://help.aliyun.com/zh/model-studio/model-deployment-introduction)），但需确保模型在所选地域可用且状态正常；  
- **裁判模型**：大模型评估维度依赖裁判模型（如千问-Max）进行语义评分，支持数值型（0–5 整数分）和分类型（Pass/Fail）输出；  
- **评估范式**：覆盖三大类共五种评测维度类型：  
  - 大模型评估-数值型 / 分类型（全自动，需裁判模型）  
  - 规则评估-文本相似度（ROUGE/BLEU/Cosine 等 7 种算法） / 字符串匹配（相等/不相等/包含）  
  - 人工评估-分类型（人工逐条标注，无裁判模型费用）  
- **数据源支持**：支持评测数据集（触发被测模型推理，产生推理费用）和推理结果集（直接评分，零推理成本）两种输入模式；  
- **基线评测**：仅限北京地域，使用平台预置公开数据集（如 C-Eval、GSM8K、BBH）快速获取基准分数，无需配置维度或数据集 [原文标题](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。

> **注意**：文档 1 称“基线评测仅北京地域可用”，而文档 2 未提及地域限制，但明确其为平台预设能力。以文档 1 的地域约束为准，其他地域用户创建任务时不会显示该选项，属正常行为。

## 关键参数

| 参数类别 | 参数名 | 说明 | 必填性 | 取值示例 |
|----------|--------|------|--------|----------|
| **通用** | 维度名称 | 模板标识，≤20 字符 | 是 | `回答准确性-LLM评分` |
| | 描述 | 补充说明，≤100 字符 | 否 | `基于语义完整性与事实正确性打分` |
| **大模型评估** | 裁判模型 | 执行评分的 LLM | 数值型/分类型必填 | `qwen-max` |
| | 评分器模板 | 预置 Prompt 模板（如综合评测、标准匹配）或自定义 | 必填 | `综合评测` |
| | 评分范围 | 数值型维度的整数区间 | 数值型必填 | `0–5` |
| | 通过阈值 | 判定 Pass 的最低分（步长 0.1）或相似度（步长 0.01） | 数值型/相似度型必填 | `3.0` / `0.65` |
| | Pass/Fail 标签 | 分类型维度的分类标签，互斥且不可重复 | 分类型/人工评估必填 | `Pass` / `Fail` |
| **规则评估** | 比较操作符（字符串匹配） | 相等 / 不相等 / 包含 | 字符串匹配必填 | `包含` |
| | 评估指标（文本相似度） | ROUGE-1 / BLEU / Cosine 等 7 种 | 文本相似度必填 | `ROUGE-L` |
| **变量引用** | `${prompt}` / `${output}` / `${completion}` | 评分器 Prompt 中唯一允许的占位符，至少使用一个 | 大模型评估必填 | `请基于${prompt}和${completion}评估${output}的事实一致性` |

所有维度类型创建后**不可修改类型**，选错需删除重建；已关联的评测任务不受影响 [原文标题](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md)。

## 使用方式

1. **准备数据**：在数据管理模块上传类型为 `EvaluationSet` 的评测数据集（含 `Prompt` 和 `Completion` 两列），并发布版本；  
2. **创建维度**：进入**模型评测 > 评测维度**，单击**创建评测维度**，按需选择类型并配置参数（如裁判模型、评分范围、Pass 标签等）；  
3. **创建任务**：进入**评测任务**，选择**自定义评测**（或北京地域的**基线评测**），指定被评测模型、数据来源（评测数据集或推理结果集）、已创建的维度；  
4. **执行与查看**：提交后等待状态变为“评测完成”，在详情页的**指标统计**Tab 查看综合得分、通过率及分布图，在**数据明细**Tab 查看每条样本的逐项评分；  
5. **进阶分析**：可将多个任务加入同一排行榜（需绑定相同维度），实现跨模型横向对比；人工评估任务需在标注页面完成全部 Pass/Fail 标注后才标记为完成 [原文标题](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。

## 限制和注意事项

- **模型限制**：仅支持文本生成类模型，不支持图像、语音、[多模态](../concepts/multimodal.md)等非文本模型；  
- **地域限制**：基线评测仅在北京地域可用，其他地域控制台不显示该选项；  
- **费用说明**：  
  - 使用评测数据集 → 产生被评测模型推理费用（按 [Token](../concepts/token.md) 计费）；  
  - 大模型评估维度 → 产生裁判模型评分费用（按 [Token](../concepts/token.md) 计费）；  
  - 规则评估与人工评估 → 无裁判模型费用；  
  - 使用推理结果集 → 无被评测模型推理费用；  
- **配置风险**：  
  - 评分器 Prompt 若未明确评分标准或变量引用错误（如漏写 `${output}`），易导致分数集中、区分度低；建议先用 10–20 条数据小规模验证；  
  - 通过阈值 ≠ 评分范围：前者决定 Pass/Fail 统计口径，后者定义裁判模型输出粒度，二者独立配置；  
- **操作约束**：  
  - 评测任务提交后不可更换被评测模型或修改维度；失败任务需删除重建；  
  - 维度模板被排行榜绑定后，删除该维度将导致排行榜无法新建任务；  
- **结果解读**：综合得分是各维度平均分，可能掩盖维度间差异；应结合**分数分布图**与**各维度明细**定位短板，1–3% 的分差通常属评测噪声，不宜作为决策依据。
