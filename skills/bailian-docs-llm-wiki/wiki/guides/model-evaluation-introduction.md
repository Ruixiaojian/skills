# model evaluation introduction

模型评测是百炼平台提供的模型能力量化评估功能，支持通过自定义或基线方式对文本生成类模型进行多维度打分与对比。它面向开发者提供可复用的评测维度、灵活的数据源选择及结构化结果分析能力，核心目标是辅助模型选型、调优验证与持续质量监控。当前仅支持文本生成类模型，不支持多模态或语音模型。

## 支持的模型与功能

- **支持模型类型**：预置模型（如千问系列）及用户调优后的文本生成模型，具体列表见[预置模型列表](https://help.aliyun.com/zh/model-studio/model-deployment-introduction)；**不支持非文本生成类模型**（如图像生成、语音合成）。  
- **评测方式**：  
  - **自定义评测**：使用用户上传的评测数据集（`EvaluationSet` 类型）或已有推理结果集，配合自定义创建的评测维度执行；支持全地域。  
  - **基线评测**：基于平台预置公开数据集（如 C-Eval、GSM8K、BBH）自动执行，仅限北京地域可用，详见[创建基线评测任务](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。  
- **评分器类型**：共五种，分为三大类：  
  - *大模型评估*（数值型/分类型）：依赖裁判模型（如千问-Max）进行语义级评判，适用于问答质量、内容安全等场景；  
  - *规则评估*（字符串匹配/文本相似度）：基于算法（ROUGE/BLEU/Cosine 等）或精确匹配，适用于翻译、摘要、Function Calling 等有确定性标准的场景；  
  - *人工评估-分类型*：由人工标注 Pass/Fail，适用于创意写作、合规审核等主观判断强的场景。  

> **注意**：文档1称“当前仅支持文本生成类模型评测”，而文档2未明确限定模型类型，但其所有示例与参数说明均围绕文本生成展开，且[评测维度](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md)中未提及非文本场景适配。因此以文档1为准，确认功能边界为文本生成类模型。

## 关键参数

| 参数类别 | 参数名 | 说明 | 必填性 | 取值约束 |
|----------|--------|------|--------|-----------|
| **通用** | 维度名称 | 评测维度模板标识符 | 是 | ≤20 字符 |
| | 描述 | 补充说明 | 否 | ≤100 字符 |
| **大模型评估** | 裁判模型 | 执行评分的 LLM | 数值型/分类型必填 | 如 `qwen-max`，费用按 [Token](../concepts/token.md) 计 |
| | 评分器 Prompt | 指导裁判模型打分的提示词 | 是 | 必须含 `${prompt}` / `${output}` / `${completion}` 至少一个变量，≤50000 字符 |
| | 评分范围（数值型） | 整数区间，如 `0-5` | 是 | 最小值 ≥0，最大值 ≥1 |
| | 通过阈值 | 判定 Pass 的最低分（数值型）或相似度（规则型） | 是 | 步长 0.1（数值型）、0.01（相似度型） |
| | Pass/Fail 标签（分类型） | 分类标签定义 | 是 | 标签互斥、无重复，各 ≤20 字符 |
| **规则评估** | 匹配规则（字符串匹配） | 相等 / 不相等 / 包含 | 是 | — |
| | 相似度算法（文本相似度） | ROUGE-1/2/L、BLEU、Cosine、Fuzzy Match、Accuracy | 是 | 7 种可选，按任务场景选择 |

## 使用方式

1. **准备数据**：在数据管理模块上传 `EvaluationSet` 类型数据集（含 `Prompt` 和 `Completion` 列），或准备已含 `Output` 的推理结果集文件。  
2. **创建评测维度**：在控制台 **模型评测 > 评测维度** 页面创建，选择类型并配置参数；维度创建后类型不可修改，详见[评测维度](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md)。  
3. **创建评测任务**：  
   - 选择 **自定义评测** 或 **基线评测**；  
   - 自定义评测需指定被评测模型、数据来源（评测数据集或推理结果集）、关联至少一个已创建维度；  
   - 基线评测仅需选择模型和预置数据集（如 MMLU），无需维度配置；  
4. **查看结果**：任务状态变为“评测完成”后，在详情页的 **指标统计** Tab 查看综合得分、通过率及分数分布，在 **数据明细** Tab 查看逐条评分。  

> **注意**：文档1指出“基线评测任务不可下载评测结果”，而文档2未提及此限制；实际行为以文档1为准，基线评测结果不支持下载。

## 限制和注意事项

- **地域限制**：基线评测仅在北京地域可用，其他地域控制台不显示该选项，属正常行为。  
- **模型与数据约束**：  
  - 仅支持文本生成类模型；  
  - 评测数据集必须为 `EvaluationSet` 类型且已发布版本；训练集不可用于评测；  
  - 推理结果集需严格按模板格式上传，否则解析失败。  
- **维度与任务约束**：  
  - 评测维度类型创建后不可修改，选错需删除重建；  
  - 已绑定维度的排行榜，删除该维度将导致排行榜无法新建任务；  
  - 人工评估任务需全部标注完成后才标记为“评测完成”。  
- **计费说明**：  
  - 使用评测数据集时产生被评测模型推理费用；  
  - 大模型评估维度产生裁判模型评分费用；  
  - 规则评估与人工评估无裁判模型费用；  
  - 成本优化建议：优先小规模验证（50–100 条）、复用推理结果集、高确定性场景首选规则评估。  
- **结果解读**：综合得分是各维度平均分，可能掩盖维度间差异；建议结合分数分布图逐维度分析，避免仅凭 1–3% 微小分差做决策。
