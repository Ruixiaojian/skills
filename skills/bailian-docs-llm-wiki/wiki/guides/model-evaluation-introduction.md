# model evaluation introduction

模型评测是百炼平台用于量化评估文本生成类模型能力的核心功能，支持通过自定义或基线方式，结合多种评分器类型对模型输出进行打分、对比与分析。其核心在于“评测维度”这一抽象单元，它封装了评分逻辑（如裁判模型评判、规则匹配或人工标注），使评估标准可复用、可迭代。本文档面向开发者，聚焦评测能力的技术实现细节与使用约束。

## 支持的模型/功能

百炼模型评测当前**仅支持文本生成类模型**，不支持多模态、语音或结构化输出模型。评测功能分为两类：

- **自定义评测**：用户自主准备评测数据集（EvaluationSet 类型）、创建评测维度、配置任务，支持三种评分方式：  
  - 大模型评估（AI 自动评测）：依赖裁判模型（如千问-Max）执行语义级判断，含分类型（Pass/Fail）和数值型（0~5 分等）两种子类型；  
  - 规则评估（自动化指标）：无裁判模型参与，含字符串匹配（相等/不相等/包含）和文本相似度（BLEU/ROUGE/余弦等 7 种算法）；  
  - 人工评估（人工标注）：由评测人员手动为每条输出标注 Pass/Fail 标签。  
  详见[评测维度](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md)。

- **基线评测**：仅限北京地域可用，使用平台预置的公开标准数据集（如 C-Eval、GSM8K、BBH），系统自动完成评分，**不支持自定义维度、不支持结果下载、不支持推理结果集输入**。其设计目标是快速获取基础能力基准分，而非精细化评估。详见[模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。

> **注意**：文档 1 中称“评测维度模板的创建和管理本身不收费”，而文档 2 明确指出“模型评测的费用由两部分构成：被评测模型的推理费用和裁判模型的评分费用”，且大模型评估类型在评测执行时产生裁判模型 Token 费用。二者无矛盾——前者指模板创建操作免费，后者指实际评测运行计费，但需明确：**维度创建不收费，维度使用才计费**。

## 关键参数

所有评测维度均需配置以下公共参数，其中类型为不可变字段：

| 参数 | 是否必填 | 说明 | 约束 |
|------|----------|------|------|
| 维度名称 | 是 | 模板标识名 | ≤20 字符 |
| 描述 | 否 | 补充说明 | ≤100 字符 |
| 类型 | 是 | 5 种之一，创建后不可更改 | — |

类型专属参数如下：

- **大模型评估-分类型/数值型**：  
  - `裁判模型`：必填，从下拉列表选择（推荐千问-Max）；  
  - `评分器模板`：预置（如“标准匹配”“综合评测”）或自定义；  
  - `评分器 Prompt`：必填，至少含 `${prompt}`、`${output}` 或 `${completion}` 之一；  
  - `评分范围`（仅数值型）：整数区间，默认 `0~5`，最小值 ≥ 0，最大值 ≥ 1；  
  - `通过阈值`（数值型/相似度型）：步长 0.1，用于统计通过率；  
  - `Pass/Fail 标签`（分类型/人工型）：标签互斥且不可重复。

- **规则评估-字符串匹配**：  
  - `评测输入`（参考文本）与 `模型输出`（待匹配文本）至少一侧含变量；  
  - `比较操作符`：相等 / 不相等 / 包含。

- **规则评估-文本相似度**：  
  - `评估指标`：7 种算法（ROUGE-L、BLEU、余弦等），按场景选（摘要用 ROUGE-L，翻译用 BLEU）；  
  - `通过阈值`：0~1 区间，步长 0.01。

- **人工评估-分类型**：仅需配置 `Pass 标签` 和 `Fail 标签`，无其他参数。

## 使用方式

完整流程为四步闭环：**准备数据集 → 创建评测维度 → 创建评测任务 → 查看结果**。

1. **准备数据集**：在数据管理模块上传 `EvaluationSet` 类型数据，至少含 `Prompt`（用户问题）和 `Completion`（参考答案）两列；若使用推理结果集，则需预先包含 `Output` 列，可规避被评测模型推理费用。

2. **创建评测维度**：在控制台 **模型评测 > 评测维度** 页面创建。强烈建议先用预置模板（如“综合评测”）快速启动，再基于小样本（50~100 条）验证效果，针对性优化 Prompt 后再扩大规模。参见[评测维度](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md)。

3. **创建评测任务**：在 **模型评测 > 评测任务** 页面，选择“自定义评测”，关联已创建的维度与数据集。关键配置：  
   - 数据来源选“评测数据集”（触发模型推理，产生费用）或“推理结果集”（零推理费用）；  
   - `System Prompt` 作用于被评测模型（非裁判模型），多数场景可留空；  
   - 排行榜参与为可选，开启后需绑定已有排行榜（绑定维度不可修改）。

4. **查看结果**：任务完成后，在详情页的 **指标统计** Tab 查看综合得分、通过率及分数分布；**数据明细** Tab 查看逐条评分。注意：**综合得分是各维度平均分，可能掩盖维度间差异，务必结合分数分布分析短板**。

## 限制和注意事项

- **类型不可变**：评测维度的 `类型` 创建后无法修改，选错必须删除重建。若该维度已被任务或排行榜引用，需先解除关联才能删除。
- **地域限制**：基线评测仅在北京地域可用，其他地域控制台不显示该选项，属正常行为。
- **费用敏感点**：  
  - 大模型评估维度在评测执行时产生裁判模型 Token 费用；  
  - 使用“评测数据集”作为数据源时，被评测模型推理也产生费用；  
  - 规则评估与人工评估无裁判模型费用，是成本最优路径。  
  成本优化策略见[计费说明](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。
- **变量引用强制要求**：大模型评估类型的 `评分器 Prompt` 必须至少包含 `${prompt}`、`${output}` 或 `${completion}` 之一，否则提交失败。
- **API 支持缺失**：当前模型评测功能**仅支持控制台操作，不提供公开 API 或 SDK**。如需自动化，需借助 PAI Judge Model API 替代。
- **数据格式强约束**：评测数据集必须为 `EvaluationSet` 类型且已发布版本；训练集、未发布版本或列名不符（如缺 `Prompt`）将导致任务失败。
