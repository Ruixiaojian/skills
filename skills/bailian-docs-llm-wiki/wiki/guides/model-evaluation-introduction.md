# model evaluation introduction

模型评测是百炼平台提供的模型能力量化评估功能，支持通过自定义或基线方式对文本生成类模型进行多维度打分与对比。它帮助开发者在模型选型、调优验证、质量监控等关键环节基于客观数据做出决策。该功能覆盖从数据准备、维度定义、任务执行到结果分析的完整闭环，但当前仅支持文本生成类模型，且部分能力存在地域或配置限制。

## 支持的模型/功能

- **支持模型类型**：仅限文本生成类模型（包括预置模型与调优后模型），不支持多模态、语音、图像等非文本生成模型。  
- **评测方式**：  
  - **自定义评测**：使用用户上传的评测数据集（EvaluationSet 类型）或已有推理结果集，配合自定义创建的评测维度进行评分；支持大模型评估、规则评估、人工评估三类共五种评分器类型（详见[评测维度](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md)）。  
  - **基线评测**：使用平台预置的公开标准数据集（如 C-Eval、GSM8K、BBH 等）快速获取基准分数，**仅北京地域可用**，且不支持自定义维度、结果下载及排行榜参与。  
- **核心能力**：  
  - 多维度联合评分（可关联多个评测维度）  
  - 排行榜横向对比（需绑定相同维度）  
  - 人工标注流程支持（仅限人工评估-分类型维度）  
  - 推理结果集复用（避免重复调用被测模型，降低成本）  

> **注意**：文档 1 中称“当前仅支持文本生成类模型评测”，而文档 2 未明确限定模型类型，但其所有示例与参数说明均围绕文本生成场景展开，且两文档均未提及非文本模型支持。因此以文档 1 的明确声明为准，实际能力边界以该约束为准。

## 关键参数

| 参数类别 | 参数名 | 说明 | 必填性 | 取值示例/约束 |
|----------|--------|------|--------|----------------|
| **评测维度** | 维度类型 | 决定评分机制，创建后不可修改 | 是 | `大模型评估-数值型`、`规则评估-字符串匹配` 等五种类型 |
| | 裁判模型 | 仅大模型评估类型需指定 | 大模型评估类型必填 | `qwen-max`（推荐） |
| | 评分器 Prompt | 指导裁判模型评判的提示词，须含 `${prompt}` / `${output}` / `${completion}` 至少一个变量 | 大模型评估类型必填 | 示例见[评测维度](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md) |
| | 评分范围 | 数值型维度专用，整数区间 | 数值型必填 | `0~5`（默认），最小值 ≥ 0，最大值 ≥ 1 |
| | 通过阈值 | 判定 Pass/Fail 的分界线 | 数值型/相似度型必填 | `3.0`（步长 0.1）、`0.85`（相似度，步长 0.01） |
| | Pass/Fail 标签 | 分类型维度专用，标签互斥且不可重复 | 分类型必填 | `Pass`/`Fail`，或 `合规`/`违规` |
| **评测任务** | 数据来源 | 决定是否触发被测模型推理 | 是 | `评测数据集`（产生推理费）或 `推理结果集`（无推理费） |
| | System Prompt | 为被测模型设定角色，多数场景可留空 | 否 | 空值或自定义指令 |
| | 是否参与排行 | 开启后需绑定已存在排行榜 | 开启时必填 | 默认关闭 |

## 使用方式

1. **准备数据**：在数据管理模块上传 `EvaluationSet` 类型数据集（含 `Prompt` 和 `Completion` 列），或整理好含 `Prompt`/`Output`/`Completion` 的推理结果集文件。  
2. **创建评测维度**：进入[评测维度](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md)页面，按业务场景选择类型并完成配置（如大模型评估需选裁判模型+Prompt，规则评估需选算法+匹配逻辑）。  
3. **创建评测任务**：  
   - 自定义评测：选择被测模型 → 指定数据来源 → 关联至少一个已建维度 → 设置 `System Prompt`（可选）→ 提交。  
   - 基线评测：仅北京地域可见，选择模型 + 预设数据集（如 `MMLU`）→ 提交。  
4. **查看结果**：任务状态变为“评测完成”后，在详情页的 **指标统计** Tab 查看综合得分、通过率及分布图；**数据明细** Tab 查看每条样本的逐项评分。支持下载 CSV 结果文件（基线评测不支持）。  
5. **进阶操作**：  
   - 创建排行榜：绑定同一维度的多个已完成任务，实现模型横向对比；  
   - 人工标注：对人工评估维度任务，进入标注页面逐条标记 `Pass`/`Fail`；  
   - 成本优化：优先复用推理结果集、小规模验证后再扩量、规则评估替代大模型评估。

## 限制和注意事项

- **地域限制**：基线评测功能**仅在北京地域可用**，其他地域控制台不显示该选项，属正常行为（参见[模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)）。  
- **模型限制**：仅支持文本生成类模型，不支持非文本生成任务（如图像生成、语音合成）。  
- **维度不可变**：评测维度的类型创建后不可修改，选错需删除重建；已被排行榜绑定的维度删除后，将导致排行榜无法新建任务。  
- **费用说明**：  
  - 使用 `评测数据集` 作为数据源时，产生被测模型推理费用；  
  - 大模型评估维度（数值型/分类型）额外产生裁判模型评分费用；  
  - 规则评估与人工评估无裁判模型费用（参见[模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)计费说明）。  
- **结果解读**：综合得分是各维度平均分，可能掩盖维度间差异；建议结合分数分布图与逐维度分析定位短板。1–3% 的分差通常属评测噪声，不宜作为决策依据。  
- **API 支持**：当前模型评测功能**仅支持控制台操作，不提供公开 API/SDK**；如需自动化，可参考 PAI Judge Model API 替代（参见[模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)常见问题）。
