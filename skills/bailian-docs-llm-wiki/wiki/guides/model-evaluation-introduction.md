# model evaluation introduction

模型评测是百炼平台提供的模型能力量化评估功能，支持通过自定义或基线方式对文本生成类模型进行多维度打分与对比。它面向模型选型、调优验证、能力归因和持续监控等核心研发场景，提供端到端的评测流程与结构化结果输出。所有功能均需在百炼控制台操作，当前不开放 API/SDK 接口。

## 支持的模型与功能

- **支持模型类型**：仅限文本生成类模型（如 Qwen 系列、Llama、GLM 等），不支持多模态、语音或结构化预测模型。预置模型与调优后模型均可评测，详见[预置模型列表](https://help.aliyun.com/zh/model-studio/model-deployment-introduction)；调优模型推理费用已含于部署算力中，不额外计费。
- **评测方式**：
  - **自定义评测**：用户上传评测数据集（EvaluationSet 类型，含 `Prompt` 和 `Completion` 列）并配置维度，支持大模型评估、规则评估、人工评估三种评分方式；
  - **基线评测**：使用平台预置公开数据集（如 C-Eval、GSM8K、BBH），仅北京地域可用，详见[创建基线评测任务](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。
- **核心能力**：维度可复用、任务可排行、结果可下载、人工标注闭环。排行榜强制绑定单一评测维度，确保横向对比公平性。

## 关键参数

| 参数类别 | 字段 | 说明 | 注意事项 |
|----------|------|------|----------|
| **评测维度** | 维度类型 | 必选：`大模型评估-数值型`/`-分类型`、`规则评估-文本相似度`/`-字符串匹配`、`人工评估-分类型` | 类型创建后不可修改，需删除重建；详见[创建评测维度](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md) |
| | 评分范围（数值型） | 整数区间，如 `0-5`，决定裁判模型输出粒度 | 默认 `0-5`，步长为 1 |
| | 通过阈值（数值型） | 小数，如 `3.0`，用于计算通过率 | 步长 `0.1`，与评分范围独立配置 |
| | 评分器 Prompt 变量 | `${prompt}`、`${output}`、`${completion}` | 自定义 Prompt 必须至少引用一个变量，否则提交失败 |
| **评测任务** | 数据来源 | `评测数据集`（触发模型推理，产生费用）或 `推理结果集`（仅评分，无推理费） | 后者需按模板上传含 `Output` 的文件；详见[创建自定义评测任务](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md) |
| | System Prompt | 作用于被评测模型，设定角色或行为规范 | 多数场景可留空；与评分器 Prompt（作用于裁判模型）严格区分 |
| | 排行参与 | 开启后需绑定已有排行榜，且该排行榜必须已绑定相同维度 | 清空维度时自动解除排行榜绑定 |

## 使用方式

1. **准备数据**：在数据管理模块上传 `EvaluationSet` 类型数据集，至少包含 `Prompt`（问题）和 `Completion`（参考答案）两列；若复用历史输出，按模板整理为 `推理结果集`。
2. **创建维度**：进入「模型评测 → 评测维度」，选择类型并配置（如大模型评估选千问-Max + 综合评测模板 + 0–5 分 + 通过阈值 3.0）。
3. **创建任务**：进入「评测任务」→「创建评测任务」→ 选「自定义评测」→ 选择模型 → 指定数据源 → 关联维度 → 提交。
4. **查看结果**：任务状态变为「评测完成」后，进入详情页：
   - 「数据明细」Tab 查看每条样本的 `Prompt`/`Output`/`Completion` 及各维度评分；
   - 「指标统计」Tab 查看综合得分（维度平均分）、通过率、分数分布图；
   - 支持下载 CSV 结果（基线评测与待执行任务不支持）。

> **注意**：基线评测不支持下载结果、不显示综合得分列、不可关联人工标注，且仅北京地域可见选项——此为地域限制，非配置错误，详见[创建基线评测任务](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。

## 限制和注意事项

- **模型限制**：仅支持文本生成类模型；多模态、语音、嵌入模型等暂不支持评测。
- **地域限制**：基线评测功能仅在北京地域可用，其他地域控制台不显示该选项，属正常设计。
- **费用风险**：
  - 使用 `评测数据集` + `大模型评估` 维度将同时产生被评测模型推理费与裁判模型评分费；
  - 规则评估与人工评估无裁判模型费用，推荐优先用于有确定性标准的场景（如翻译、NL2SQL）；
  - 成本优化建议：先用 50–100 条数据小规模验证配置，再扩量；保存首次输出复用为 `推理结果集`。
- **配置约束**：
  - 评测维度类型不可修改，误配需删除重建（已关联任务不受影响）；
  - 任务提交后不可更换被评测模型或修改数据源，需删除重建；
  - 排行榜绑定维度后不可更改，删除排行榜不影响已有关联任务。
- **结果解读**：综合得分是各维度平均值，可能掩盖维度间差异；建议结合分数分布图与「数据明细」逐维度分析短板；1–3% 分差通常属评测噪声，不宜作为决策依据。
