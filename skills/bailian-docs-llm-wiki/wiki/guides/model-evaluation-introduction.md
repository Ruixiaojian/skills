# model evaluation introduction

模型评测是百炼平台提供的模型能力量化评估功能，支持通过自定义或基线方式对文本生成类模型进行多维度打分与对比。它面向开发者提供 AI 自动评测、规则评估和人工评估三种评分范式，帮助完成模型选型、调优验证、质量监控等核心任务。当前功能仅支持文本生成类模型，且部分能力存在地域限制。

## 支持的模型/功能

- **支持的模型类型**：仅限文本生成类模型（如 Qwen 系列、Llama 等），不支持多模态、语音、向量模型等其他类型。预置模型与调优后模型均可作为被评测对象，详见[模型评测产品概览](https://help.aliyun.com/zh/model-studio/model-evaluation-introduction/) —— 该能力说明见 [模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。
- **评测方式**：
  - **自定义评测**：用户上传评测数据集（EvaluationSet 类型，含 `Prompt` 和 `Completion` 列）并配置维度，支持大模型评估、规则评估、人工评估三类共五种评分器；
  - **基线评测**：使用平台预置公开数据集（如 C-Eval、GSM8K、BBH），系统自动执行、不可配置维度，**仅北京地域可用** —— 此限制在 [模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md) 中明确强调。
- **复用能力**：评测维度以模板形式创建，可被多个评测任务引用，实现评估标准统一；排行榜支持跨任务横向对比，但要求所有关联任务使用**相同评测维度与数据集**以保障公平性。

> **注意**：文档 1 称“基线评测仅北京地域可用”，而文档 2 未提及地域限制。应以文档 1 的明确声明为准，其他地域用户无法看到基线评测选项属正常行为。

## 关键参数

| 参数类别 | 参数名 | 说明 | 必填性 | 注意事项 |
|----------|--------|------|--------|----------|
| **维度级** | 维度类型 | 5 种：大模型评估-数值型/分类型、规则评估-字符串匹配/文本相似度、人工评估-分类型。**创建后不可修改** | 是 | 选错需删除重建；已关联任务不受影响 —— 参见 [评测维度](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md) |
| | 裁判模型 | 仅大模型评估类型需指定（推荐千问-Max） | 大模型评估必填 | 影响评分质量与费用 |
| | 评分器 Prompt | 指导裁判模型评判的提示词，须含 `${prompt}` / `${output}` / `${completion}` 至少一个变量 | 大模型评估必填 | 变量引用错误将导致提交失败 —— 详见 [评测维度](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md) |
| | 评分范围 & 通过阈值 | 数值型：整数区间（默认 0–5）；所有类型均需设置通过阈值（步长 0.1 或 0.01） | 数值型/相似度型必填 | “评分范围”决定打分粒度，“通过阈值”独立用于统计通过率，二者不可混淆 |
| **任务级** | 数据来源 | “评测数据集”（触发被测模型推理，产生费用）或“推理结果集”（仅评分，零推理费） | 是 | 推理结果集需按模板提前上传，且不含 `Completion` 列时部分规则评估不可用 |

## 使用方式

1. **准备数据**：在数据管理模块上传 `EvaluationSet` 类型数据集（至少含 `Prompt` 和 `Completion` 两列），并发布版本。
2. **创建维度**：在「模型评测 > 评测维度」中创建至少一个维度模板。推荐从预置模板（如“综合评测”“标准匹配”）起步，小样本验证后再定制 Prompt。
3. **创建任务**：
   - 自定义评测：选择模型 → 指定数据来源 → 关联维度 → 设置 `System Prompt`（可选，作用于被测模型）→ 提交；
   - 基线评测：仅北京地域可见，选择模型 + 公开数据集（如 MMLU）→ 提交。
4. **查看结果**：任务完成后，在「数据明细」Tab 查看逐条评分，在「指标统计」Tab 查阅综合得分、通过率及分数分布。**强烈建议分析分布而非仅看均值**，避免掩盖维度间差异。

## 限制和注意事项

- **地域限制**：基线评测功能仅在北京地域可用，其他地域控制台不显示该选项 —— 此为硬性限制，非配置问题。
- **模型限制**：当前**仅支持文本生成类模型**，不支持图像生成、语音合成等非文本任务。
- **维度不可变**：维度类型、裁判模型、评分范围等核心参数创建后不可编辑，修改需删除重建。
- **费用敏感点**：
  - 使用“评测数据集”会触发被测模型推理，按 [Token](../concepts/token.md) 计费；
  - 大模型评估维度（数值型/分类型）额外产生裁判模型评分费用；
  - 规则评估与人工评估无裁判模型费用，成本最低。
- **数据要求**：
  - 评测数据集必须为 `EvaluationSet` 类型且已发布；
  - 推理结果集文件需严格按模板格式（含 `Prompt`、`Output` 列，`Completion` 可选）；
  - 小规模验证建议 50–100 条，正式评测推荐 200–500 条。
- **人工评估特殊性**：任务状态需待全部人工标注完成后才变为“评测完成”，期间无法下载结果；标签设计需互斥穷尽，避免歧义。
