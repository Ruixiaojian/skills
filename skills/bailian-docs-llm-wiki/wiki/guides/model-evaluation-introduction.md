# model evaluation introduction

模型评测是百炼平台提供的模型能力量化评估功能，支持通过自定义或基线方式对文本生成类模型进行多维度打分与横向对比。它面向模型选型、调优验证、能力归因和持续监控等核心场景，提供 AI 自动评分、规则算法计算和人工标注三种评估范式，并可生成结构化报告与排行榜。该功能当前仅支持文本生成类模型，不适用于多模态或语音模型。

## 支持的模型与功能

- **支持模型类型**：预置模型（如千问系列）及用户调优后的文本生成模型，详见[预置模型列表](https://help.aliyun.com/zh/model-studio/model-deployment-introduction)；**不支持多模态、语音、向量模型**。
- **核心功能**：
  - **自定义评测**：使用用户上传的评测数据集（EvaluationSet 类型）或已有推理结果集，关联自定义评测维度执行评分；
  - **基线评测**：基于平台预置公开数据集（如 C-Eval、GSM8K、BBH 等）快速获取基准分数，**仅北京地域可用**；
  - **排行榜**：在统一维度下横向对比多个模型表现，支持自动锁定评分标准；
  - **人工标注**：针对创意性、专业性等主观场景，由人工逐条标注 Pass/Fail 标签。

> **注意**：文档 1 称“当前仅支持文本生成类模型评测”，而文档 2 未明确限定模型类型，但所有示例与参数均围绕文本生成展开，且无任何多模态输入/输出字段说明。此处以文档 1 的明确声明为准，实际使用中若尝试非文本生成模型将触发配置校验失败。详情请参见[模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。

## 关键参数

| 参数类别 | 参数名 | 说明 | 必填性 | 取值约束 |
|----------|--------|------|--------|-----------|
| **维度通用** | 维度名称 | 模板标识符 | 是 | ≤20 字符 |
| | 描述 | 补充说明 | 否 | ≤100 字符 |
| **大模型评估** | 裁判模型 | 执行评分的 LLM（如千问-Max） | 是（仅大模型评估类型） | 下拉选择，影响费用与质量 |
| | 评分器 Prompt | 指导裁判模型打分的提示词 | 是（仅大模型评估） | 必须含 `${prompt}` / `${output}` / `${completion}` 至少一个变量，≤50000 字符 |
| | 评分范围（数值型） | 整数区间，如 `0-5` | 是（仅数值型） | 最小值 ≥ 0，最大值 ≥ 1 |
| | 通过阈值 | 判定 Pass 的最低分（数值型）或相似度（规则型） | 是（数值型/相似度型） | 数值型步长 0.1，相似度型步长 0.01，范围 0–1 |
| **规则评估** | 匹配规则（字符串匹配） | 相等 / 不相等 / 包含 | 是（仅字符串匹配） | — |
| | 相似度算法（文本相似度） | ROUGE-1/2/L、BLEU、Cosine、Fuzzy Match、Accuracy | 是（仅文本相似度） | — |
| **人工评估** | Pass/Fail 标签 | 分类标签名称 | 是（仅人工评估） | 标签间不可重复，各 ≤20 字符 |

所有维度类型创建后**不可修改类型**，选错需删除重建；已关联任务不受影响。更多参数细节请参考[评测维度](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md)。

## 使用方式

1. **准备数据**：在数据管理模块上传 `EvaluationSet` 类型数据集（含 `Prompt` 和 `Completion` 列），或整理好含 `Prompt`/`Output` 的推理结果集；
2. **创建维度**：在「评测维度」Tab 创建至少一个维度模板，按业务选择类型（如问答质量用「大模型评估-数值型」，Function Calling 用「规则评估-字符串匹配」）；
3. **创建任务**：
   - 自定义评测：选择模型 → 指定数据来源（评测数据集 or 推理结果集）→ 关联维度 → 设置 `System Prompt`（可选）→ 提交；
   - 基线评测：仅北京地域可见，选择模型 + 公开数据集（如 MMLU）→ 提交；
4. **查看结果**：任务状态为「评测完成」后，在详情页「指标统计」Tab 查综合得分与通过率，「数据明细」Tab 查逐条评分；
5. **复用与优化**：下载推理结果集用于后续低成本复评；保存高质维度模板供多任务复用。

> **注意**：文档 1 明确指出“模型评测当前仅支持控制台操作，不提供公开 API/SDK”，而文档 2 未提及接口能力。若需自动化，应参考 PAI Judge Model API 替代方案。该限制在实际集成中必须遵守，详见[模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。

## 限制和注意事项

- **地域限制**：基线评测仅在北京地域可用，其他地域控制台不显示该选项；
- **数据要求**：评测数据集必须为 `EvaluationSet` 类型且已发布版本；训练集不可用于评测；
- **费用相关**：
  - 使用「评测数据集」时产生被评测模型推理费用；
  - 「大模型评估」维度产生裁判模型评分费用（按 [Token](../concepts/token.md) 计费）；
  - 「规则评估」与「人工评估」无裁判模型费用；
- **维度绑定约束**：已被排行榜绑定的维度删除后，该排行榜将无法创建新任务（绑定维度为空）；
- **人工标注**：任务状态需待全部数据标注完成后才变为「评测完成」，中途不可跳过未标注项导出结果；
- **成本优化建议**：优先用小样本（50–100 条）验证配置；复用推理结果集避免重复推理；有确定性标准时优先选用规则评估。

如遇配置异常（如任务失败、分数区分度低），请首先检查数据格式、变量引用完整性及评分器 Prompt 明确性。详细排障指引请参见[模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。
