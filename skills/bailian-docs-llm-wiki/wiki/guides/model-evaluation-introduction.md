# model evaluation introduction

模型评测是百炼平台提供的模型能力量化评估功能，支持通过自定义或基线方式对文本生成类模型进行多维度打分与对比。它面向模型选型、调优验证、能力归因和持续监控等核心场景，提供 AI 自动评分、规则计算和人工标注三种评估范式，并以结构化报告和排行榜形式输出结果。该功能当前仅支持文本生成类模型，不支持多模态或语音类模型。

## 支持的模型/功能

- **支持的模型类型**：仅限文本生成类模型（包括预置模型与调优后模型），详见[模型评测产品概览](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。多模态、语音等非文本生成模型暂不支持。
- **核心评估范式**：
  - **大模型评估**（AI 自动评测）：使用裁判模型（如千问-Max）对输出进行语义级评分或分类；
  - **规则评估**（自动化指标）：基于 ROUGE、BLEU、Cosine、字符串匹配等算法直接计算得分；
  - **人工评估**（人工标注）：由人工对每条样本标注 Pass/Fail 标签。
- **评测模式**：
  - **自定义评测**：用户上传评测数据集（EvaluationSet 类型，含 `Prompt` 和 `Completion` 列）并配置维度，全地域可用；
  - **基线评测**：使用平台预置公开数据集（如 C-Eval、GSM8K、BBH），**仅北京地域可用**，详见[创建基线评测任务](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。

> **注意**：文档 1 称“当前仅支持文本生成类模型评测”，文档 2 未明确限定模型类型，但其所有示例与参数说明均围绕文本生成展开，且未提及多模态输入/输出支持。二者一致，无矛盾。

## 关键参数

| 参数类别 | 参数名 | 说明 | 必填性 | 约束 |
|----------|--------|------|--------|------|
| **通用** | 维度名称 | 最长 20 字符，建议采用“评估方面+评估方式”命名（如“回答准确性-LLM评分”） | 是 | — |
| | 描述 | 最长 100 字符，用于补充说明评判目标 | 否 | — |
| **大模型评估** | 裁判模型 | 如千问-Max，影响评分质量与费用 | 是（仅大模型评估类型） | 下拉选择 |
| | 评分器 Prompt | 必须包含 `${prompt}`、`${output}` 或 `${completion}` 至少一个变量 | 是（仅大模型评估类型） | ≤50000 字符；详见[配置评分器Prompt](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md) |
| | 评分范围（数值型） | 整数区间，如 `0~5`，默认 `0~5` | 是（仅数值型） | 最小值 ≥ 0，最大值 ≥ 1 |
| | 通过阈值 | 判定 Pass 的最低分（数值型）或相似度（规则型），步长 0.1（数值型）/0.01（相似度型） | 是（数值型/相似度型） | 数值型：≤ 评分范围上限；相似度型：∈ [0,1] |
| | Pass/Fail 标签（分类型） | 标签互斥且穷尽，各标签 ≤20 字符 | 是（仅分类型） | Pass 与 Fail 标签不可重复 |
| **规则评估** | 比较操作符（字符串匹配） | 相等 / 不相等 / 包含 | 是（仅字符串匹配） | — |
| | 评估指标（文本相似度） | ROUGE-1/2/L、BLEU、Cosine、Fuzzy Match、Accuracy | 是（仅文本相似度） | — |

## 使用方式

1. **准备数据**：在数据管理模块上传 `EvaluationSet` 类型数据集（含 `Prompt` 和 `Completion` 列），或复用已有推理结果集（含 `Prompt`、`Output`、`Completion`）。
2. **创建评测维度**：在控制台 **模型评测 > 评测维度** 页面创建，选择类型并配置参数。维度创建后类型不可修改，需删除重建（见[创建评测维度](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)）。
3. **创建评测任务**：
   - **自定义评测**：选择模型、数据来源（评测数据集或推理结果集）、关联已建维度；可选开启排行参与。
   - **基线评测**：仅北京地域可见，选择模型与预置数据集（如 MMLU、HellaSwag），无需配置维度。
4. **查看结果**：任务状态为“评测完成”后，在详情页查看 **指标统计**（综合得分、通过率、分数分布）和 **数据明细**（逐条评分）。支持下载 CSV 结果文件（基线评测不支持下载）。

## 限制和注意事项

- **地域限制**：基线评测功能**仅在北京地域可用**，其他地域控制台不显示该选项，属正常行为（见[创建基线评测任务](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)）。
- **模型与数据约束**：
  - 仅支持文本生成类模型；多模态、语音等模型不可评测。
  - 数据集必须为 `EvaluationSet` 类型且已发布版本；训练集不可用于评测。
  - 推理结果集需严格按模板格式上传（含 `Prompt`、`Output`、`Completion` 字段）。
- **维度与任务约束**：
  - 评测维度类型创建后不可修改，选错需删除重建；删除维度前须确保无排行榜绑定（否则阻止新任务创建）。
  - 人工评估任务需全部标注完成后才变为“评测完成”状态。
- **计费说明**：
  - 使用评测数据集时产生被评测模型推理费用（按 [Token](../concepts/token.md) 计费）；
  - 大模型评估维度产生裁判模型评分费用（按 [Token](../concepts/token.md) 计费）；规则评估与人工评估无裁判模型费用。
  - 基线评测同样产生被评测模型推理费用（见[计费说明](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)）。
- **结果解读建议**：
  - 避免仅依赖综合得分，应结合分数分布分析各维度表现差异；
  - 1–3% 的分数差异通常属评测噪声，不宜作为决策依据；
  - 小规模验证（50–100 条）推荐优先使用规则评估或预置 Prompt，确认配置正确后再扩大规模。
