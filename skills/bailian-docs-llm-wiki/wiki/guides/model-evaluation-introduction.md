# model evaluation introduction

模型评测是百炼平台提供的核心能力评估功能，用于对文本生成类模型的推理结果进行结构化打分与对比分析。它通过可复用的评测维度定义评分标准，支持大模型自动评估、规则匹配和人工评审三种范式，帮助开发者量化模型表现、验证调优效果或支撑选型决策。所有评测均基于明确的输入（Prompt）、输出（Output）与参考答案（Completion）三元组展开。

## 支持的模型/功能

百炼模型评测当前**仅支持文本生成类模型**（如 Qwen 系列、Llama 衍生模型等），不支持多模态或语音模型。评测功能分为两类：

- **自定义评测**：完全由用户控制，需自行准备评测数据集（EvaluationSet 类型，含 `Prompt` 和 `Completion` 列）并创建评测维度，支持 AI 自动评测、规则评估和人工评估三种方式。详见 [模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。
- **基线评测**：使用平台预置的公开标准数据集（如 C-Eval、GSM8K、BBH），无需上传数据或配置维度，但**仅在北京地域可用**，且不支持结果下载与排行榜关联。详见 [模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。

> **注意**：文档 1 中“评测维度概述”提到“覆盖大模型评估、规则评估和人工评估三大类共五种评分器类型”，而文档 2 在“自定义评测与基线评测”章节明确指出“自定义评测支持以下三种评分方式：大模型评估（AI 自动评测）、规则评估（自动化指标）、人工评估（人工标注）”。二者分类逻辑一致（五种类型是三种方式下的细分），但术语层级不同。实际使用中应以五种具体类型（大模型评估-分类型/数值型、规则评估-字符串匹配/文本相似度、人工评估-分类型）为准，该结构在 [评测维度](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md) 中有完整定义。

## 关键参数

评测维度的核心参数按类型区分，创建后**类型不可更改**，需谨慎选择：

| 参数 | 适用类型 | 是否必填 | 说明 |
|------|----------|----------|------|
| **裁判模型** | 大模型评估（分类型/数值型） | 是 | 如 `qwen-max`，决定评分质量与费用；推荐千问-Max。详见 [评测维度](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md)。 |
| **评分器 Prompt** | 大模型评估（分类型/数值型） | 是 | 必须包含至少一个变量 `${prompt}`、`${output}` 或 `${completion}`；定义裁判模型的评判逻辑与输出格式。详见 [配置评分器Prompt](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md)。 |
| **评分范围** | 大模型评估-数值型 | 是 | 整数区间（如 `0~5`），默认 `0~5`；范围过大会降低 LLM 评分一致性，建议 ≤10。 |
| **通过阈值** | 数值型、文本相似度型 | 是 | 数值型为小数（步长 0.1，如 `3.0`），相似度型为 `[0,1]` 区间（步长 0.01）；用于统计通过率。 |
| **比较操作符** | 规则评估-字符串匹配 | 是 | `相等`/`不相等`/`包含`；Function Calling 常用 `包含`，NL2SQL 常用 `相等`。 |
| **评估指标** | 规则评估-文本相似度 | 是 | 支持 `ROUGE-L`（摘要）、`BLEU`（翻译）、`Cosine`（语义）、`Accuracy`（精确匹配）等 7 种算法。 |
| **Pass/Fail 标签** | 大模型评估-分类型、人工评估-分类型 | 是 | 标签互斥且穷尽；不可重复，长度 ≤20 字符。 |

## 使用方式

完整流程为四步闭环：**准备数据集 → 创建评测维度 → 创建评测任务 → 查看结果**。

1. **准备数据集**：在数据管理模块上传 `EvaluationSet` 类型数据，至少包含 `Prompt`（用户问题）和 `Completion`（参考答案）两列；若使用推理结果集，则需额外提供 `Output` 列，可避免重复推理费用。
2. **创建评测维度**：在控制台 **模型评测 > 评测维度** 页面创建，按场景选择五种类型之一。例如快速入门可选“大模型评估-数值型”，裁判模型选 `qwen-max`，模板选“综合评测”，评分范围 `0~5`，阈值 `3.0`。
3. **创建评测任务**：
   - 自定义评测：选择目标模型、数据来源（评测数据集 or 推理结果集）、关联已创建的维度；
   - 基线评测：仅北京地域可见，选择预置数据集（如 `MMLU`）后直接提交。
4. **查看结果**：任务完成后，在 **数据明细 Tab** 查看逐条评分，在 **指标统计 Tab** 获取综合得分、通过率及分布图；支持结果下载（基线评测不支持）。

## 限制和注意事项

- **地域限制**：基线评测仅限北京地域，其他地域控制台不显示该选项，属正常行为。
- **类型锁定**：评测维度的类型创建后不可修改，选错需删除重建；若已被任务引用，须先解除关联。
- **费用归属**：
  - 使用**评测数据集**时，产生被评测模型的推理费用（按 [Token](../concepts/token.md) 计费）；
  - **大模型评估类型**额外产生裁判模型评分费用（按 [Token](../concepts/token.md) 计费）；
  - **规则评估**（字符串匹配/文本相似度）和**人工评估**无裁判模型费用；
  - 使用**推理结果集**可规避被评测模型推理费用。
- **数据要求**：评测数据集必须为 `EvaluationSet` 类型且已发布版本；训练集不可用于评测。
- **成本优化建议**：优先对小样本（50–100 条）验证配置，确认 Prompt 合理后再扩大规模；保存并复用推理结果集；有确定性标准的场景（如 Function Calling）优先选用规则评估。

> **注意**：文档 1 的“常见问题”指出“切换评分器模板后，之前手动编辑的 Prompt 内容消失”，而文档 2 的“创建评测维度”部分未强调此行为。该行为为系统预期设计，切换模板会覆盖 Prompt，重要自定义内容请提前备份——此细节在 [评测维度](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md) 中有明确警示。
