# application evaluation

应用评测是阿里云百炼平台提供的核心能力，用于系统化评估智能体应用和工作流应用的输出质量。平台支持自动评测和人工评测两种方式，并提供评测集管理、评估器配置、标签标注等配套功能，帮助开发者在应用上线前后持续监控和优化应用效果。

> **注意**：百炼平台当前存在新旧两个版本的应用评测系统。新版评测支持智能体、工作流和自定义评测集类型，并引入了评估器和标签体系；旧版评测包含自动评测和手动评测功能。可在评测页面左上角通过"返回旧版"切换。

## 评测模式概览

百炼平台提供以下几种评测模式：

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| **自动评测（旧版）** | 基于知识库自动生成评测集，由大模型自动评分并生成报告 | RAG 智能体应用的快速评估 |
| **手动评测（旧版）** | 人工构建评测集，人工对比打分 | 需要领域专家判断的场景 |
| **评测任务（新版）** | 支持评估器自动评分 + 人工标签标注 | 智能体和工作流应用的多维度评测 |

## 支持的应用类型

- **智能体应用**：旧版自动评测和手动评测、新版评测任务均支持
- **工作流应用**：仅新版评测任务支持
- 自动评测仅面向**已发布**且**已配置知识库**的智能体应用

## 评测集

评测集是评测任务的数据基础。根据所使用的评测版本，支持的评测集类型有所不同，详见 [评测集](../../raw/application-user-guide/application-evaluation/application-evaluation-dataset.md) 和 [新版评测集](../../raw/application-user-guide/application-evaluation/new-version-of-application-evaluation/new-version-of-evaluation-set.md)。

### 旧版评测集类型

| 类型 | 文件格式 | 用途 |
|------|----------|------|
| 对话分析 | `.xls`、`.xlsx` | 手动评测，支持单轮/多轮对话 |
| 知识问答 | `.jsonl` | 自动评测，含 query、referenceAnswer、关键词等字段 |

### 新版评测集类型

| 类型 | 说明 |
|------|------|
| 智能体 | 根据智能体应用的出入参自动生成数据模板 |
| 工作流 | 根据工作流应用的出入参自动生成数据模板 |
| 自定义 | 自定义表结构，适用于特殊评测场景 |

### 创建方式

- **自动生成**：在自动评测流程中，基于知识库由大模型生成（仅知识问答类型）
- **手动上传**：下载模板填写后上传，单次最多 10 个文件，单文件不超过 20MB
- **从应用观测导入**：将线上真实数据导入评测集（新版）

评测集创建后需**发布**才能用于评测任务，支持版本管理。

## 自动评测（旧版）

自动评测利用大模型基于知识库自动生成评测集，自动评分并生成含调优建议的评测报告。详见 [自动评测](../../raw/application-user-guide/application-evaluation/application-auto-evaluation.md)。

### 前提条件

1. 应用已发布且已配置知识库
2. 已开通**应用观测**功能，并将应用添加到观测列表
3. 子账号需具备 `管理员` 或 `应用评测-操作` 权限

### 评测模式

- **单应用评测**：深度评估单个应用，生成评分、错误分析和优化建议
- **多应用横向评测**：最多 8 个应用在同一基准下对比，所有应用须关联至少一个相同知识库

### 操作流程

1. **创建评测任务**：选择应用和知识库
2. **设置评测集**：选择生成评测集（2~8 种任务类型，支持自定义）或复用已有评测集；生成模型仅支持 `qwen-max` 和 `qwen-plus`
3. **配置评测规则**：设置分类采样数和评测模型，可先试运行预览效果
4. **执行评测**：确认后开始评测，完成后可追加应用（总数不超过 8 个）

### 评分机制与归因分析

评分范围 1-5 分，≥4 分为正确。对低于 4 分的 BadCase 自动归因：

| 归因类型 | 含义 | 建议操作 |
|----------|------|----------|
| 模型理解有误 | 已获取正确知识但推理出错 | 优化 Prompt 或换更强模型 |
| 重排不佳 | 正确切片召回但排序靠后 | 调整重排配置或增加切片数量 |
| 检索无效 | 检索策略不当导致召回异常 | 调整检索方式 |
| 切片不完整 | 切分粒度过细 | 增大切片长度或启用语义切分 |
| 未获取知识 | 知识库缺失相关内容 | 补充知识库 |

## 手动评测（旧版）

手动评测通过人工构建评测集并对应用回答进行人工打分，详见 [手动评测](../../raw/application-user-guide/application-evaluation/evaluate-manual-application.md)。

### 操作流程

1. **准备评测集**：下载模板，填写 Prompt、Completion 和 SessionId 字段
2. **上传并发布评测集**：上传后等待导入成功，发布后方可使用
3. **创建评测任务**：选择已发布的智能体应用和评测集，选择评测维度
4. **人工标注**：对比应用输出与标准答案，给出评价（较差/一般/较好）
5. **查看报告**：完成标注后提交，查看评测结果

## 新版评测任务

新版评测任务支持评估器自动评分与人工标签标注结合，适用于智能体和工作流应用。详见 [评测任务](../../raw/application-user-guide/application-evaluation/new-version-of-application-evaluation/evaluation-task.md)。

### 关键配置

| 配置项 | 说明 |
|--------|------|
| 评测集 | 从已发布评测集中选择 |
| 应用关联 | 不关联应用（纯人工标注）、工作流或智能体 |
| 评估器 | 最多添加 10 个，需完成参数映射 |
| 标签 | 用于人工标注，支持分类/布尔值/数字/文本四种类型 |

### 评估器

评估器是自动评分的核心组件，分为两类：

- **LLM 评估器**：基于大模型语义理解进行评分，适合相关性、幻觉检测等场景，会产生 Token 费用
- **Code 评估器**：基于 Python 脚本进行规则判断，适合格式校验、精确匹配等场景，无额外费用

创建方式包括：基于预置模板创建、自定义创建、基于历史评测任务创建。评估器支持配置评分范围和通过阈值（≥ 阈值为 Pass）。

### 标签体系

标签用于人工标注，支持四种类型：

| 类型 | 适用场景 | 示例 |
|------|----------|------|
| 分类 | 枚举类评测维度 | 回答质量（较差/一般/较好） |
| 布尔值 | 是/否判断 | 是否存在幻觉 |
| 数字 | 精确打分 | 评分（1-5 分） |
| 文本 | 自由描述 | 错误原因说明 |

标签可同时用于评测任务和应用观测模块的数据标注。

## 计费说明

- 评测过程中调用大模型产生的 Token 费用按正常标准计费
- 自动评测生成评测集和评分均消耗 Token，仅支持 `qwen-max` 和 `qwen-plus`
- 新版评估器模型限时免费
- 使用独占资源部署的模型不额外收费
- 任务失败时，已完成步骤消耗的 Token 仍计入用量

## 限制与注意事项

- 自动评测仅支持已发布且配置知识库的智能体应用
- 多应用横向评测最多支持 8 个应用，所有应用须关联至少一个相同知识库
- 评测任务创建后配置不可修改，如需调整须创建新任务
- 评测期间请勿关闭应用观测，否则可能导致任务失败或数据丢失
- 评测集和评测任务为离线排队执行，排队期间进度为 0%
- 草稿状态的评测集不能用于评测任务，必须发布后使用
- 评测报告中仅显示成功用例，失败用例不计入正确率计算

## 最佳实践

### 持续评测触发时机

- 知识库更新后
- 调整 Prompt 或更换模型后
- 修改检索/重排策略后
- 定期回归（每周或每月）

### 优化闭环

1. 识别 BadCase（得分 < 4 分）
2. 根据归因类型定位问题
3. 实施针对性优化
4. 发布新版本，使用同一评测集再次评测
5. 对比新旧版本结果，验证改进效果
