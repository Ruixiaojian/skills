# 知识接入方式对比：Knowledge API vs 知识库指南 vs 数据连接概览

本页面向百炼平台开发者，系统对比三种核心知识接入能力的技术定位、能力边界与工程适用性。三者并非互斥替代关系，而是分层协同的架构组件：**数据连接（Data Connection）解决“数据从哪来”，知识库（Knowledge Base）解决“知识如何组织与增强”，Knowledge API 解决“能力如何标准化调用”**。明确差异有助于避免重复建设、选型失当或权限/地域误配，提升 RAG 应用开发效率与生产稳定性。

## 关键维度对比表

| 维度 | Knowledge API | 知识库指南（Knowledge Base） | 数据连接概览（Data Connection） |
|------|----------------|------------------------------|--------------------------------|
| **本质定位** | **标准化服务能力接口**：提供开箱即用的语义检索（`/search`）与端到端问答（`/chat`）RESTful 接口，封装底层 RAG 流程 | **知识管理与增强中枢**：提供知识库创建、多模态解析、联合召回、重排、路由等全生命周期管理能力，是 RAG 的“引擎+数据容器” | **外部数据源统一纳管通道**：实现结构化（DB）、非结构化（文件/OSS）及半结构化（语雀）数据的安全接入、同步与工具化调用 |
| **输入格式** | - `search`: JSON `{ "query": "文本", "top_k": N, "filter": {...} }`<br>- `chat`: JSON `{ "messages": [...] }`（支持历史上下文） | - 控制台：上传文件（PDF/Word/Excel/Markdown等）、配置元数据标签、设置相似度阈值等<br>- API：通过 `CreateIndex` 等 SDK 接口提交文档内容或 OSS 路径 | - 文件/表格：本地上传或 OSS 路径（需标签授权）<br>- 数据库：连接参数（地址、账号、网络配置）<br>- 语雀/OSS：[Token](../concepts/token.md) 或 Bucket 名称与向量服务状态 |
| **输出格式** | - `search`: JSON 数组，含 `content`, `source`, `score`, `metadata` 等字段的文本切片<br>- `chat`: SSE 流式响应，含 `planning`（规划）、`tool_calls`（工具调用）、`generation`（生成）三阶段结构化事件 | - 检索结果：经重排后的文本切片（含引用溯源、拒答标识）<br>- 问答结果：自然语言回答 + 可信度评分 + 引用来源高亮<br>- 日志：SLS 可投递的完整调用链日志（需手动开通） | - 工具调用结果：由具体连接器决定（如 `queryMySQL` 返回 JSON 表格；`searchYuQueDoc` 返回语雀文档摘要；`searchOSSFile` 返回向量匹配文件列表）<br>- 不提供统一语义问答输出 |
| **支持模型** | **不暴露模型选择权**：语义计算由平台托管模型完成（默认 `qwen3-plus` 等），开发者无需指定模型 ID | **全量支持百炼预置与自定义模型**：<br>- 文本：Qwen3/Qwen2.5/DeepSeek-R1/Llama3.1 等<br>- 多模态：VL-Max/Plus/OCR/Qwen3-VL<br>- 向量/排序：`text-embedding-v4`, `qwen3-vl-embedding`, `qwen3-rerank` 等 | **不直接调用 LLM 或 Embedding 模型**：仅作为数据通道，其输出可被下游模型（如知识库问答节点、智能体中的 LLM 节点）消费 |
| **API 端点** | - 检索：`POST https://{workspaceId}.cn-beijing.maas.aliyuncs.com/api/v1/indices/knowledge/search`<br>- 问答：`POST https://{workspaceId}.cn-beijing.maas.aliyuncs.com/api/v2/apps/knowledge/chat` | - 管理类：`CreateIndex`, `UpdateIndex`, `DeleteIndex`（SDK/API）<br>- 检索类：`Retrieve`（SDK/API），或通过绑定的知识问答服务统一调用 | - 无统一 RESTful 端点<br>- 通过智能体/工作流中预置工具调用（如 `queryMySQL`, `searchFile`, `searchYuQueDoc`），工具名即逻辑端点 |
| **计费方式** | **按调用次数计费**：<br>- `/search`: 按请求次数计费<br>- `/chat`: 按请求次数 + 生成 tokens 计费<br>（不单独收取知识库规格费） | **双重计费**：<br>- **规格费**：按小时计（标准版 0.03 元/小时，旗舰版 0.2 元/RCU/小时）<br>- **模型调用费**：向量化、Rerank（按初步召回量）、路由、问答生成均单独计费 | **按资源使用量计费**：<br>- 平台存储：文件连接器（200,000 文件/1TB 免费额度）、表格连接器（1TB 免费）<br>- 数据同步：DTS 流量费（数据库）、OSS 请求费<br>- 向量检索服务：OSS 连接器需额外开通并计费 |
| **典型场景** | - 快速构建轻量级 RAG 应用（如客服 FAQ 助手）<br>- 需要流式响应集成至前端对话界面<br>- 希望规避知识库管理复杂度，专注业务逻辑 | - 构建高精度、可调优的垂直领域知识助手（如法律/医疗/金融）<br>- 需多知识库联合召回、精细化排序与权重控制<br>- 要求引用溯源、拒答能力、日志审计与效果优化 | - 实时查询业务数据库（如订单/用户信息）<br>- 接入语雀/钉钉/飞书等协作平台知识<br>- 批量纳管企业内部 OSS 文档资产并支持向量检索 |

## 各方案的适用场景建议

### ✅ 优先选用 Knowledge API 的场景：
- **MVP 快速验证**：希望在 1 小时内跑通一个基于已有知识库的问答 Demo，无需配置知识库参数、重排模型或数据连接。
- **前端直连轻应用**：Web/App 客户端需直接调用后端服务获取答案，要求低延迟、流式响应、简单鉴权（Bearer [Token](../concepts/token.md)）。
- **标准化能力复用**：多个业务线共用同一套知识服务，但各自维护独立知识库，需统一入口和限流策略（25 QPS 默认）。

### ✅ 优先选用知识库指南（Knowledge Base）的场景：
- **效果深度调优需求**：需精细控制 `相似度阈值`、`初步 TopK`、`重排模型`、`知识库权重` 等参数以平衡准确率与成本。
- **多源异构知识融合**：同时接入文档库、表格库、图片库，并要求跨类型联合召回与统一排序。
- **强合规与可观测性要求**：需 SLS 日志审计、引用溯源、拒答保护、定期数据同步（OSS/飞书）及完整的配额监控。

### ✅ 优先选用数据连接概览（Data Connection）的场景：
- **实时动态数据依赖**：业务逻辑必须查询最新数据库记录（如库存、账户余额），而非静态快照。
- **非文本数据源接入**：需直接操作 MySQL 表、执行 PostgreSQL SQL、搜索语雀知识库原文、或在 OSS 中按文件名/关键词检索。
- **零知识库依赖的工具调用**：智能体流程中仅需“查数据库”或“搜语雀文档”作为原子步骤，不涉及语义理解或生成。

## 技术选型参考（面向开发者）

| 选型决策点 | 推荐方案 | 理由说明 |
|------------|----------|----------|
| **是否需要自己管理知识库生命周期（创建/更新/删除/同步）？** | 知识库指南 | Knowledge API 无法创建或修改知识库；数据连接仅负责接入，不提供知识组织能力。知识库指南是唯一支持全生命周期管理的方案。 |
| **是否必须调用特定 LLM（如 Qwen3-VL）或自定义排序模型？** | 知识库指南 | Knowledge API 和数据连接均不开放模型选择；知识库指南明确支持全量百炼模型及专用 rerank/embedding 模型。 |
| **是否需在一次请求中同时查询数据库 + 检索知识库 + 调用 API？** | 组合使用：数据连接 + 知识库指南 + Knowledge API | 典型智能体架构：用数据连接工具查实时 DB → 用知识库检索私有文档 → 将结果注入 Knowledge API `/chat` 进行最终生成。三者互补，非二选一。 |
| **是否受限于地域？** | 全部方案均**仅支持华北2（北京）** | Knowledge API Base URL、知识库服务、数据连接器创建页面均强制限定地域，跨地域部署将失败。务必在控制台确认 workspace 所属地域。 |
| **是否担心数据安全与权限隔离？** | 数据连接 > 知识库指南 > Knowledge API | 数据连接支持 RAM 精细授权、OSS 标签隔离、DMS 安全网关；知识库数据限定在 workspace 内；Knowledge API 依赖 workspaceId 隔离，但无额外 RBAC 控制。 |
| **是否追求最低接入成本与最快上线？** | Knowledge API | 无需创建知识库、无需配置连接器、无需开通 SLS 日志，仅需 API Key 和 workspaceId 即可发起 `curl` 测试。 |

> **重要提醒**：  
> - **三者非替代关系，而是分层协作**：数据连接提供“燃料”，知识库提供“引擎与油箱”，Knowledge API 提供“方向盘与仪表盘”。  
> - **所有方案均依赖 `workspaceId` 和 `API Key`**，且当前仅支持华北2（北京）地域，请在控制台创建业务空间时严格校验。  
> - 生产环境强烈建议：对 Knowledge API 启用客户端重连机制（应对 SSE 中断）；对知识库开启 SLS 日志投递；对数据连接器启用连通性检测并配置白名单。
