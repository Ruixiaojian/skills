# 知识增强方案对比：Knowledge API 与 Knowledge Base

本文旨在帮助开发者清晰理解百炼平台提供的两类核心知识增强能力——**Knowledge API**（即 `knowledge` 服务）与 **Knowledge Base**（知识库），明确其定位差异、能力边界与适用范式，从而在构建 RAG 应用、智能客服、内部助手等场景时做出高效、合规的技术选型。

二者虽均服务于“将私有/领域知识注入大模型”的目标，但设计哲学与工程实现存在本质区别：  
- **Knowledge API** 是一个**轻量级、托管式、开箱即用的语义问答服务接口**，面向快速集成与标准化调用，不暴露底层索引与模型控制权；  
- **Knowledge Base** 是一个**全生命周期可管可控的 RAG 基础设施**，提供从数据接入、解析切片、向量化索引到检索生成的完整链路，支持深度定制与规模化运营。

以下从关键维度展开系统性对比，并给出选型建议。

## 关键维度对比

| 维度 | Knowledge API | Knowledge Base |
|------|----------------|----------------|
| **本质定位** | 托管型 RESTful 服务接口（SaaS 化能力封装） | 可配置、可扩展的 RAG 基础设施（PaaS/IaaS 层能力） |
| **输入格式** | 纯文本 query（`/search`）或标准对话消息数组（`/chat`）；不支持文件上传 | 支持多格式文件上传（PDF/DOCX/TXT/图片/音视频等）+ 元数据配置 + 结构化标签；API 方式支持批量文件管理（SDK） |
| **输出格式** | • `/search`：JSON 格式文本切片列表（含 `content`, `score`, `metadata`）<br>• `/chat`：SSE 流式响应，含 `planning`/`tool_calls`/`generation` 三阶段结构化事件 | • 控制台/工作流：可视化结果 + 引用溯源高亮<br>• API：JSON 格式召回切片或生成答案（含 `citations` 字段）<br>• 支持[多模态](../concepts/multi-modal.md)输出（如图文混排、表格渲染） |
| **支持模型** | **不开放模型选择**：语义计算由平台统一调度（Embedding + LLM 均托管），无模型 ID 参数 | **完全开放模型协同**：<br>• 向量模型：`qwen3-vl-embedding` 等专用嵌入模型<br>• 排序/路由模型：`qwen3-rerank` 等<br>• 问答模型：Qwen 系列（Qwen3/Qwen2.5/Qwen2/Plus/Turbo）、DeepSeek-R1、Llama3.1、Yi-Large 等（需控制台可选） |
| **API 端点** | • 检索：`POST /api/v1/indices/knowledge/search`<br>• 问答：`POST /api/v2/apps/knowledge/chat`<br>• 统一鉴权：Bearer [Token](../concepts/token.md) + workspaceId 路径前缀 | • 管理类：`ApplyFileUploadLease`/`AddFile`/`CreateIndex`（SDK 封装）<br>• 检索类：`POST /v1/knowledge_base/{kb_id}/retrieve`<br>• 问答类：`POST /v1/knowledge_base/{kb_id}/chat`<br>• 鉴权：DashScope SDK 或 Bearer [Token](../concepts/token.md)（需对应权限） |
| **计费方式** | **按调用量计费（QPS + [Token](../concepts/token.md)）**：<br>• 默认限流 25 QPS（超限 429）<br>• 费用计入 DashScope API 总账单，无独立知识库规格费 | **双轨制计费**：<br>• **规格费用**：按知识库运行时长计费（标准版 0.03 元/小时；旗舰版按 RCU，0.2 元/RCU/小时）<br>• **模型费用**：独立计费，含向量/排序/路由/问答各阶段 Token 消耗（注意：排序费用按 *初步召回 TopK 总量* 计，非最终返回数） |
| **知识库管理** | **不可见、不可控**：仅对「已发布且 active」的知识库生效，开发者无法创建/编辑/删除知识库，也无法查看索引状态 | **全生命周期自主管理**：<br>• 控制台可视化操作（上传、解析、切片、发布、下线）<br>• 支持多知识库联合、权重分配、标签过滤、元数据抽取<br>• 提供命中测试、效果分析、切片调试等优化工具 |
| **典型场景** | • 快速验证知识问答效果<br>• 构建轻量级客服 Bot（无需知识运维）<br>• 作为现有系统插件式接入（如 CRM 内嵌问答框）<br>• PoC 或 MVP 阶段快速交付 | • 企业级知识中枢（如法务/HR/IT 内部知识平台）<br>• 多源异构文档（合同/手册/日志）的统一检索与推理<br>• 需要严格引用溯源、防泄漏、拒答控制的合规场景<br>• 与智能体（Agent）、工作流深度集成的复杂应用 |

## 适用场景建议

### ✅ 选择 **Knowledge API** 当：
- 你已有结构化知识库（如已部署好的 FAQ、产品文档库），仅需“调用即用”的语义检索或问答能力；
- 开发周期紧张，希望跳过知识入库、切片、索引等环节，直接对接 query → answer 链路；
- 应用对知识更新频率低（月度级），且无需精细化控制召回策略（如相似度阈值、元数据过滤）；
- 团队无专职 RAG 运维人员，倾向平台全托管、免运维模式；
- 需要流式响应（SSE）快速渲染对话界面，且接受平台默认的三阶段生成逻辑。

### ✅ 选择 **Knowledge Base** 当：
- 你需要从原始文件（PDF/扫描件/会议纪要/音视频字幕）出发，构建专属知识资产；
- 要求对召回精度、响应速度、成本结构进行精细调控（如动态调整 `TopK`、关闭重排序、设置元数据过滤条件）；
- 场景涉及多知识库协同（如“销售政策”+“技术白皮书”+“客户案例”联合检索），需权重/标签/时间范围等高级过滤；
- 必须满足合规要求：引用溯源（标注来源页码/时间戳）、内容拒答（敏感词拦截）、输出防泄漏（脱敏规则）；
- 计划长期运营知识库，需版本管理、效果监控（命中率/平均延迟）、A/B 测试及自动化 DevOps 同步（通过 SDK/API）；
- 已有成熟大模型应用架构，需将知识能力作为可插拔模块深度集成至 Agent 工作流或自定义 [Prompt 工程](../concepts/prompt-engineering.md)中。

## 技术选型参考（面向开发者）

| 选型考量项 | Knowledge API | Knowledge Base | 建议动作 |
|------------|----------------|----------------|----------|
| **是否需要上传原始文件？** | ❌ 不支持 | ✅ 支持 PDF/DOCX/图片/音视频等 | 若输入是文件 → 必选 KB |
| **是否需控制向量/排序/生成模型？** | ❌ 不可选 | ✅ 完全可选（控制台或 API 指定） | 若需模型微调/成本优化/效果归因 → 必选 KB |
| **是否需元数据过滤（如 `source: "manual"`）？** | ⚠️ 实测支持但未文档化（风险） | ✅ 显式支持（创建时配置 + 检索时传参） | 若依赖结构化过滤 → 优先 KB |
| **是否需引用溯源（精确到页码/时间戳）？** | ❌ 仅返回 `metadata` 字段（无原文定位） | ✅ 支持高亮引用 + 源文件锚点链接 | 若需审计/可信回答 → 必选 KB |
| **是否需多轮对话上下文改写？** | ❌ 无此能力 | ✅ 支持「多轮智能模式」自动重写 query | 若对话历史影响检索质量 → 必选 KB |
| **是否需与 Agent 工作流节点编排？** | ❌ 仅独立接口 | ✅ 原生支持「知识库」节点拖拽配置 | 若构建复杂智能体 → 必选 KB |
| **是否受限于地域？** | ✅ 全地域可用（随 DashScope 公共 endpoint） | ❌ 仅华北2（北京）地域可用 | 若部署在新加坡/法兰克福 → 只能选 Knowledge API |
| **是否需低于 1s 的 P95 响应延迟？** | ✅ 默认高并发（25 QPS） | ⚠️ 标准版仅 1 QPS；旗舰版需按 RCU 扩容 | 若超高实时性要求 → 评估 KB 规格配额 |

> 💡 **最佳实践提示**：  
> - **混合使用更高效**：可先用 Knowledge API 快速验证业务逻辑与用户反馈，再迁移至 Knowledge Base 进行规模化、精细化运营；  
> - **成本敏感型项目**：Knowledge API 适合低频、偶发问答；Knowledge Base 在高频、多知识源场景下单位查询成本更低（尤其启用缓存与合理 TopK 后）；  
> - **安全合规红线**：涉及金融、医疗、政务等强监管领域，Knowledge Base 提供的拒答、防泄漏、审计日志等能力为刚性需求，不可替代。
