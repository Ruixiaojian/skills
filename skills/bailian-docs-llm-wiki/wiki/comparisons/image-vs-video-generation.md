# 图像生成与视频生成对比

本页旨在为百炼平台开发者提供图像生成（Image Generation）与视频生成（Video Generation）两大核心多模态能力的系统性对比，帮助技术团队在实际项目中快速识别能力边界、理解调用差异、规避常见陷阱，并基于业务需求做出高效、稳定、可扩展的技术选型决策。随着AIGC应用从静态内容向动态表达演进，厘清二者在架构设计、资源消耗、开发成本与适用场景上的本质区别，已成为构建高质量AI内容生产流水线的关键前提。

## 关键维度对比

| 维度 | 图像生成（Image Generation） | 视频生成（Video Generation） |
|------|------------------------------|------------------------------|
| **输入格式** | • 文本提示（`prompt` 或 `input.messages`）<br>• 可选：基础图（`base_image_url`）、蒙版图（`mask_image_url`）、草图（`sketch_url`）、参考图（`reference_image_url`）等<br>• 支持纯文本、图文混合（多模态消息数组）输入 | • 文本提示（必填 `input.prompt`）<br>• 可选媒体输入：单图/首尾帧/多张参考图/原始视频（通过 `input.media` 数组指定，含 `type` 字段如 `"image_url"`、`"first_frame"`、`"reference_image"`、`"video"`）<br>• 不支持纯文本以外的非媒体类结构化输入（如动作序列、时间码） |
| **输出格式** | • 单张或多张静态图像（JPEG/PNG）<br>• 同步调用：直接返回含 `output.images`（URL列表）的JSON响应<br>• 异步调用：返回 `task_id`，轮询后获取 `output.images`（24小时有效期） | • 单个短视频文件（MP4/H.264）<br>• **强制异步**：始终返回 `task_id`，需轮询 `/tasks/{task_id}` 获取 `output.video_url`（24小时有效期）<br>• 输出不含帧序列或中间产物，仅最终合成视频 |
| **支持模型（典型代表）** | • **万相系列**：`wan2.7-image-pro`（4K文生图）、`wan2.6-t2i`（V2文生图）、`wanx-x-painting`（局部重绘）<br>• **千问系列**：`qwen-image-3.0-pro`（T2I/I2I一体化）、`qwen-image-2.0-pro`（强文本渲染）<br>• **轻量/专用**：`z-image-turbo`（极速）、`kling/kling-v3-omni-image-generation`（分镜组图）、`vidu/vidu-image_reference2image`（UI精准还原） | • **文生视频**：`wan2.7-t2v-2026-06-12`、`vidu/viduq3-turbo_text2video`、`kling/kling-v3-video-generation`、`happyhorse-1.1-t2v`<br>• **图生视频**：`pixverse/pixverse-c1-it2v`、`vidu/viduq3-pro-fast_img2video`、`wan2.7-r2v-2026-06-12`（参考生视频）<br>• **编辑增强**：`video-style-transform`、`pixverse/pixverse-upscale`、`videoretalk`（口型替换） |
| **API 端点（主流路径）** | • 同步：`POST /api/v1/services/aigc/multimodal-generation/generation`（推荐多数模型）<br>• 异步：`POST /api/v1/services/aigc/image2image/image-synthesis`（旧模型/编辑类）<br>• **注意**：路径与模型版本强绑定（如 `multimodal-generation` 适配 `wan2.7`/`qwen-image-3.0`；`image2image` 适配 `wanx-v1`/`wanx-x-painting`） | • **统一异步端点**：`POST /api/v1/services/aigc/video-generation/video-synthesis`（`wan2.7`/`vidu`/`kling`/`pixverse` 主流模型）<br>• **遗留路径**：`/api/v1/services/aigc/image2video/video-synthesis`（仅 `wan2.2` 等旧版模型）<br>• **无同步端点**：所有视频模型均不支持同步调用 |
| **调用模式** | • **同步与异步双模支持**：<br>  - 同步：`wan2.6+`、`wan2.7`、`qwen-image-3.0-pro`、`z-image-turbo` 等新模型默认支持，低延迟、易集成<br>  - 异步：`wanx-v1`、`wanx-sketch-to-image-lite`、免费体验模型等必须异步 | • **强制异步**：<br>  - 所有模型必须设置请求头 `X-DashScope-Async: enable`<br>  - 缺失该头将报错 `current user api does not support synchronous calls`<br>  - 开发者需自行实现任务创建 → 轮询 → 结果处理完整链路 |
| **计费方式** | • 按**成功生成的图片张数**计费（如 `n=3` 则计3次）<br>• 免费体验模型（如 `wanx-x-painting`）额度用尽即停用，**不支持付费开通**<br>• 分辨率影响计费等级（如 `4K` > `2K` > `1K`），但同模型内按张计费，不按像素或尺寸阶梯收费 | • 按**成功生成的视频任务次数**计费（1次任务 = 1次计费，无论时长或分辨率）<br>• **无免费体验额度**：所有视频模型均为付费服务<br>• 分辨率（`720P`/`1080P`）与时长（3s/5s/10s）可能影响单价，需查阅[计费详情页](https://help.aliyun.com/product/420491.html)确认具体模型费率 |
| **典型场景** | • 电商：商品主图生成、背景替换、AI试衣、海报设计<br>• 设计：创意插画、风格迁移、LOGO草图转高清、UI组件生成<br>• 内容创作：社交媒体配图、文章封面、个性化头像、教育图表绘制<br>• 工业：缺陷标注图生成、CAD示意图补全 | • 营销：短视频广告生成（产品展示、节日活动）、IP形象动态化<br>• 媒体：新闻可视化动效、数据故事短片、社交媒体竖版短视频<br>• 教育：知识讲解动画、实验过程模拟、语言学习情景视频<br>• 娱乐：数字人播报、虚拟偶像表演、游戏过场动画生成 |

## 适用场景建议

### ✅ 推荐优先选用图像生成的场景：
- **高频、轻量、实时性要求高**：如电商后台批量生成1000张商品图、设计工具中用户实时预览风格效果、CMS系统自动为文章配图。同步调用 + 低延迟响应是关键优势。
- **需要精细控制单帧质量**：如高精度UI还原（`vidu`）、复杂文字渲染（`qwen-image-2.0-pro`）、专业人像写真（`facechain`），图像模型在构图、细节、文本保真度上更成熟稳定。
- **预算敏感且用量可控**：利用免费体验模型（如局部重绘、虚拟模特）完成MVP验证；或通过 `z-image-turbo` 实现低成本快速出图。
- **已有图像资产需增强**：对存量图片做擦除补全、扩图、风格重绘、背景生成等，图像编辑类API天然契合。

### ✅ 推荐必须选用视频生成的场景：
- **内容表达依赖时间维度**：如展示产品使用流程、模拟物理运动（水流、火焰）、呈现人物表情/动作变化、制作带节奏感的营销短视频。
- **需保持角色/物体一致性**：通过参考生视频（R2V）技术，用3–5张参考图驱动生成10秒角色连贯视频，适用于品牌IP、虚拟主播、教育培训等强一致性需求场景。
- **已有视觉素材需动态化**：将静态海报转化为短视频、为产品首帧图添加镜头运镜、为PPT页面添加平滑过渡动画。
- **专业视频后期增强**：超分提升画质（`pixverse-upscale`）、为无声视频自动匹配口型（`videoretalk`）、替换视频整体艺术风格（`video-style-transform`）。

### ⚠️ 需谨慎评估或组合使用的场景：
- **“伪视频”需求**：若仅需3–5张关键帧GIF，优先用图像生成（多图+`n=5`）+ 前端合成，成本更低、可控性更强；仅当需真实运动连贯性、物理模拟或音频同步时，才启用视频生成。
- **长视频（>10秒）**：当前所有模型均不支持单次生成超10秒视频。需采用分段生成（如每5秒一段）+ 后期剪辑拼接，或选用支持续写的模型（如 `wan2.7` 的视频续写能力）。
- **高并发实时生成**：视频生成因强制异步+24小时任务有效期+普遍RPS=1限流，**不适合**高并发API网关直连（如万人同时点击“生成短视频”）。建议引入队列缓冲、任务池管理及结果缓存策略。

## 技术选型参考（面向开发者）

作为百炼平台开发者，在启动新项目前，请按以下 checklist 进行决策：

1. **明确核心产出物**  
   → 若交付物是**静态图像**（PNG/JPEG），直接进入图像生成技术栈；  
   → 若交付物是**视频文件**（MP4），必须使用视频生成API，无需犹豫。

2. **评估实时性与交互体验要求**  
   → 要求用户操作后 **<2秒内看到结果**（如设计工具实时预览）？→ 选支持同步的图像模型（`wan2.7-image-pro`, `qwen-image-3.0-pro`）。  
   → 可接受 **5–60秒等待+进度提示**（如营销平台“生成中…”）？→ 视频生成或图像异步模型均可，但视频生成必然在此区间。

3. **审查输入资产与工作流**  
   → 是否已有高质量首帧图/参考图/原始视频？→ 视频生成的图生视频（I2V）、参考生视频（R2V）将极大提升效果与一致性。  
   → 输入仅为文本描述？→ 文生图（T2I）与文生视频（T2V）均可，但需权衡：T2I成本低、质量稳、可批量；T2V成本高、耗时长、但具动态表现力。

4. **核算成本与用量规模**  
   → 小批量（日均<100次）、验证型项目：善用图像免费体验模型降低门槛。  
   → 大批量（日均>1000次）、生产环境：务必对比 `wan2.7-image-pro`（4K单图）与 `wan2.7-t2v-2026-06-12`（5秒视频）的单位成本，视频通常为图像的5–10倍；考虑是否可用图像+前端动效替代部分视频需求。

5. **检查地域与基础设施约束**  
   → 所有调用必须确保 **模型开通地域 = API Key所属地域 = Endpoint域名地域**（如华北2北京）。视频生成对此要求更严格，跨地域调用100%失败。  
   → 生产环境强烈推荐使用 **业务空间专属域名**（`https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com`），避免公共域名限流与稳定性风险。

6. **关注长期维护性**  
   → 优先选用 `wan2.7`、`qwen-image-3.0-pro`、`kling-v3` 等新一代模型，其接口统一（`input.messages`/`input.media`）、文档完善、持续迭代。  
   → 避免新项目接入 `wanx-v1` 等已标注“V1版已过时”的模型，未来可能下线且缺乏技术支持。

> **最后提醒**：图像与视频生成并非互斥，而是互补。最佳实践常为**分层生成**——先用图像生成产出高质量关键帧、分镜图或角色设定图，再以这些图像为输入，调用视频生成模型制作动态内容。百炼平台统一的鉴权体系与相似的参数设计（如 `watermark`, `resolution`），为这种协同工作流提供了坚实基础。
