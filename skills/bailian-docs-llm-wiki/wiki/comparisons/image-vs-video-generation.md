# 图像生成与视频生成对比

本文旨在帮助开发者清晰理解百炼平台中图像生成与视频生成两类能力的核心差异，为技术选型、架构设计与成本规划提供客观依据。随着多模态生成技术快速发展，图像与视频虽同属视觉内容生成范畴，但在计算范式、工程约束、服务协议及业务适配性上存在本质区别。本对比基于百炼平台当前（2024年中）正式发布的 API 能力与文档规范，聚焦实际开发落地的关键维度，避免理论泛化，强调可执行的技术判断依据。

## 关键维度对比

| 维度 | 图像生成 | 视频生成 |
|--------|-----------|------------|
| **输入格式** | 支持纯文本（[prompt](../guides/prompt.md)）、单张/多张图像 URL（JPG/PNG/WEBP）、掩码图、风格参考图；部分模型支持图文混排输入（如 `wan2.7-image-pro`） | 支持文本（[prompt](../guides/prompt.md)）、单张/多张图像 URL（首帧/尾帧/参考图）、音频 URL（数字人场景）、视频 URL（口型替换/重绘）；输入结构高度模型依赖（如 `wan2.7-r2v-*` 要求至少 1 张图 + [prompt](../guides/prompt.md)，`wan2.2-s2v` 要求 image_url + audio_url） |
| **输出格式** | 主要为 PNG（高保真），少数模型输出 JPG（如 `qwen-mt-image`）；返回图片 URL（有效期 24 小时）或 base64 数据（同步调用） | 统一为 MP4 视频文件（H.264 编码）；仅返回 `video_url`（有效期 24 小时），不支持 base64 响应 |
| **支持模型类型** | **通用生成模型**：`wan2.7-image-pro`、`qwen-image-3.0-pro`、`z-image-turbo`、`vidu/vidu-image_reference2image`、`kling/kling-v3-omni-image-generation`<br>**垂直工具模型**：`facechain-portrait-generation`、`image-out-painting`、`wanx-style-repaint-v1`、`wordart-quick-start` 等 | **通用生成模型**：`wan2.7-t2v-*`、`wan2.7-i2v-*`、`wan2.7-r2v-*`、`happyhorse/happyhorse-t2v`、`pixverse/pixverse-c1-t2v`、`vidu/vidu-reference-to-video`、`kling/kling-v3-omni-video-generation`<br>**数字人专用模型**：`wan2.2-s2v`、`emo-v1`、`liveportrait`、`videoretalk` 等 |
| **API 端点** | 分两类：<br>- **同步端点**（推荐）：`POST /api/v1/services/aigc/multimodal-generation/generation`（适用于 `wan2.7-image-pro`、`qwen-image-3.0-pro` 等）<br>- **异步端点**（必需）：如 `/api/v1/services/aigc/text2image/image-synthesis`（旧模型） | **统一异步端点**：<br>`POST /api/v1/services/aigc/video-generation/video-synthesis`（主流模型）<br>⚠️ 注意：`wan2.2` 等旧版模型使用 `/api/v1/services/aigc/image2video/video-synthesis`，路径不兼容 |
| **调用协议** | **混合协议**：新模型（V2.6+）默认支持同步响应；旧模型（V2.5 及以下）强制异步（需轮询 `task_id`） | **强制异步协议**：所有模型均需 `X-DashScope-Async: enable` 请求头；必须通过 `GET /api/v1/tasks/{task_id}` 轮询状态，无同步选项 |
| **计费方式** | 按**成功生成的图片张数**计费（失败/超时任务不计费）；多数模型含 500 张/90 天免费额度；部分垂直模型（如 `wanx-x-painting`、`shoemodel-v1`）**免费额度用尽后不可调用且不支持付费** | 按**成功生成的视频条数**计费（失败/超时任务不计费）；各模型独立计费，无跨模型共享额度；数字人模型（如 `emo-v1`）按并发任务数+时长复合计费，QPS 与并发数受严格限制 |
| **典型场景** | - 静态创意内容生产（海报、Banner、电商主图）<br>- 人像写真批量生成（FaceChain）<br>- UI/图表像素级还原（Vidu）<br>- 局部编辑与风格迁移（擦除补全、风格重绘）<br>- 文字艺术设计（WordArt） | - 动态营销素材（短视频广告、产品演示）<br>- 数字人播报/直播（S2V、EMO）<br>- 视频风格迁移与重绘（PixVerse、Vidu）<br>- 首尾帧动画生成（角色动作延展）<br>- 口型同步驱动（视频配音） |
| **地域与密钥约束** | API Key、Endpoint 地域、模型开通地域三者必须一致；跨地域调用导致鉴权失败 | 同样强约束：**模型、Endpoint URL、API Key 必须同地域**（如华北2北京），且业务空间专属域名（`{WorkspaceId}.cn-beijing.maas.aliyuncs.com`）为最佳实践 |

## 各方案适用场景建议

### ✅ 图像生成更适合：
- **高频、低延迟、确定性输出**需求：如电商详情页自动配图、A/B 测试多版本海报生成、设计稿快速原型验证；
- **精细化控制要求高**的场景：需精确指定分辨率（`1024*1024`）、水印开关（`watermark=false`）、提示词增强（`prompt_extend=true`）等；
- **轻量级集成**：同步调用无需管理任务生命周期，适合前端直连或 Serverless [函数调用](../concepts/function-calling.md)；
- **成本敏感型批量任务**：利用免费额度覆盖基础需求，且单张图片成本显著低于单条视频。

### ✅ 视频生成更适合：
- **动态表达强依赖**的业务：如企业数字人客服、短视频平台内容创作、教育类动画讲解；
- **多模态协同工作流**：需结合音频驱动（`s2v`）、视频参考（`r2v`）、首尾帧逻辑（`i2v-first-last`）等复杂输入；
- **专业级视频质量要求**：Vidu 的广告级参考生视频、Kling 的分镜连续性、PixVerse 的动作模仿等能力不可被图像替代；
- **已具备异步任务调度能力**的系统：能可靠处理 `task_id` 轮询、超时重试、结果缓存等工程链路。

### ⚠️ 不推荐混用或替代的典型误区：
- ❌ 用图像生成“逐帧合成”视频：效率极低（N 张图 ≈ N 倍成本+延迟），且无法保证帧间一致性与运动自然性；
- ❌ 用视频生成替代静态图：视频生成耗时长（通常 30–120 秒/条）、成本高（约 5–10 倍于单图）、接口复杂，纯静态需求属过度设计；
- ❌ 在未校验输入合规性前提下调用数字人模型：`emo-v1` 等必须先调用 `emo-detect-v1` 检测人脸质量，否则必然失败。

## 面向开发者的选型参考

作为技术决策者，请按以下优先级进行判断：

1. **明确输出形态本质需求**  
   → 若最终交付物是**静态图片**（网页展示、印刷物料、APP 图标），**直接选用图像生成**，无需考虑视频能力。  
   → 若最终交付物是**可播放的动态内容**（H5 广告、小程序短视频、数字人播报），**必须选用视频生成**，图像生成无法满足。

2. **评估系统架构兼容性**  
   → 若现有服务无异步任务管理能力（如无定时轮询、无任务状态存储），**优先选择图像生成中的同步模型**（如 `wan2.7-image-pro`），降低接入门槛。  
   → 若已构建成熟的任务队列（如基于 Redis 或消息队列），且能容忍 30 秒以上响应延迟，**视频生成可平滑集成**。

3. **核算真实成本与额度**  
   → 对比单位成本：以 `wan2.7-image-pro`（≈0.02 元/张） vs `wan2.7-t2v-2026-06-12`（≈0.15 元/条）为例，**单次视频成本 ≈ 7–8 张高质量图片**。需确认业务是否愿为动态性支付溢价。  
   → 关注额度隔离：图像免费额度**不可用于视频**，视频模型无通用免费池，需单独购买资源包。

4. **验证模型能力边界**  
   → 图像生成中，`vidu` 擅长文字渲染但不支持视频；`kling` 支持分镜图但非视频生成。  
   → 视频生成中，`wan2.2-s2v` 仅支持单图+音频，不支持纯文生视频；`pixverse-lipsync` 仅做口型替换，不生成新画面。  
   → **务必查阅对应模型的最新 API 参考文档，避免因命名相似（如 `wan2.7` 系列）误用跨模态能力**。

5. **强制遵守地域一致性**  
   → 无论图像或视频，**API Key、Endpoint、模型开通地域三者必须完全一致**。建议在初始化阶段即校验 `region_id`，并在 CI/CD 中固化地域配置，杜绝运行时错误。

> 💡 最佳实践提示：对于需“图+视”联动的复杂应用（如先生成产品图再生成演示视频），建议采用**解耦架构**——图像生成与视频生成分别调用各自最优模型，通过业务层串联，而非尝试用单一模型覆盖全部需求。
