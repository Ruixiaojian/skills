# 图像、视频与3D生成能力对比

本文旨在为开发者提供百炼平台中图像生成、视频生成与3D生成三大模态生成能力的系统性对比，帮助技术团队在实际业务场景中快速识别能力边界、评估接入成本、规避地域与协议陷阱，并做出符合长期演进目标的技术选型决策。随着AIGC从静态内容向动态化、空间化演进，理解三类能力在输入输出、模型生态、调用范式与工程约束上的差异，已成为构建下一代创意生产管线的关键前提。

## 关键维度对比表

| 维度 | 图像生成（Image Generation） | 视频生成（Video Generation） | 3D生成（3D Generation） |
|------|------------------------------|------------------------------|--------------------------|
| **核心输入格式** | 文本（`prompt`）、图像（`image_url`）、掩码图（`mask_image_url`）、多图（最多14张，含局部重绘/参考图） | 文本（T2V）、单图/首帧/首尾帧（I2V）、多图（R2V）、视频+音频（编辑/对口型）、混合参考（图像+视频+音频） | 文本（文生3D）、单张图像（单图生3D）、四视角图像数组（【前、左、后、右】，多图生3D） |
| **核心输出格式** | JPEG/PNG 格式图片 URL（支持 512×512 至 4K 分辨率），部分模型支持返回优化提示词、置信度图等辅助输出 | MP4 格式视频 URL（典型时长 2–5 秒，分辨率支持 720P/1024×576/1280×720 等），部分模型返回预览帧或元数据（如关键帧时间戳） | GLB 格式 PBR 材质3D模型 URL（默认）、无贴图基础网格 URL（需显式关闭 `pbr` & `texture`）、渲染预览图 URL（PNG） |
| **支持模型/功能体系** | • 通用模型：`qwen-image-3.0-pro`、`wan2.6-t2i`、`wan2.7-image-pro`、`z-image-turbo`<br>• 垂直工具：背景生成、AI试衣、人像风格重绘、擦除补全等<br>• 增强模型：`facechain`（写真训练）、`outfitanyone`（试衣精修） | • T2V：`wan2.7-t2v`、`vidu/viduq3-turbo_text2video`、`kling/kling-v3-video-generation`<br>• I2V/R2V：`wan2.7-i2v`、`pixverse/pixverse-c1-r2v`、`happyhorse-1.1-t2`<br>• 编辑增强：指令编辑、风格重绘、动作模仿、超分<br>• 数字人驱动：`emo-v1`、`liveportrait`、`videoretalk` | • `Tripo/Tripo-H3.1`（高精度，≤200万面，支持 `ultra` 几何质量）<br>• `Tripo/Tripo-P1.0`（快速生成，≤2万面）<br>• *仅 Tripo 官方模型，暂无国产替代或轻量分支* |
| **API 端点（推荐）** | `https://{WorkspaceId}.{region}.maas.aliyuncs.com/api/v1/services/aigc/image-generation/image-synthesis`（同步/异步共用路径，行为由 `X-DashScope-Async` 头决定） | `https://{WorkspaceId}.{region}.maas.aliyuncs.com/api/v1/services/aigc/video-generation/video-synthesis`（万相2.7及主流模型统一路径；旧版 `image2video` 已逐步淘汰） | `https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/api/v1/services/aigc/video-generation/3d-generation`（**仅华北2北京地域**，路径命名含 `video-generation` 属历史遗留，实际为3D专属） |
| **调用模式** | **混合模式**：<br>• 同步：`qwen-image-3.0-pro`、`wan2.7-image-pro`、`z-image-turbo` 等新模型支持直接返回结果（HTTP 200）<br>• 异步：`kling`、`vidu`、`wanx-*` 系列等必须轮询任务状态 | **强制异步**：<br>所有模型均需两步调用：`POST` 创建任务 → `GET` 轮询 `task_id`；任务有效期 24 小时；不支持同步响应 | **强制异步**：<br>严格两步流程：`POST` 创建任务 → `GET` 轮询 `task_id`；任务有效期 24 小时；缺失 `X-DashScope-Async: enable` 头将直接报错 |
| **计费方式** | • 按**成功生成的输出图片张数**计费（免费额度 500 张/90天）<br>• 商业化模型单价示例：`wanx-v1` 0.16元/张<br>• 输入图、失败任务不计费 | • 按**模型粒度独立计费**：<br>  - T2V/I2V：按生成秒数或“次”（如 `wan2.7-t2v` 按 2 秒视频计 1 次）<br>  - 数字人驱动：按“处理时长秒数”或“任务次”（如 `emo-v1` 按音频时长计费）<br>• 免费额度分散（如 `emo-detect-v1` 200 张） | • 按**任务成功次数**计费（无论输出面数高低）<br>• `Tripo-H3.1` 与 `Tripo-P1.0` 单价不同（H3.1 更高）<br>• 无公开免费额度，需开通服务后查看控制台资费页 |
| **地域约束** | **强隔离**：API Key、Endpoint、模型开通必须同地域（华北2、新加坡、美东）；跨地域调用鉴权失败 | **强绑定**：模型、API Key、Endpoint 必须同地域；混用导致 404 或鉴权错误；新加坡/美东已支持主流模型 | **绝对锁定**：**仅支持华北2（北京）地域**；其他地域 Endpoint / API Key 均不可用；控制台开通入口亦仅限北京地域 |
| **典型场景** | • 电商素材批量生成（主图/详情图/场景图）<br>• 社媒内容创作（海报/头图/表情包）<br>• 设计辅助（背景替换、局部修改、风格迁移）<br>• AI试衣、虚拟模特上身 | • 短视频营销（文生剧情短视频、产品演示动画）<br>• 数字人播报（新闻/客服/培训视频）<br>• 影视预演（分镜生成、镜头衔接）<br>• 视频增强（老片修复、口型同步、画质超分） | • 游戏/AR/VR 资源快速建模（道具、角色基础网格）<br>• 工业设计原型验证（产品外观可视化）<br>• 电商3D商品展示（单图转可交互3D模型）<br>• 教育/医疗三维可视化（解剖结构、机械拆解） |

## 各方案适用场景建议

### ✅ 推荐选择图像生成当：
- 需要**高频、低延迟、确定性交付**的静态视觉内容（如每日千张电商图生成）；
- 业务链路中已存在成熟图像处理流水线（如 CDN 分发、尺寸裁剪、水印叠加），希望无缝集成生成能力；
- 对成本敏感且需利用免费额度启动 MVP（500 张/90天足够验证创意可行性）；
- 场景高度垂直（如试衣、背景生成、擦除补全），可直接复用平台封装好的专用模型，避免自研后处理逻辑。

### ✅ 推荐选择视频生成当：
- 目标是**动态叙事表达**而非单帧美感（如品牌广告片、知识科普短视频、数字人直播）；
- 具备音视频基础设施（如对象存储、CDN、播放器 SDK），能承接 MP4 下载与分发；
- 需要**[多模态](../concepts/multi-modal.md)协同控制**（如用首尾帧定义运动轨迹 + 文本描述中间过程 + 音频驱动口型）；
- 接受 5–10 分钟级任务等待周期，并已设计好前端轮询降级策略（如超时提示、邮件通知）。

### ✅ 推荐选择3D生成当：
- 业务本质依赖**三维空间表达**（如游戏资产管线、AR 商品预览、工业仿真）；
- 输入资源具备明确几何先验（单张正视图或四视角照片），且能保障公网可访问性与分辨率（≥256px）；
- 团队具备 3D 渲染基础（如 Three.js、Unity、Unreal），能解析 GLB/PBR 材质并集成至自有引擎；
- **接受地域锁定限制**，且已规划北京地域部署架构（或可接受跨地域数据传输成本）。

### ⚠️ 需谨慎评估或规避的情形：
- **跨模态强行替代**：  
  ❌ 不要用图像生成替代视频生成（无法表达时序）；  
  ❌ 不要用视频生成替代3D生成（缺乏拓扑结构与物理属性）；  
  ❌ 不要用3D生成替代图像生成（渲染开销大、实时性差、细节保真度当前仍弱于2D）。
- **地域混用**：  
  ❌ 图像/视频服务开通于新加坡，却用北京 API Key 调用——必然失败；  
  ❌ 3D服务**只能在北京开通与调用**，任何其他地域尝试均为无效操作。
- **协议误用**：  
  ❌ 对 `kling` 或 `vidu` 图像模型省略 `X-DashScope-Async: enable` 头——直接报错；  
  ❌ 对 `wan2.2-kf2v` 等旧版视频模型使用 `/video-generation/` 路径——404；  
  ❌ 对3D接口传入 `input.prompt` 与 `input.image` 并存——`InvalidParameter` 错误。

## 面向开发者的技术选型参考

1. **优先验证地域一致性**：  
   在编码前，务必确认——模型开通地域、API Key 所属地域、Endpoint 域名地域、业务服务器部署地域——四者完全一致。这是所有调用成功的**第一道门槛**。

2. **异步任务治理是必修课**：  
   视频与3D生成强制异步，图像生成部分模型也需异步。建议统一采用以下工程实践：  
   - 使用 `task_id` 作为业务唯一标识，写入数据库并关联用户请求；  
   - 实现指数退避轮询（初始1s，上限15s），避免高频请求触发限流；  
   - 对接异步回调（Webhook）替代轮询，提升系统响应性（[文档](https://help.aliyun.com/zh/model-studio/async-task-api)）；  
   - 设置 `task_id` 24小时过期清理机制，防止僵尸任务堆积。

3. **输入 URL 是高频故障点**：  
   - 所有图像/视频/音频 URL 必须公网可直连（禁用内网地址、私有OSS签名URL、含中文路径URL）；  
   - 建议在调用前增加 `HEAD` 请求校验可用性；  
   - 多图场景（3D四视角、视频参考图）注意顺序与空占位符 `{}` 的语义准确性。

4. **模型选型遵循「够用+演进」原则**：  
   - 初期选用 `qwen-image-3.0-pro`（图像）、`wan2.7-t2v`（视频）、`Tripo-P1.0`（3D）作为基准模型，平衡效果与成本；  
   - 高阶需求再升级：4K图用 `wan2.7-image-pro`，长视频用 `kling`，高精模型用 `Tripo-H3.1`；  
   - 关注文档中标注的「推荐迁移」路径（如 `wanx-*` 模型已明确要求迁移到 `qwen-image-edit`），避免技术债累积。

5. **计费监控前置化**：  
   - 在控制台开通「用量告警」，对图像张数、视频秒数、3D任务数设置阈值提醒；  
   - 对接账单 API，将生成成本映射到具体业务单元（如「某SKU每日生成成本」）；  
   - 免费额度用尽后，自动切换至付费通道——需在代码中捕获额度耗尽错误（如 `QuotaExceeded`）并触发降级逻辑。

> 技术选型没有银弹，但清晰的能力地图与严格的工程规范，能让 AIGC
