# [知识库](../concepts/knowledge-base.md)与[长期记忆](../concepts/memory.md)能力对比

本文旨在帮助开发者清晰区分百炼平台中两类核心记忆增强能力：**[知识库](../concepts/knowledge-base.md)（Knowledge Base）** 与**[长期记忆](../concepts/memory.md)（Long Term Memory，新）**。二者虽均支持语义检索与上下文增强，但设计目标、数据来源、生命周期管理及适用架构存在本质差异。正确选型可显著提升 RAG 应用的准确性、时效性与工程可维护性。本文基于最新控制台能力、API 规范与配额文档整理，适用于智能体（Agent）、工作流（Workflow）及自定义模型服务等典型场景。

## 关键维度对比

| 维度 | [知识库](../concepts/knowledge-base.md)（Knowledge Base） | [长期记忆](../concepts/memory.md)（Long Term Memory，新） |
|------|--------------------------|----------------------------------|
| **核心定位** | 面向**领域知识注入**的 RAG 基础设施，用于增强模型对私有/专业/时效性内容的理解与生成能力 | 面向**用户状态建模**的记忆管理系统，用于持久化跨会话的用户偏好、习惯、任务、画像等个性化信息 |
| **输入格式** | 支持多源异构数据：<br>• 文档（PDF/Word/Excel/PPT/TXT/HTML）<br>• 表格（CSV/Excel，支持结构化字段抽取）<br>• 音视频（ASR+OCR 后文本切片）<br>• 纯文本（通过 API 批量导入） | 以**对话上下文**或**短文本片段**为主：<br>• `messages`：最多 50 条对话记录（role/content 格式）<br>• `custom_content`：≤512 字符纯文本<br>• 支持 `meta_data`（键值对）标注来源、场景等元信息 |
| **输出格式** | 检索结果为**结构化切片列表**（`retrieved_chunks`），含：<br>• `content`（原始文本片段）<br>• `score`（相似度分）<br>• `source`（文件名/URL/页码）<br>• `metadata`（用户定义字段）<br>问答服务额外返回带引用标记的自然语言回答 | 检索结果为**记忆节点列表**（`memory_nodes`），含：<br>• `content`（提炼后的关键事实，如“每天9点喝水”）<br>• `id`（唯一记忆 ID）<br>• `created_at` / `updated_at`<br>• `meta_data`（写入时携带的元数据）<br>• `profile_fields`（若启用画像抽取） |
| **支持模型** | • **显式指定**：需在应用/工作流中绑定预置模型（Qwen 系列、DeepSeek-R1、Llama3.1 等）或自定义调优模型<br>• **向量模型可选**：`text-embedding-v4/v3`（文本）、`qwen3-vl-embedding`（文档视觉理解）、`multimodal-embedding-v1`（图片问答） | • **完全托管**：底层提取、向量化、摘要、画像抽取等均由平台统一模型链完成<br>• **不暴露模型选择权**：开发者无需配置或感知具体模型，仅通过 API 参数控制行为 |
| **API 端点** | • 检索：`POST /v1/apps/{app_id}/knowledge_retrieve`（工作流内）<br>• 独立服务：`POST /v1/knowledge_bases/{kb_id}/retrieve`<br>• 管理：`POST /v1/knowledge_bases`（创建）、`PUT /v1/knowledge_bases/{id}/files`（导入） | • 统一 RESTful 命名空间：<br> `POST /api/v2/apps/memory/add`<br> `POST /api/v2/apps/memory/search`<br> `GET /api/v2/apps/memory/list`<br>• SDK 封装：`agentscope-runtime` 提供 `AddMemory`, `SearchMemory` 等高层工具类 |
| **计费方式** | • **规格费**：按小时计费（标准版 0.03 元/小时；旗舰版 0.2 元/RCU/小时）<br>• **模型费**：独立计算：<br> – `qwen-plus` 路由判断（如启用）<br> – Rerank 排序（费用 = 初步召回总切片数 × 单切片 [Token](../concepts/token.md) 成本）<br> – 大模型生成（问答服务中）<br>• **存储费**：按知识库规格包含，超出部分按对象存储计费 | • **无规格费/存储费**：按调用次数计费（QPM 限流，非用量计费）<br>• **无模型费**：所有记忆处理（提取、向量化、搜索）均为平台能力，不产生额外模型调用费用<br>• **当前免费公测中**（以控制台最新公告为准） |
| **地域支持** | **仅华北2（北京）地域可用**，其他地域（如新加坡、法兰克福）不可用 | **全地域支持**（与 DashScope API 一致，覆盖阿里云全部公共云 Region） |
| **数据生命周期** | • 数据静态持久化：上传后长期存在，无自动过期<br>• 更新需重新导入或手动编辑切片<br>• 不支持按时间/事件自动清理 | • **支持规则级过期**：可在控制台为记忆库/项目配置 `memory_expiration_time`（7/30/180 天或永不过期）<br>• 自动去重更新（`auto_update=true` 默认开启）<br>• 支持显式 `DeleteMemory` 或批量清理 |
| **典型场景** | • 客服知识库：产品手册、FAQ、工单历史<br>• 企业内搜：合同库、制度文档、会议纪要<br>• 多模态问答：图纸解读、PPT 内容问答、财报表格分析<br>• 实时资讯接入：新闻稿、研报、公告 PDF 流式更新 | • 个人助理：日程提醒、饮食偏好、健康目标追踪<br>• 销售助手：客户沟通要点、历史承诺、跟进计划<br>• 教育 Agent：学生学习进度、错题记录、薄弱知识点<br>• 智能家居控制：设备使用习惯、常用指令组合、家庭成员偏好 |

## 适用场景建议

### ✅ 优先选用**知识库**当：
- 你需要将**大量、静态、结构化/半结构化**的业务文档（如 PDF 手册、Excel 表格、PPT 方案）作为权威知识源；
- 场景要求**高精度溯源**（如“请引用第3页原文”），且需保留原始格式、页码、表格行列等上下文；
- 数据具有**强时效性**（如每日更新的行情报告、政策文件），需支持高频增量导入与快速检索；
- 应用需**多模态理解能力**（如从扫描件中识别表格、从 PPT 中提取图表说明）；
- 已有成熟文档治理体系，希望零代码接入工作流或通过 SDK 构建定制化 RAG 管道。

### ✅ 优先选用**长期记忆**当：
- 你的核心需求是**建模用户个体状态**，而非注入通用知识（例如：“张三喜欢咖啡、过敏花生、常订周二会议”）；
- 数据天然来自**对话交互流**，需自动提炼关键事实（如“帮我取消明天下午的会议” → 记忆：“会议已取消，时间：2025-04-10 14:00”）；
- 需要**跨会话持续记忆**且支持自动过期（如临时验证码 5 分钟失效、旅行计划 30 天后归档）；
- 希望快速集成到 Agent 框架（如 OpenClaw），利用 `autoCapture`/`autoRecall` 插件实现开箱即用；
- 追求**低运维成本与确定性成本**，避免模型费用波动与向量模型选型复杂度。

### ⚠️ 避免混淆的边界情况
- **❌ 不要用知识库存用户聊天记录**：知识库切片粒度粗（默认 512+ [Token](../concepts/token.md)）、无用户隔离、不支持语义去重，易造成隐私泄露与噪声累积。  
- **❌ 不要用长期记忆存产品说明书**：记忆库单条 `custom_content` ≤512 字符，无法承载长文档；无文件解析、表格识别、多页关联等能力。  
- **✅ 可协同使用**：典型架构为——知识库提供“世界知识”（What the system knows），长期记忆提供“用户知识”（What the user needs），两者检索结果共同注入大模型 Prompt。

## 技术选型参考（面向开发者）

| 选型考量项 | 知识库 | 长期记忆 |
|------------|--------|-----------|
| **集成复杂度** | 中高：需处理文件解析、切片策略、元数据映射、路由逻辑；工作流需手动拼接 `{kb1/result}` 变量 | 低：SDK 提供开箱即用工具类；OpenClaw 插件一键启用；REST API 接口简洁统一 |
| **调试可观测性** | 强：SLS 日志完整记录检索 Query、召回切片、Rerank 排序过程、命中率统计 | 中：提供 `request_id` 用于排查；控制台可查看记忆库卡片与记忆节点列表，但无细粒度检索日志 |
| **数据安全与隔离** | • 租户级隔离<br>• 知识库间硬隔离<br>• 支持字段级权限（企业版） | • `user_id` 为强隔离边界，不同用户记忆绝对不可见<br>• 默认记忆库受账号级管控，新建库可分配给子账号 |
| **扩展性** | • 支持多知识库联合检索（最多 15 个）<br>• 可对接外部向量数据库（自建 Milvus/PGVector） | • 支持多记忆库（`memory_library_id`），但当前主流实践为单库多用户<br>• 用户画像模板（`profile_schema`）支持灵活扩展结构化字段 |
| **未来演进方向** | • 增强实时流式索引（Kafka/EventBridge 接入）<br>• 更细粒度权限控制（行级/列级）<br>• 与百炼 Data Studio 深度打通 | • 记忆推理能力增强（如自动推导用户意图、冲突检测）<br>• 与百炼 Agent 编排引擎深度协同（记忆驱动的 Agent 自主规划）<br>• 支持更长 `custom_content` 与富媒体记忆（图片描述、音频摘要） |

> **决策口诀**：  
> **“文档找知识库，用户找长期记忆；静态靠导入，动态靠对话；溯源看原文，个性看提炼。”**  
> 若仍不确定，建议先用长期记忆快速验证用户状态建模效果，再以知识库补充领域知识盲区——二者非互斥，而是百炼智能体能力栈的左右手。
