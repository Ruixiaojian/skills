# 知识管理方案对比：知识库与记忆库

为帮助开发者在百炼平台上高效构建具备专业性与连贯性的智能应用，本文对两类核心知识管理能力——**知识库（Knowledge Base）** 与**记忆库（Memory Library）** 进行系统性对比。二者虽均以“增强大模型能力”为目标，但在设计目标、技术路径、适用边界和工程实践上存在本质差异。本对比聚焦实际开发选型需求，从输入输出、模型依赖、集成方式、计费逻辑等关键维度展开分析，避免概念混淆，助力技术决策。

## 关键维度对比

| 维度 | 知识库（Knowledge Base） | 记忆库（Memory Library） |
|------|--------------------------|---------------------------|
| **核心定位** | 面向**领域知识注入**：将结构化/非结构化私有数据（文档、表格、音视频等）转化为可检索的语义知识源，提升回答的专业性与事实准确性 | 面向**用户状态持久化**：自动提取并存储跨会话的用户偏好、习惯、意图、画像等个性化信息，实现对话连贯性与个性化体验 |
| **输入格式** | 支持多源异构数据：<br>• 本地文件（PDF/Word/Excel/PPT/图片/音视频等，≤150MB）<br>• OSS、飞书、钉钉、语雀、SharePoint 等外部系统定时/即时同步<br>• 文本切片（经平台智能分块，单切片≤6000 [Token](../concepts/token.md)） | 支持轻量级语义输入：<br>• 对话消息数组（`messages`，最多50条，一问一答计2条）<br>• 纯文本内容（`custom_content`，≤512字符）<br>• 结构化元数据（`meta_data`，如 `{"category": "health_reminder"}`）<br>• 用户画像模板 ID（`profile_schema`） |
| **输出格式** | 返回**语义相关性排序后的知识切片列表**（含原文片段、来源文档、相似度分数），作为上下文注入大模型；支持极速模式（单次检索）或多轮智能模式（Agentic 规划） | 返回**结构化记忆节点（Memory Node）列表**，每项包含 `content`、`id`、`created_at`、`meta_data` 等字段；支持分页、过滤、按相似度阈值（`min_score`）筛选 |
| **支持模型** | **分层解耦，模型职责明确**：<br>• 向量模型：`text-embedding-v4/v3`（文本类）、`qwen3-vl-embedding`（[多模态](../concepts/multimodal.md)类，强制绑定）<br>• 排序模型：`qwen3-rerank` / `qwen3-vl-rerank`（可选）<br>• 问答模型：由用户在智能体/工作流中自主选择（如 `qwen3.7-plus`），知识库仅提供上下文 | **模型封装，开箱即用**：<br>• 底层由百炼自研记忆理解与检索模型驱动，**无需用户指定基础大模型**<br>• 检索策略通过 `plan_version` 控制：`pro`（启用 Rerank）或 `lite`（基础向量检索） |
| **API 端点** | • `Retrieve`（检索）<br>• `ApplyFileUploadLease` + `AddFile`（上传）<br>• 所有 API **仅限华北2（北京）地域可用** | • `POST /api/v2/apps/memory/add`（写入）<br>• `POST /api/v2/apps/memory/memory_nodes/search`（检索）<br>• `GET /api/v2/apps/memory/memory_nodes/list`（列表）等<br>• **全地域可用**（无地域限制） |
| **计费方式** | • **规格费**：按小时计费（标准版 ¥0.03/小时；旗舰版按 RCU）<br>• **模型调用费**：独立计费，含 Query 向量化、Rerank 排序、路由判断、问答生成等环节，费用取决于实际 [Token](../concepts/token.md) 消耗<br>• **关键成本敏感点**：`初步向量检索 TopK` 值直接影响 Rerank 费用（费用 = 召回总切片数 × 平均 [Token](../concepts/token.md) 数 × 单价） | • **按次计费**（商业化起始时间：2026年8月20日10:00）：<br> – `AddMemory`：Pro ¥0.03/次，Lite ¥0.018/次<br> – `SearchMemory`：Pro ¥0.001/次，Lite ¥0.00002/次<br>• `plan_version` 参数决定计费档位，**优先级高于 `enable_rerank`** |
| **典型场景** | • 客服知识问答（基于产品手册、FAQ、工单记录）<br>• 企业内部文档智能搜索（合同、制度、财报）<br>• [多模态](../concepts/multimodal.md)内容检索（图片中文字识别+问答、视频关键帧检索）<br>• 行业报告分析（PDF 表格数据抽取+语义查询） | • 个人助理（“每天9点提醒我喝水”、“我不吃香菜”）<br>• 销售助手（记住客户行业、预算、上次沟通痛点）<br>• 教育应用（持续跟踪学生错题、学习偏好、薄弱知识点）<br>• 电商导购（记录历史购买、尺码偏好、退换货习惯） |
| **数据生命周期** | • 文件级副本管理：同步规则创建的文件为独立副本，源文件删除后不自动清除<br>• 切片无自动过期机制，需人工清理或配置标签过滤 | • 记忆片段/用户画像**无默认自动过期机制**<br>• 过期时间由 `CreateMemoryProject` 的 `expired_in_days` 参数显式控制（未配置则按规则默认值，如180天；可设为永不过期） |
| **权限与隔离** | • 按「业务空间」隔离，支持多知识库联合检索（最多15个）<br>• 权重配置、路由判断支持精细化知识融合 | • 严格按 `user_id` 隔离，天然支持多租户<br>• 支持多应用共享同一记忆库，也支持细粒度规则（`project_id`）配置 |

## 适用场景建议

### ✅ 选择知识库，当您需要：
- **注入静态、权威、批量的领域知识**（如企业规章制度、产品文档、技术白皮书、历史报表）；
- 处理**复杂格式数据**（PDF 表格、PPT 图表、音视频内容）并要求高精度语义理解；
- 构建**面向公众或内部员工的通用问答系统**，答案需强事实依据与可溯源；
- 需要**多知识源联合检索与权重调控**（例如：优先返回最新版本合同，其次参考历史案例）；
- 对检索结果的**可解释性与调试能力要求高**（支持命中测试、切片编辑、相似度阈值调优）。

### ✅ 选择记忆库，当您需要：
- **维护用户个性化状态**，实现跨会话上下文延续（如习惯、偏好、待办、身份属性）；
- 快速接入**轻量级[长期记忆](../concepts/memory.md)能力**，无需管理向量模型、索引构建、分块策略等底层细节；
- 构建**强交互性、高个性化**的智能体（如私人助理、专属顾问、教育陪练）；
- 依赖**自动化记忆提取**（`autoCapture`）与**零代码注入**（`autoRecall` 插件）降低开发门槛；
- 要求**严格的用户数据隔离**与灵活的生命周期控制（按用户、按规则设置过期策略）。

### ⚠️ 注意：二者并非互斥，而是互补
- **典型组合模式**：在智能体中，**知识库提供领域知识上下文**（如“公司差旅报销标准”），**记忆库注入用户个性化约束**（如“张三偏好高铁而非飞机”），两者共同作为 LLM 的 Prompt 输入，实现“专业 + 个性”的双重增强。
- **工程实践建议**：优先使用记忆库管理用户侧动态状态；将组织级、静态、高价值知识沉淀至知识库；避免将用户聊天记录直接导入知识库（易引发隐私与性能问题）。

## 技术选型参考（面向开发者）

| 选型考量 | 知识库推荐做法 | 记忆库推荐做法 |
|----------|----------------|----------------|
| **快速验证 MVP** | 使用控制台上传少量 PDF/Word，开启「极速模式」快速验证检索效果；避免初期配置过高 TopK 增加成本 | 直接调用 `AddMemory`/`SearchMemory` API 或集成 OpenClaw 插件，5 分钟完成记忆闭环；`top_k=5`、`min_score=0.3` 为安全起点 |
| **生产环境部署** | • 必须部署于华北2（北京）地域<br>• 启用 SLS 日志监控，关注 `latency` 与 `response_code`<br>• 对高频查询启用「多轮智能模式」提升召回率<br>• 定期清理无效切片与冗余标签 | • 全地域可用，无需地域适配<br>• 合理设置 `plan_version`：高频低敏感场景用 `lite`，高精度需求用 `pro`<br>• 通过 `meta_data` 实现业务维度分类（如 `"source": "web_chat"`），提升检索精度<br>• 主动调用 `ListMemory` + `DeleteMemory` 进行定期归档 |
| **成本优化重点** | • 严控 `初步向量检索 TopK`（建议 20–50），避免 Rerank 过度消耗<br>• 关闭非必要功能（如视觉理解、关键词检索）<br>• 使用「智能切分」替代固定长度分块，减少冗余切片 | • `SearchMemory` 高频调用优先选用 `lite` 版本<br>• `AddMemory` 避免重复写入相同语义内容（利用 `auto_de_duplication` 或业务层去重）<br>• 设置合理 `expired_in_days`，避免无效记忆长期占用资源 |
| **扩展性与治理** | • 通过「标签过滤」+「元数据抽取」构建知识治理体系<br>• 利用「多知识库联合检索」实现知识域划分（如法务库、HR库、IT库） | • 创建多个 `MemoryProject` 实现不同业务线记忆隔离<br>• 定义标准化 `profile_schema` 统一用户画像字段（避免语义歧义）<br>• 将 `user_id` 与业务主键（如 `customer_id`）强绑定，保障数据一致性 |

> **最后提醒**：知识库是“**让模型知道更多**”，记忆库是“**让模型记住更多**”。正确区分二者边界，是构建健壮、可演进、可治理的智能应用的第一步。
