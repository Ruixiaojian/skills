# [长期记忆](../concepts/memory.md)与知识库方案对比

为帮助开发者在构建智能体（Agent）、对话系统或 RAG 应用时做出合理技术选型，本文系统对比百炼平台两大核心状态与知识管理能力：**[长期记忆](../concepts/memory.md)（新）** 与 **知识库**。二者虽均支持语义检索与上下文增强，但设计目标、数据生命周期、适用架构存在本质差异。本对比聚焦工程落地关键维度，避免概念混淆，助力高效集成。

| 维度 | [长期记忆](../concepts/memory.md)（新） | 知识库 |
|------|----------------|---------|
| **核心定位** | 用户级、会话级的**动态状态持久化**能力，面向 Agent 的“个人记忆”建模 | 领域级、应用级的**静态知识注入**能力，面向 RAG 的“外部知识源”管理 |
| **输入格式** | 结构化对话消息（`messages` 数组，≤50 条）或轻量自定义文本（`custom_content`，≤512 字符） | [多模态](../concepts/multi-modal.md)原始文件（PDF/Word/Excel/图片/音视频等），自动切片、向量化；支持 OSS 批量导入 |
| **输出格式** | JSON 格式记忆片段列表，含 `memory_node_id`、`content`、`score`、`meta_data` 等字段；支持用户画像对象（`UserProfile`） | JSON 格式检索结果列表，含 `chunk_id`、`content`、`score`、`metadata`、`source_file_name` 等；问答模式下直接返回自然语言答案 |
| **支持模型** | **不绑定特定大模型**；作为工具被任意 LLM（如 Qwen3、DeepSeek-R1）调用；SDK 封装与 `agentscope-runtime` 深度集成 | **强模型耦合**：预置支持 Qwen 全系列（QwQ/Long/Max/Plus/Turbo/VL-Max/OCR/Deep-Research）、Qwen3/Qwen2.5/Qwen2 及部分第三方模型（DeepSeek-V3.1/Llama3.1/Yi-Large）；需部署于华北2（北京）地域 |
| **API 端点** | RESTful 统一 Base URL：<br>`https://dashscope.aliyuncs.com/api/v2/apps/memory/`<br>接口：`POST /add`、`POST /memory_nodes/search`、`GET /memory_nodes`、`DELETE /memory_nodes/{id}`、`PATCH /memory_nodes/{id}` | 分服务形态：<br>- 知识检索：`POST /v2/knowledge_retrieval`<br>- 知识问答：`POST /v2/knowledge_qa`<br>- 管理 API：`POST /v2/knowledge_base/indexes` 等<br>需配置 `WORKSPACE_ID` 与子账号 AccessKey |
| **计费方式** | **按调用量计费（QPM + 调用次数）**：<br>- 免费额度：无明确公开免费额度<br>- 主要费用项：API 调用次数（`/add`、`/search` 等）<br>- 无存储容量费、无向量计算费 | **分层计费（规格 + 模型 + 调用）**：<br>- 规格费：标准版（0.03 元/小时）或旗舰版（0.2 元/RCU/小时）<br>- 模型费：独立收取（如 `qwen3.7-plus` 按 token 计费）<br>- 向量 & Rerank 费：按召回切片数 × [Token](../concepts/token.md) 数计费（`TopK` 是成本杠杆）<br>- 免费额度：720 小时/月（仅抵扣标准版规格费） |
| **典型场景** | - 多轮对话中持续记忆用户偏好（如“我喜欢素食”“上次订的是咖啡”）<br>- Agent 自主维护用户画像（生日、职业、历史决策）<br>- 对话状态机中的上下文锚点管理（如“正在处理退款申请”）<br>- 低延迟、高频率的会话片段增删查 | - 客服机器人基于产品手册/FAQ 回答问题<br>- 法律/医疗/金融领域专业问答（依赖结构化文档）<br>- 多源异构知识融合（合同+财报+会议纪要联合检索）<br>- 图片/音视频内容语义搜索（如“找出上周会议中提到‘预算’的幻灯片”） |
| **数据生命周期** | **无自动过期机制**；业务需主动调用 `DeleteMemory` 或通过 `user_id` + 时间戳逻辑清理；`UpdateMemory` 支持增量更新 `meta_data`，但 `content` 全量覆盖 | **静态为主，支持动态更新**：<br>- 文档类知识库支持新增/删除/重索引切片<br>- 音视频类知识库仅支持编辑/删除，不支持新增切片<br>- 元数据抽取配置在创建时锁定，不可后期修改 |
| **检索能力** | 单用户维度语义搜索（`user_id` 隔离）；支持多规则混合检索（`project_ids`）；可启用 `rerank`/`judge`/`rewrite`（需开通） | 多知识库联合检索；混合检索（向量+关键词）；Query 改写、Rerank 排序、标签/元数据过滤；支持路由与混排策略 |
| **开发侵入性** | **低侵入**：SDK 提供 `AddMemory`/`SearchMemory` 异步封装；`user_id` 作为唯一上下文标识，天然适配 Agent 架构 | **中等侵入**：需显式管理知识库 ID、`TopK`、相似度阈值；工作流中需手动连接节点并引用 `{result}`；API 集成需子账号权限与 Workspace 配置 |

## 各方案的适用场景建议

### ✅ 选择 **长期记忆（新）** 当：
- 你的应用是**以用户为中心的智能体（Agent）**，需跨会话记住个性化状态（如购物偏好、健康目标、任务进度）；
- 数据粒度细、更新频繁、生命周期短（如单次对话摘要、临时决策依据）；
- 要求低延迟、高并发的实时记忆操作（如每轮对话后立即存入、即时语义召回）；
- 不希望管理知识库的索引重建、文件版本、地域部署等运维复杂度；
- 已使用 `agentscope-runtime`，追求 SDK 开箱即用与 Agent 生命周期无缝对齐。

### ✅ 选择 **知识库** 当：
- 你的核心需求是**提升大模型在垂直领域的回答准确性与事实性**，依赖大量私有文档、报表、图像等静态知识；
- 数据来源多样（PDF/Excel/图片/音视频）、体量大（GB~TB 级）、更新周期长（周/月级）；
- 需要企业级能力：多知识库路由、敏感信息标签过滤、跨源混排、审计日志、权限隔离；
- 已有成熟文档管理体系（OSS 存储、CMS 系统），希望零代码接入或通过 API 批量同步；
- 愿意承担模型调用与向量计算的显式成本，并通过 `TopK`/阈值/关闭 Rerank 等手段精细化控本。

### ⚠️ 避免混淆的关键边界：
- **不要用知识库替代用户记忆**：知识库无法天然隔离 `user_id`，所有用户共享同一知识源，无法表达“张三喜欢咖啡，李四讨厌咖啡”这类个性化事实；
- **不要用长期记忆承载领域知识**：其 `content` ≤512 字符、`messages` ≤50 条，且无文档解析、[多模态](../concepts/multi-modal.md)支持、切片优化等 RAG 必备能力；
- **可协同使用**：典型架构为 —— Agent 用长期记忆维护用户状态，同时调用知识库检索领域知识，再将两者融合生成响应（例如：“根据您上次说的过敏史（长期记忆），结合《2024 过敏用药指南》（知识库），推荐……”）。

## 面向开发者的选型参考

1. **先问“数据属于谁？”**  
   → 属于**某个具体用户**？→ 选长期记忆（新）  
   → 属于**整个应用/团队/行业**？→ 选知识库  

2. **再问“数据如何产生？”**  
   → 由**对话过程自动生成**（如聊天记录提炼）？→ 长期记忆（新）更自然  
   → 由**人工上传/系统导出/批量采集**？→ 知识库提供完整 ingest pipeline  

3. **检查基础设施约束**：  
   - 若应用部署在**新加坡/法兰克福等国际地域** → 知识库不可用，长期记忆（新）不受地域限制；  
   - 若需**毫秒级记忆查询响应**（如实时推荐）→ 长期记忆（新）限流更宽松（`/search` 300 QPM），知识库检索链路更长；  
   - 若已有**大量非文本数据（扫描件/PPT/录音）** → 知识库原生支持，长期记忆（新）仅支持文本输入。

4. **成本敏感型项目注意**：  
   - 高频小数据写入（如每轮对话存 1 条）→ 长期记忆（新）调用费可控；  
   - 少量高质量知识但需高精度召回 → 知识库开启 Rerank 可能更优，但需权衡 [Token](../concepts/token.md) 成本；  
   - 预算有限且知识量小（<100MB 文档）→ 标准版知识库 + 免费额度可覆盖基础需求。

> **最后建议**：对于复杂 Agent 应用，推荐采用**分层记忆架构**——长期记忆（新）负责用户态（Who & What），知识库负责领域态（Where & How），二者通过统一提示词模板或工作流编排协同，兼顾个性化与专业性。
