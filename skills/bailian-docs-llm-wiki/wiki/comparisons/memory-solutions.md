# [长期记忆](../concepts/long-term-memory.md)与知识库方案对比

为帮助开发者在百炼平台中科学选型，本文系统对比「[长期记忆](../concepts/long-term-memory.md)（新）」与「知识库」两大核心能力方案。二者虽均支持语义检索与信息增强，但设计目标、技术路径、适用边界存在本质差异：**[长期记忆](../concepts/long-term-memory.md)聚焦于用户级、会话级的个性化状态沉淀与轻量召回；知识库则面向领域级、文档级的规模化知识注入与深度RAG生成**。本对比基于最新平台文档（2024年Q3），旨在为架构设计、成本控制与体验优化提供可落地的技术决策依据。

| 维度 | 长期记忆（新） | 知识库 |
|------|----------------|---------|
| **核心定位** | 用户个体记忆管理（事件+画像），支撑个性化、连贯性对话体验 | 领域知识注入与增强（文档/音视频/表格），支撑专业、准确、可溯源的问答生成 |
| **输入格式** | • `messages`：最多50条对话记录（role/content结构化数组）<br>• `custom_content`：纯文本（≤512字符），优先级高于messages<br>• 支持结构化画像字段（通过`profile_schema`关联Schema） | • 多格式文件：PDF/DOCX/TXT/CSV/JSON/MP4/MP3等（单文件≤150MB PDF/DOCX，≤512MB音视频）<br>• 支持元数据标注、标签分类、结构化字段映射<br>• 不支持直接传入对话消息或自然语言片段 |
| **输出格式** | • `SearchMemory` 返回结构化记忆片段列表（含`id`, `content`, `timestamp`, `score`, `meta_data`）<br>• `GetUserProfile` 返回JSON Schema定义的结构化画像对象<br>• 输出内容轻量、确定性强，无大模型生成环节 | • 检索接口：返回带`score`和`source`引用的文本切片（chunk）列表<br>• 问答接口：返回自然语言答案 + 引用溯源（`citations`数组含原文位置、来源文件等）<br>• 输出含模型生成成分，具备上下文整合与语言润色能力 |
| **支持模型** | • **不依赖大模型推理**：提取、检索、管理均由专用NLP服务完成<br>• 底层NLP模型未公开，不可替换或调优<br>• 仅需API Key认证，无模型选型环节 | • **强耦合多模型协同**：<br> - 向量化：`text-embedding-v4`、`qwen3-vl-embedding`等<br> - 排序（Rerank）：`qwen3-rerank`、`bge-reranker`等<br> - 生成：`qwen3.7-plus`、`qwen2.5-max`、`deepseek-r1`、`llama3.1`等数十种预置/自定义模型<br>• 模型可自由组合、按需切换 |
| **API端点** | 统一基地址：<br>`https://dashscope.aliyuncs.com/api/v2/apps/memory/`<br>• `/add` / `/search` / `/list` / `/delete` / `/update`（PATCH）<br>• 所有接口强制要求`user_id` | 分场景端点：<br>• 检索：`/v2/knowledge_retrieval`（文档类知识库）<br>• 问答：`/v2/knowledge_qa`（含多轮智能模式）<br>• 服务化Endpoint：独立发布，支持多库路由与混排<br>• **地域限制严格：仅华北2（北京）可用** |
| **计费方式** | • **按调用次数计费（QPM）**：<br> - 总体 ≤ 3000 QPM（账号级）<br> - `AddMemory` ≤ 120 QPM<br> - `SearchMemory` ≤ 300 QPM<br>• **无[Token](../concepts/token.md)消耗费用**，不产生向量/Rerank/生成类模型费用<br>• 无存储容量费用（默认长期保留） | • **多维度独立计费**：<br> - **规格费**：按RCU（检索计算单元）或QPS包年包月<br> - **模型费**：<br>  ✓ Query向量化（如`text-embedding-v4`）<br>  ✓ 切片Rerank（如`qwen3-rerank`）<br>  ✓ 问答生成（所选LLM，按input+output [Token](../concepts/token.md)计费）<br> - **存储费**：超出免费额度（标准版100GB）后按量计费<br>• 调试即计费，需谨慎使用控制台测试功能 |
| **典型场景** | • 用户偏好持续学习（“我喜欢咖啡，不要茶”）<br>• 跨会话任务提醒（“明天9点会议”自动触发）<br>• 个性化画像构建（年龄、职业、健康目标等结构化属性）<br>• Agent自动捕获/召回（OpenClaw插件无缝集成） | • 企业内部知识问答（产品手册、SOP文档）<br>• 客服知识库（FAQ、工单历史、合同条款）<br>• 研究辅助（论文PDF检索+摘要生成）<br>• 多模态知识应用（视频关键帧检索+语音转录分析） |
| **数据生命周期** | • 默认永不过期（但可通过`project_id`规则配置7/30/180天或永久）<br>• 需主动调用`DeleteMemory`清理<br>• 无自动过期策略（除非显式配置） | • 文件级生命周期由用户控制（上传/删除/更新）<br>• 切片无独立TTL，随源文件变更同步刷新<br>• 不支持单切片级时效设置 |
| **开发复杂度** | • 极低：统一REST API + Python SDK封装（`agentscope-runtime`）<br>• OpenClaw插件开箱即用，零代码接入自动捕获<br>• 无需[模型部署](../concepts/model-deployment.md)、向量配置、Rerank调优 | • 中高：需理解RAG全链路（分块→向量化→检索→Rerank→生成）<br>• 需权衡参数（TopK、相似度阈值、混合权重）<br>• 控制台调试+API集成双路径，调试成本高 |

## 适用场景建议

### ✅ 选择「长期记忆（新）」当：
- 你的应用核心是**用户个性化交互**（如智能助手、教育陪练、健康管理Bot），需记住用户习惯、承诺、偏好、待办事项等轻量但高频的状态信息；
- 你追求**低延迟、确定性、低成本**，不希望每次检索都触发大模型调用；
- 你需要快速集成到Agent框架（如OpenClaw），且不愿管理向量模型、分块策略等底层细节；
- 数据敏感度高，要求记忆完全隔离（`user_id`硬隔离），且不希望知识被其他用户或应用意外访问。

### ✅ 选择「知识库」当：
- 你的数据是**静态或半静态的领域知识资产**（如产品文档、法律条文、培训材料），需被多个用户、多个应用共享查询；
- 你要求回答具备**专业性、准确性、可溯源性**，并能处理长文档、表格、音视频等复杂格式；
- 你愿意投入资源进行**RAG效果调优**（如定制分块策略、微调Rerank模型、设计Prompt工程）；
- 你的业务部署在**华北2（北京）地域**，且能接受多模型协同带来的费用透明度与管控复杂度。

### ⚠️ 不建议混用或替代的情况：
- **勿用知识库替代用户记忆**：知识库无`user_id`隔离机制，无法安全存储用户隐私数据（如健康记录、消费偏好）；其检索结果面向全局，不具备个性化上下文感知。
- **勿用长期记忆替代知识库**：长期记忆不支持PDF解析、音视频处理、大规模文档切片、多库联合检索等RAG核心能力；单次输入长度受限（≤512字符直写），无法承载万字文档。
- **跨地域项目慎选知识库**：国际站（新加坡、法兰克福等）暂不支持知识库，若需全球化部署，长期记忆是唯一可行的语义记忆方案。

## 技术选型参考（面向开发者）

| 决策维度 | 关键检查项 | 推荐动作 |
|----------|------------|-----------|
| **数据性质** | □ 是用户专属、动态变化的对话状态？<br>□ 是组织共享、相对稳定的文档资产？ | 前者 → 长期记忆；后者 → 知识库 |
| **性能要求** | □ 端到端延迟需 < 300ms？<br>□ 可接受500ms+且需生成式回答？ | 前者 → 长期记忆；后者 → 知识库 |
| **成本模型** | □ 预算严格限定为固定QPM配额？<br>□ 可接受按[Token](../concepts/token.md)+RCU弹性付费？ | 前者 → 长期记忆；后者 → 知识库 |
| **部署环境** | □ 应用部署在华北2（北京）？<br>□ 部署在国际站或其他地域？ | 前者 → 两者均可；后者 → **仅长期记忆可用** |
| **集成深度** | □ 使用OpenClaw等Agent框架，需零代码接入？<br>□ 自研调度系统，需精细控制RAG各环节？ | 前者 → 长期记忆插件；后者 → 知识库API+SDK |
| **合规与安全** | □ 敏感用户数据必须物理隔离？<br>□ 知识需跨角色权限分级（如HR/IT文档隔离）？ | 前者 → 长期记忆（`user_id`隔离）；后者 → 知识库（通过多库+标签过滤实现逻辑隔离） |

> **最佳实践提示**：  
> - **组合使用更强大**：在智能体中，可同时启用长期记忆（记住“用户张三上周说过敏史”）与知识库（检索“青霉素过敏处置指南”），前者注入Prompt作为上下文，后者提供权威依据供LLM引用。  
> - **监控先行**：长期记忆关注QPM配额水位；知识库务必开启SLS日志，分析`rerank_input_tokens`与`qa_output_tokens`分布，避免Rerank过度召回导致费用激增。  
> - **版本演进注意**：长期记忆（新）已取代旧版，知识库持续迭代Rerank与Embedding模型（如`qwen3-vl-embedding`），建议定期查阅[模型支持列表](https://help.aliyun.com/zh/model-studio/model-list)更新选型。
