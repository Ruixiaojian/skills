# 模型微调、模型训练与模型部署对比

## 概述

在百炼平台上，**模型微调**（Fine-tuning）、**模型训练**（Model Training API）和**模型部署**（Model Deployment）是构建定制化 AI 应用的三个核心环节。模型微调侧重于方法论与最佳实践，模型训练提供 API 层面的技术实现，模型部署则将训练产出或预置模型转化为可调用的推理服务。

本文旨在帮助开发者厘清三者的定位差异、功能边界和协作关系，为技术选型和工作流设计提供参考。

## 核心维度对比

| 维度 | 模型微调（Fine-tuning） | 模型训练（Training API） | 模型部署（Deployment） |
|------|------------------------|------------------------|----------------------|
| **核心定位** | 方法论与端到端指南，涵盖数据准备到评测的完整流程 | API 层面的技术实现，提供标准化接口完成训练任务 | 将模型转化为可调用的在线推理服务 |
| **主要输入** | 训练数据（ChatML 格式 JSON、音频 ZIP 等） | 文件 ID（`file_id`）、模型 ID、超参数配置 | 模型名称/ID、计费方式、容量配置 |
| **主要输出** | 调优后的模型（需部署后使用） | 任务状态、调优后模型 ID（`fine_tuned_model`） | 部署后的模型 Code（`deployed_model`），可直接调用 |
| **API 端点** | 通过控制台或 API 操作 | `POST /api/v1/fine-tunes`（创建）<br>`GET /api/v1/fine-tunes/{job_id}`（查询） | `POST /api/v1/deployments`（创建）<br>`GET /api/v1/deployments/{deployed_model}`（查询）<br>`DELETE /api/v1/deployments/{deployed_model}`（删除） |
| **支持模型类型** | 文本生成（Qwen 系列）、视觉理解（Qwen-VL）、视频生成（Wan 系列）、语音合成（CosyVoice） | 文本生成、视觉理解、语音合成、视频生成、语音识别（热词） | 预置模型（Qwen、DeepSeek、GLM、MiniMax 等）、调优后模型、OSS 导入 LoRA 模型 |
| **训练/调优方式** | SFT、CPT、DPO；全参训练与 LoRA 高效训练 | `sft`、`efficient_sft`、`cpt`、`dpo_full`、`dpo_lora`、`compile_asr_phrase` | 不涉及训练，仅负责推理服务化 |
| **计费方式** | 按 [Token](../concepts/token.md) 数 × 循环次数 × 训练单价（各模型单价不同） | 同模型微调（API 创建的任务仅支持按 [Token](../concepts/token.md) 计费） | 预置吞吐（PTU）、模型单元（MU）、[Token](../concepts/token.md) 用量、实例时长（图片/视频生成） |
| **使用方式** | 控制台（可视化）+ API/CLI | 纯 API/CLI 操作 | 控制台 + API/CLI |
| **地域限制** | 仅中国大陆版（北京地域） | 仅中国大陆版（北京地域） | 仅中国内地（北京）地域 |
| **并发限制** | 同一时间仅一个训练任务可执行 | 同一时间仅一个训练任务可执行 | 可同时部署多个服务 |

## 数据格式对比

| 维度 | 模型微调 / 模型训练 | 模型部署 |
|------|-------------------|---------|
| **文本生成 SFT** | ChatML 格式 JSONL（`messages` 数组含 system/user/assistant） | 不涉及训练数据 |
| **DPO** | 在 messages 基础上增加 `chosen` 和 `rejected` 字段 | — |
| **CPT** | 纯文本格式 `{"text": "..."}` | — |
| **视觉理解** | `content` 使用数组格式传入文本和图像/视频，压缩为 ZIP | — |
| **语音合成** | `.wav` 音频 + `data.jsonl` 打包 ZIP | — |
| **推理调用** | — | [OpenAI 兼容接口](../concepts/openai-compatible-api.md) / DashScope 接口，`model` 使用部署后 Code |

## 完整工作流关系

```
数据准备 → 模型微调/训练 → 模型部署 → 推理调用
         (Fine-tuning)   (Training API)   (Deployment)    (Inference)
              ↓                ↓                ↓               ↓
         方法选择          API 创建任务      上线推理服务     业务集成
         数据格式化        超参数配置        计费方式选择     API 调用
         最佳实践          状态监控          扩缩容管理       效果评测
```

## 适用场景建议

### 模型微调（Fine-tuning 指南）

适合以下场景的开发者参考：

- **初次接触模型定制**：需要了解 CPT/SFT/DPO 的选择策略和推荐流程
- **数据准备阶段**：需要明确数据格式要求、数据量建议和超参数推荐值
- **方案评估阶段**：在 Prompt 工程效果不佳后，评估是否需要进行模型调优
- **控制台操作**：偏好可视化界面完成训练全流程

### 模型训练（Training API）

适合以下场景的开发者使用：

- **自动化流水线**：需要将训练流程集成到 CI/CD 或自动化工作流中
- **批量任务管理**：通过 API 批量创建、查询和管理训练任务
- **精细参数控制**：需要精确设置每个超参数（如 LoRA rank、学习率调度策略等）
- **多模型训练**：需要对文本、视觉、语音、视频等多种模型类型进行统一管理
- **语音识别热词**：Paraformer 模型的热词管理仅通过 API 支持

### 模型部署（Deployment）

适合以下场景的开发者使用：

- **生产上线**：将调优后模型部署为独立推理服务，保障 SLA
- **资源隔离**：需要专享计算资源，避免共享池的排队和波动
- **预置模型定制**：部署平台提供的预置模型（如 DeepSeek、GLM 等）获得专属服务
- **外部模型导入**：将本地训练的 LoRA 模型通过 OSS 导入并部署
- **灵活计费**：根据业务特点选择 PTU（吞吐保障）、MU（按时长）或 Token 用量计费

## 技术选型决策参考

### 问题 1：我应该先微调还是直接部署？

- 如果现有预置模型通过 Prompt 工程即可满足需求 → **直接部署预置模型**
- 如果模型在特定领域/任务上表现不佳且 Prompt 无法改善 → **先微调再部署**
- 微调是改进模型表现的"最后手段"，建议优先尝试 Prompt 优化和插件调用

### 问题 2：使用控制台还是 API？

| 需求 | 推荐方式 |
|------|---------|
| 快速验证、小规模实验 | 控制台（可视化操作） |
| 生产级自动化流水线 | API/CLI |
| 使用模型训练单元（预付费） | 控制台（API 仅支持按 Token 计费） |
| CosyVoice 语音合成调优 | 仅 API 支持 |

### 问题 3：如何选择计费方式？

| 业务特点 | 推荐计费方式 |
|---------|------------|
| 高并发、稳定流量、需要吞吐保障 | 预置吞吐（PTU） |
| 长期运行、算力需求可预估 | 模型单元（MU），包月更经济 |
| 流量波动大、按需使用 | Token 用量（仅部分 LoRA 模型支持） |
