# 模型微调、模型训练与模型部署对比

## 概述

在百炼平台上，**模型微调**、**模型训练**和**模型部署**是构建定制化 AI 应用的三个核心环节。模型微调侧重于调优策略的选择与数据准备（用户指南视角），模型训练侧重于通过 API 执行训练任务的技术实现（API 视角），模型部署则负责将模型转化为可调用的推理服务。

本文旨在帮助开发者厘清三者的定位、能力边界和协作关系，以便在实际项目中做出合理的技术选型。

## 关键维度对比

| 维度 | 模型微调（Fine-tuning 指南） | 模型训练（Training API） | 模型部署（Deployment） |
|------|---------------------------|------------------------|---------------------|
| **核心定位** | 调优策略选择与数据工程 | 训练任务的编程接口与流程管控 | 将模型转化为可用的推理服务 |
| **解决的问题** | 如何提升模型在特定场景下的表现 | 如何通过 API 创建和管理训练任务 | 如何让训练好的模型对外提供服务 |
| **输入格式** | ChatML JSON（SFT）、纯文本（CPT）、正负样本对（DPO）、ZIP 包（VL/视频/语音） | 文件 ID（`file_id`）+ 模型 ID + 超参数配置 | 模型名称/ID + 计费方式 + 容量配置 |
| **输出** | 调优后的模型 ID（`fine_tuned_model`） | 训练任务 ID（`job_id`）及最终的模型 ID | 部署服务名称（`deployed_model` code），可用于推理调用 |
| **支持的模型** | Qwen 系列（文本/VL）、CosyVoice、Wan 视频生成 | 文本生成、视觉理解、语音合成、视频生成、语音识别（热词） | 预置模型（Qwen、DeepSeek、GLM 等）+ 所有调优后模型 + OSS 导入 LoRA 模型 |
| **主要 API 端点** | 无独立端点（策略与数据层面的指导） | `POST /api/v1/files`（上传）<br>`POST /api/v1/fine-tunes`（创建）<br>`GET /api/v1/fine-tunes/{job_id}`（查询） | `POST /api/v1/deployments`（创建）<br>`GET /api/v1/deployments/{deployed_model}`（查询）<br>`DELETE /api/v1/deployments/{deployed_model}`（删除） |
| **计费方式** | 按 Token 计费（训练 Token × 循环次数 × 单价）；CosyVoice 按 Token + 部署时长 | 同左（API 方式仅支持按 Token 计费，不支持训练单元） | 预置吞吐（PTU）/ 模型单元（MU）/ Token 用量（LoRA）/ 按实例时长（图视频） |
| **使用方式** | 控制台（可视化）+ API/CLI | 纯 API/CLI | 控制台 + API/CLI |
| **地域限制** | 中国大陆版（北京地域） | 中国大陆版（北京地域） | 中国内地（北京）地域 |
| **并发限制** | 同一时间仅允许 1 个训练任务运行 | 同一时间仅允许 1 个训练任务运行 | 无明确并发限制，可通过 RPM/TPM 限流 |
| **典型耗时** | 数小时到数天（取决于数据量和模型规模） | 同左 | 部署启动通常数分钟 |

## 调优方式详细对比

| 调优方式 | 核心目标 | 最低数据要求 | 训练模式 | 适用阶段 |
|---------|---------|------------|---------|---------|
| CPT（继续预训练） | 注入领域知识 | 1000 万+ Token 无标签文本 | 全参/LoRA | 前期知识注入 |
| SFT（监督微调） | 学会遵循指令 | 1000+ 条高质量问答对 | 全参/LoRA | 核心调优环节 |
| DPO（直接偏好优化） | 对齐人类偏好 | 100+ 组正负样本对 | 全参/LoRA | 效果精修 |

## 部署计费方式对比

| 计费方式 | 付费模式 | 适用模型 | 扩缩容方式 | 典型场景 |
|---------|---------|---------|-----------|---------|
| 预置吞吐（PTU） | 随用随付/包天 | 部分预置模型 | 自助增减 TPM | 稳定吞吐量需求，需要性能保障 |
| 模型单元（MU） | 随用随付/包月 | 预置模型 + 调优后模型 | 自助增减单元数 | 长时间运行的生产环境 |
| Token 用量（LoRA） | 随用随付 | 部分 LoRA 调优后模型 | 控制台申请，人工审核 | 低频调用、成本敏感场景 |
| 按实例时长 | 后付费/包月 | 图片/视频生成模型 | — | 多媒体生成任务 |

## 适用场景建议

### 场景一：快速验证业务可行性

**推荐路径**：直接使用预置模型部署 → Prompt 工程调优

如果现有模型通过 Prompt 工程即可满足需求，无需进行微调。模型部署支持多种预置模型（Qwen、DeepSeek、GLM 等），开发者可快速部署并测试效果。

### 场景二：模型在特定领域表现不佳

**推荐路径**：数据准备（模型微调指南）→ API 创建训练任务（模型训练）→ 部署调优后模型（模型部署）

- 当 Prompt 工程无法满足需求时，参考模型微调指南选择合适的调优策略（SFT/CPT/DPO）
- 通过模型训练 API 执行调优任务
- 训练完成后通过模型部署上线服务

### 场景三：需要定制化语音/视频能力

**推荐路径**：准备音频/视频数据 → SFT-LoRA 高效微调 → 模型单元部署

- CosyVoice 语音合成：仅支持 API 方式发起训练，需部署后使用
- Wan 视频生成：支持 SFT-LoRA 高效微调，适合定制动作/特效/风格

### 场景四：已有本地训练的 LoRA 模型

**推荐路径**：OSS 上传模型文件 → 模型导入 → 模型部署

支持从 OSS 导入本地训练的 LoRA 模型（需符合 rank 8/16/32/64 限制），无需在百炼平台重新训练。

## 技术选型参考

### 决策流程

```
是否需要定制模型能力？
├─ 否 → 直接部署预置模型
└─ 是 → 已有训练好的 LoRA 模型？
         ├─ 是 → OSS 导入 → 模型部署
         └─ 否 → 选择调优策略
                  ├─ 需注入领域知识 → CPT + SFT
                  ├─ 需遵循特定指令格式 → SFT
                  └─ 需优化输出质量偏好 → SFT + DPO
```

### 关键建议

1. **先尝试 Prompt 工程**：模型调优是"最后手段"，建议先充分利用 Prompt 和插件能力。

2. **训练模式选择**：全参训练和 LoRA 高效训练费用相同，若模型支持全参训练则优先选择全参，性价比更高。

3. **API vs 控制台**：
   - 控制台
