# [长期记忆](../concepts/long-term-memory.md)与知识库方案对比

为帮助开发者在百炼平台中科学选型，本文对**[长期记忆](../concepts/long-term-memory.md)（Long-Term Memory, 新版）**与**知识库（Knowledge Base, RAG 方案）**两大核心数据增强能力进行系统性对比。二者虽均支持语义检索与上下文增强，但设计目标、数据来源、管理粒度及适用范式存在本质差异：  
- **[长期记忆](../concepts/long-term-memory.md)**聚焦于**用户个体维度的动态、轻量、会话级记忆沉淀**，强调自动提取、身份隔离与画像构建，服务于智能体的“人格化”与连续交互体验；  
- **知识库**面向**组织/业务维度的静态或半静态领域知识注入**，强调多源异构数据接入、规模化索引与端到端问答生成，服务于专业场景下的准确、可溯源回答。

以下从关键技术维度展开对比，并提供明确的选型建议。

## 关键维度对比

| 维度 | 长期记忆（新） | 知识库（RAG） |
|------|----------------|----------------|
| **核心定位** | 用户级、会话衍生的记忆片段与结构化画像管理 | 业务级、预置文档/数据驱动的领域知识增强 |
| **输入格式** | • `messages`：最多 50 条对话消息（role/content 格式）<br>• `custom_content`：≤512 字符纯文本（绕过提取）<br>• 支持 `meta_data` 键值对分类 | • 多模态文件：PDF/Word/Excel/PPT/图片/音视频/Markdown/纯文本等<br>• 支持 OSS/飞书/钉钉/语雀/SharePoint 等外部源定时同步<br>• 文本切片自动处理（≤6000 字符/片） |
| **输出格式** | • `SearchMemory` 返回结构化 `memory_nodes[]`（含 `content`, `score`, `meta_data`, `created_at`）<br>• `GetUserProfile` 返回 JSON Schema 化画像对象<br>• 无原生生成能力，需开发者自行拼接 Prompt | • 检索接口：返回带 `score` 和 `source` 的文本切片列表（含引用位置）<br>• 问答接口：返回自然语言答案 + 可溯源引用（`citations` 字段）<br>• 支持直接输出 Markdown/HTML 格式答案 |
| **支持模型** | • **不绑定具体大模型**：所有 API 为独立服务，输出供任意模型消费<br>• 与 Qwen 系列、DeepSeek、Llama3 等无耦合 | • **深度集成模型生态**：<br>  – 预置：Qwen3/Qwen2.5/Qwen2/Long/Max/Plus/Turbo/VL-Max/OCR 等全系<br>  – 第三方：DeepSeek-R1/V3.1、abab6.5s、Yi-Large、Llama3.1 等<br>  – 自定义微调模型（基于上述基座）<br>• 问答服务强制绑定模型，检索服务可解耦 |
| **API 端点** | 统一 Base URL：<br>`https://dashscope.aliyuncs.com/api/v2/apps/memory/`<br>• `/add` / `/search` / `/list` / `/delete` / `/update` / `/profile/schema` 等 | 分离式架构：<br>• **索引管理**：`/v2/knowledge_bases/{kb_id}/files` 等（需租约上传）<br>• **检索服务**：`/v2/pipelines/{pipeline_id}/retrieve`<br>• **问答服务**：`/v2/pipelines/{pipeline_id}/chat`<br>• 全部需 `pipeline_id`（即知识库 ID） |
| **计费方式** | • **按调用次数计费**（2026年8月20日起）：<br>  – `AddMemory`：Lite ¥0.018/次，Pro ¥0.03/次<br>  – `SearchMemory`：Lite ¥0.00002/次，Pro ¥0.001/次<br>• 无规格费、无存储费、无模型调用费（仅记忆 API 费） | • **分层计费**：<br>  – **规格费**：标准版 ¥0.03/小时，旗舰版 ¥0.2/RCU/小时（720 小时免费额度仅抵扣此项）<br>  – **模型调用费**：独立计费 — 向量化、Rerank、路由、生成均按 Token 计费<br>  – **存储费**：OSS 存储费用另计（知识库本身不收存储费）<br>• 多知识库场景费用线性叠加 |
| **典型场景** | • 智能客服记住用户历史投诉与偏好（如“上次说空调不制冷”）<br>• 个人助理持续学习用户日程习惯（“每天9点吃药”“每周三健身”）<br>• 教育应用构建学生画像（年级、薄弱知识点、错题倾向）<br>• 游戏 NPC 记住玩家关键选择与关系状态 | • 企业内部知识问答（制度/流程/产品文档）<br>• 客服坐席辅助（FAQ+工单+合同条款联合检索）<br>• 法律/医疗垂直领域专业问答（论文/指南/判例）<br>• 多模态内容理解（财报PDF解析+图表问答+会议录音摘要） |
| **数据生命周期** | • **无默认过期**：由 `CreateMemoryProject` 中 `expired_in_days` 显式配置，未设则永不过期<br>• 无自动清理机制，需业务侧主动 `DeleteMemory` 或更新 `expired_in_days` | • 文件上传后**永久保留**（除非手动删除）<br>• 同步规则导入的文件为**独立副本**，源端删除不影响百炼内数据<br>• 支持手动触发重新索引以更新内容 |
| **地域与权限** | • 全地域可用（中国站/国际站均支持）<br>• 仅需 `DASHSCOPE_API_KEY` 认证，无子账号权限要求 | • **地域强约束**：<br>  – 中国站：仅华北2（北京）<br>  – 国际站：仅新加坡<br>• API 调用需子账号具备 `AliyunBailianDataFullAccess` 权限并加入业务空间 |
| **开发者集成复杂度** | • **低**：SDK 封装完善（`agentscope-runtime>=1.1.5`），5 行代码完成写入/检索<br>• 无需管理索引、切片、向量模型等底层概念 | • **中高**：需理解上传→索引→检索/问答三阶段流程<br>• 控制台配置项多（Meta 抽取、标签、改写开关等），且**创建后不可修改**，试错成本高<br>• 多模态处理需额外适配（如 OCR、ASR） |

## 适用场景建议

### ✅ 优先选用「长期记忆」当：
- 你的应用核心是**与特定用户建立长期、个性化交互关系**（如 C 端助手、教育陪练、游戏 NPC）；
- 数据来源于**实时对话流**，需自动提炼事件、意图、承诺等轻量信息；
- 要求严格**用户数据隔离**（`user_id` 隔离），且不同用户记忆互不可见；
- 需要**结构化用户画像**（年龄、职业、偏好等）并支持增量更新；
- 希望最小化集成成本，快速上线记忆能力（SDK 一行调用即可）；
- 对延迟敏感（`SearchMemory` 端到端 200–500ms），且无需原生生成答案。

### ✅ 优先选用「知识库」当：
- 你的目标是**提升大模型在专业领域的回答准确性与可信度**（如法律咨询、IT 运维、金融投顾）；
- 知识源为**已有的、结构化/半结构化文档资产**（PDF 手册、数据库表、网页、音视频）；
- 需要**跨多个知识源联合检索**（如同时查合同+法条+历史判例），并支持标签/元数据过滤；
- 要求**答案可溯源、可审计**（问答接口返回 `citations`，支持点击跳转原文）；
- 接受一定集成复杂度，愿意投入资源做知识清洗、切片策略调优与 Rerank 模型选型；
- 场景符合地域限制（北京或新加坡），且有稳定业务空间与权限管理体系。

### ⚠️ 不建议混用或强行替代的情况：
- ❌ 用知识库存储用户聊天记录 → 成本高、隔离弱、无法自动提取事件、无 `user_id` 语义；
- ❌ 用长期记忆托管企业产品手册 → 单条内容超 512 字符限制，无多模态支持，无法做表格/图片理解；
- ❌ 在同一应用中对同一类数据（如用户订单）既写入记忆又导入知识库 → 架构冗余，维护困难；
- ✅ **推荐协同模式**：  
  **长期记忆**管理 *用户个性化状态*（“张三讨厌弹窗广告”），  
  **知识库**承载 *通用业务规则*（“百炼平台隐私政策第3.2条”），  
  二者检索结果共同注入 Prompt，实现“个性+专业”的混合增强。

## 技术选型参考（面向开发者）

| 选型决策点 | 长期记忆 | 知识库 | 建议动作 |
|------------|----------|--------|----------|
| **是否需要 `user_id` 级别数据隔离？** | ✅ 原生强支持 | ❌ 无内置用户维度，需业务层加前缀模拟 | 若必须隔离，选长期记忆 |
| **主要数据来源是对话消息还是文档文件？** | ✅ 对话消息（`messages`） | ✅ 文档/音视频/数据库 | 按源头匹配方案 |
| **是否需结构化用户画像（Schema 化字段）？** | ✅ 原生支持 `ProfileSchema` | ❌ 仅支持非结构化 `meta_data` 键值对 | 需画像必选长期记忆 |
| **是否要求答案自带引用溯源（citations）？** | ❌ 仅返回记忆内容，无原文定位 | ✅ 问答接口原生返回 `citations` | 需合规/审计场景必选知识库 |
| **是否接受地域限制（仅北京/新加坡）？** | ❌ 无限制 | ✅ 强制限制 | 国际多地域部署选长期记忆 |
| **团队是否有 RAG 调优经验？** | ❌ 无需调优（自动提取+默认 Rerank） | ✅ 需调相似度阈值、TopK、Rerank 模型 | 新团队建议从长期记忆起步 |
| **预算敏感度：更关注调用频次成本 or 规格+Token 综合成本？** | ✅ Lite 版 `SearchMemory` 仅 ¥0.00002/次 | ❌ 规格费+向量化+Rerank+生成 Token 全链路计费 | 高频轻量查询选长期记忆 |

> **最后建议**：  
> - **MVP 快速验证**：从长期记忆切入，用 `AddMemory` + `SearchMemory` 30 分钟搭建用户记忆闭环；  
> - **专业场景深化**：当业务知识沉淀达 100+ 文档、需多源融合与强溯源时，平滑迁移至知识库；  
> - **混合架构落地**：在智能体应用中，将 `SearchMemory` 结果作为 `system prompt` 注入，再调用绑定知识库的问答服务，实现双引擎协同。
