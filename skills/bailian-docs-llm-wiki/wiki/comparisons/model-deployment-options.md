# 模型部署方式对比：模型生产、模型压缩与模型监控

## 对比目的与背景

在百炼平台构建端到端大模型应用的过程中，**模型生产（Model Production）**、**模型压缩（Model Compression）** 和 **模型监控（Model Monitoring）** 是支撑模型从训练走向稳定落地的三大关键能力模块。它们分别聚焦于 *“如何把模型变成可用服务”*、*“如何让服务更轻量更经济”* 与 *“如何保障服务长期可靠运行”* —— 三者并非替代关系，而是按序协同、逐层增强的生产闭环环节。

本对比旨在帮助开发者清晰理解三者的定位差异、技术边界与集成路径，避免常见误用（如试图对未微调的基础模型直接压缩、或在无部署服务的前提下启用高级推理日志），从而在架构设计初期即做出合理的技术选型与资源规划。

## 关键维度对比表

| 维度 | 模型生产（Model Production） | 模型压缩（Model Compression） | 模型监控（Model Monitoring） |
|------|------------------------------|-------------------------------|------------------------------|
| **核心目标** | 实现模型定制化训练与在线服务发布 | 降低已训练模型的推理资源消耗与成本 | 提供全链路可观测性与稳定性保障 |
| **输入格式** | JSONL 训练数据（含 `messages` 字段）；模型版本 ID 或 Hugging Face 格式模型包 | 百炼微调产出的全精度自定义模型（如 `qwen3.5-flash-2026-02-23`） | 任意已部署模型的实时/历史调用流量（自动采集，无需主动上报） |
| **输出格式** | 微调任务产出 `model_version_id`；部署后生成 `endpoint_url`（HTTP/SSE 接口） | 新模型 ID（源模型名 + 后缀，如 `my-model-quant8`），可直接用于部署 | 多维指标（RPM/TPM/首[Token](../concepts/token.md)延时等）、调用日志（含请求/响应原文）、告警事件、Prometheus 时间序列数据 |
| **支持模型** | ✅ Qwen 系列（`qwen2-7b`, `qwen2-57b`）、Llama3（`llama3-8b`）等平台预置基座模型<br>❌ 不支持自定义基座模型部署 | ✅ 仅限百炼平台内微调成功的自定义模型<br>❌ 不支持基础模型、第三方导入模型、OSS 直接加载模型 | ✅ 所有已在模型列表中可见的模型（含基础模型、微调模型、压缩模型）<br>⚠️ 高级能力（推理日志、分钟级指标）仅限特定地域+指定快照版本（如 `qwen3.7-plus-2026-05-26`） |
| **API / 控制台入口** | REST API：<br>`POST /fine_tuning/jobs`<br>`POST /deployments`<br>控制台路径：**模型 > 模型训练 > 微调任务 / 部署服务** | 控制台专属功能：<br>**模型 > 模型训练 > 模型压缩 > 创建压缩任务**<br>❌ 无公开 REST API（当前仅控制台操作） | REST API（Prometheus HTTP API） + 控制台：<br>监控页：`/model-telemetry`<br>告警页：`/model-alert`<br>API 地址需在控制台获取 |
| **计费方式** | • 微调任务：按 GPU 小时计费（实例规格 × 运行时长）<br>• 部署服务：按所选 `instance_type`（如 `gpu.2xlarge`）的 MU 规格小时计费 | • 压缩任务本身：限时免费（以控制台公告为准）<br>• 压缩后模型部署：仍按 MU 规格计费（但同等性能下 MU 成本显著降低） | • 普通监控（用量统计、失败率等）：免费<br>• 高级监控（推理日志、TPS、分钟级延迟、Prometheus 接入）：按日志条数/指标查询量/存储时长收费<br>• 免费额度耗尽后返回 `403 AllocationQuota.FreeTierOnly` |
| **典型场景** | • 客服对话机器人定制<br>• 金融文档问答微调<br>• 快速验证新 [prompt](../guides/prompt.md) 工程效果并灰度上线 | • 高并发低延迟场景下的成本优化（如 APP 内嵌 AI 助手）<br>• 边缘设备或轻量云实例部署<br>• A/B 测试多量化版本效果 | • 生产环境 SLA 异常快速定位（如首[Token](../concepts/token.md)延时突增）<br>• 内容安全违规审计<br>• 成本归因分析（按 API Key / 模型 / 业务线）<br>• 自建运维平台对接（Grafana / ELK） |
| **地域限制** | 全地域支持（以控制台可用区为准） | 仅华北2（北京）地域可用 | • 普通监控：全地域<br>• 高级监控（含推理日志）：仅北京、新加坡、弗吉尼亚<br>• 上海支持高级监控但不支持推理日志 |

## 各方案适用场景建议

### ✅ 推荐使用「模型生产」当：
- 需要基于业务数据定制模型行为（如适配行业术语、话术风格）；
- 要求快速迭代与灰度发布能力（通过 `deployment_name` 切换流量）；
- 部署目标为标准云 GPU 实例，对单次推理延迟敏感度中等（< 2s）；
- **注意**：若计划后续压缩，请确保微调阶段选用平台明确支持的基座模型（如 `qwen2-7b`），否则无法进入压缩流程。

### ✅ 推荐使用「模型压缩」当：
- 已完成微调且验证效果达标，进入规模化部署阶段；
- 当前部署成本过高（如 `gpu.2xlarge` → `mu8.1xlarge` 可降本约 56%）；
- 应用场景对精度容忍度较高（如摘要生成、简单分类），且已通过业务测试集验证量化损失可控；
- **关键前提**：必须在华北2（北京）地域操作，且源模型状态为 `succeeded`。

### ✅ 推荐使用「模型监控」当：
- 模型已上线生产环境，需建立 SLO（如“99% 请求首[Token](../concepts/token.md)延时 < 800ms”）；
- 出现偶发失败或性能抖动，需下钻至单次请求分析根因；
- 需向财务或合规部门提供按模型/密钥/业务线粒度的成本报告；
- **进阶建议**：开通高级监控前，务必确认目标模型版本在[官方支持列表](../../raw/model-user-guide/model-monitoring/model-telemetry.md)中，并优先在北京/新加坡/弗吉尼亚地域部署。

## 技术选型参考（面向开发者）

| 决策问题 | 推荐动作 | 注意事项 |
|----------|-----------|-----------|
| **“我的开源模型能否直接部署？”** | ❌ 不支持。必须基于百炼预置基座模型（如 `qwen2-7b`）微调后部署；Hugging Face 模型仅支持通过 `import_model` 导入，且须满足平台兼容性要求。 | 查阅 [模型部署 API 文档](../../raw/model-api-reference/model-production/deployments-api.md) 获取最新支持型号清单。 |
| **“能否先压缩再微调？”** | ❌ 不允许。压缩是微调后的**单向后处理步骤**，压缩后模型不可继续训练。 | 若需调整，必须回到原始微调任务重新训练，再发起新压缩任务。 |
| **“如何低成本验证压缩效果？”** | ✅ 利用免费期：对同一源模型尝试多个量化模板（如 `quant4`/`quant8`），分别部署并用相同测试集压测对比精度与延迟。 | 压缩任务免费，但部署费用实时产生——建议测试完成后及时停用非主力压缩模型。 |
| **“为什么看不到请求内容日志？”** | 🔍 检查三项：<br>1. 是否已开通「推理日志」（控制台 > 模型监控 > 配置）；<br>2. 模型是否位于北京/新加坡/弗吉尼亚；<br>3. 模型版本是否在[支持快照列表](../../raw/model-user-guide/model-monitoring/model-telemetry.md)中。 | 上海地域不支持推理日志，即使开通也无法记录内容。 |
| **“如何自动化告警？”** | ✅ 使用 Prometheus API + 自建 Alertmanager，或配置控制台 Webhook 告警（推荐钉钉/企业微信机器人）。 | 告警规则需在**目标业务空间内单独创建**，子账号无法跨空间设置。 |
| **“能否监控未部署的模型？”** | ❌ 不能。监控对象必须是已成功部署（`status: "ready"`）或已调用过的模型。基础模型若从未被调用，不会出现在监控列表中。 | 模型用量页面仅展示有实际调用记录的模型。 |

> 💡 **最佳实践组合路径**：  
> `微调训练（Model Production）`  
> → `效果验证 & 业务测试`  
> → `模型压缩（Model Compression）`（如需降本）  
> → `部署压缩模型（Model Production）`  
> → `开通高级监控（Model Monitoring）`（生产环境必备）  
> → `配置 SLO 告警 + 定期审计日志`
