# 知识库与[长期记忆](../concepts/long-term-memory.md)对比

本页旨在帮助开发者清晰区分百炼平台中两大核心上下文管理能力：**知识库（Knowledge Base）** 与**[长期记忆](../concepts/long-term-memory.md)（新）（Long Term Memory New）**。二者虽均支持“检索+语义理解”，但设计目标、技术定位与适用边界存在本质差异。知识库面向**静态、共享、领域化的外部知识注入**，是 RAG 架构的基础设施；而[长期记忆](../concepts/long-term-memory.md)面向**动态、私有、用户粒度的对话状态沉淀**，是智能体个性化与连续性的关键支撑。正确选型可显著降低开发复杂度、避免功能错配，并优化成本与效果。

---

## 关键维度对比

| 维度 | 知识库（Knowledge Base） | 长期记忆（新）（Long Term Memory New） |
|------|--------------------------|----------------------------------------|
| **核心定位** | 静态领域知识的结构化索引与检索增强（RAG 场景） | 动态用户对话状态的自动提取、存储与复用（Agent 连续性场景） |
| **输入格式** | 多模态文件（PDF/DOCX/Excel/图片/音视频等），支持批量上传与 OSS 导入；内容经切片、向量化后构建索引 | 结构化 API 输入：<br>• `messages`：最多 50 条对话消息（JSON 数组）<br>• `custom_content`：≤512 字符纯文本；二者互斥必填 |
| **输出格式** | 检索结果为带元数据（source、page、chunk_id 等）的文本切片列表（`nodes[]`），供 LLM 作为上下文生成答案；支持返回原始文件链接、高亮片段等 |
| **支持模型** | 仅限百炼平台托管的生成模型（如 `qwen-plus`, `qwen-max`, `deepseek-r1`, `llama3.1` 等），且需显式绑定至知识库调用链路 | **模型无关**：所有语义提取、向量化、检索均由平台专用服务完成，**不依赖也不暴露任何大模型调用接口** |
| **API 端点** | - 控制台：`https://bailian.console.aliyun.com/?tab=app#/knowledge-base`<br>- SDK/API：`CreateIndex`, `SubmitIndexJob`, `Retrieve`, `QueryKnowledgeBase` 等（需 Bailian SDK + `AliyunBailianDataFullAccess` 权限） | - HTTP Base URL：`https://dashscope.aliyuncs.com/api/v2/apps/memory/`<br>- 接口路径：`/add`, `/memory_nodes/search`, `/memory_nodes`, `/memory_nodes/{id}` 等<br>- 推荐使用 `agentscope-runtime>=1.1.5` SDK 封装 |
| **计费方式** | **双轨计费**：<br>• 规格费：按小时计费（标准版/旗舰版）<br>• 模型调用费：[向量嵌入](../concepts/vector-embedding.md)、Rerank、路由模型、问答模型均按 [Token](../concepts/token.md) 单独计费（如 `qwen-plus` 调用费用独立于知识库规格） | **单一定价**：<br>• 按调用次数计费（QPM 限流内）<br>• 无模型 [Token](../concepts/token.md) 费用，无存储容量费<br>• 当前免费公测中（以控制台最新计费说明为准） |
| **地域限制** | 仅支持 **华北2（北京）** 地域 | 全地域可用（与 DashScope API 一致） |
| **数据所有权与隔离** | 知识库存储于业务空间内，支持多知识库绑定与权重路由；数据逻辑隔离，但**不天然绑定用户 ID** | 强用户粒度隔离：所有操作必须传入 `user_id`（≤64 字符），不同 `user_id` 数据物理隔离，天然支持多租户 |
| **元数据能力** | 创建时一次性配置 Meta 信息抽取规则（常量/变量/LLM/正则/关键词），**创建后不可修改**；支持标签过滤、结构化字段查询 | `AddMemory` / `UpdateMemory` 支持写入任意 `meta_data`（JSON 对象）；`ListMemory` 返回完整 `meta_data`；其他接口不透出，灵活性更高 |
| **时效性与生命周期** | 内容静态为主；更新需重新索引（异步任务）；无自动过期机制，需人工维护 | 记忆片段与用户画像**无自动过期**；需业务侧通过 `DeleteMemory` 或定时任务主动清理 |
| **典型场景** | • 客服知识问答（产品手册、FAQ、工单记录）<br>• 法律/医疗文档辅助解读<br>• 多源财报/研报联合分析<br>• 音视频内容语义搜索（如会议录像关键片段定位） | • 智能客服中持续记住用户偏好（“上次说过敏，推荐无坚果方案”）<br>• 个人助理中积累日程、习惯、关系网络<br>• 教育应用中跟踪学生知识点掌握状态<br>• 销售助手自动归纳客户历史沟通要点 |

## 适用场景建议

### ✅ 选择知识库，当您需要：
- 向模型注入**组织级、领域级、非用户专属**的权威知识（如企业制度、行业规范、产品文档）；
- 处理**多模态原始资料**（扫描件 PDF、培训视频、Excel 表格），并要求跨模态联合检索；
- 实现**高精度、可控性强的 RAG 流水线**（如自定义切片策略、双路召回、Rerank 排序、拒答策略）；
- 支持**多知识库协同路由**（例如：按问题类型自动分发至“技术文档库”或“售后政策库”）；
- 对检索结果的**溯源性、可解释性、合规性**有强要求（需返回原始页码、文件名、高亮位置）。

### ✅ 选择长期记忆（新），当您需要：
- 在**多轮对话中自动沉淀用户个性化信息**（如姓名、地址、饮食禁忌、设备型号、历史投诉点）；
- 构建**轻量级、低延迟、免模型依赖的用户画像**（Profile Schema），并支持实时聚合查询；
- 快速集成**状态感知能力**到智能体中，无需自行设计 LLM 提取 [prompt](../guides/prompt.md) 或管理向量数据库；
- 业务逻辑要求**严格用户数据隔离**，且 `user_id` 已在系统中统一管理；
- 希望规避模型 [Token](../concepts/token.md) 成本与推理延迟，追求**确定性、低成本、高并发的上下文复用**。

### ⚠️ 避免混用或误用：
- ❌ 不要用长期记忆存储产品说明书、合同模板等**通用知识**——缺乏多模态支持、无 Rerank 优化、无法溯源；
- ❌ 不要用知识库存储用户对话摘要或偏好——无 `user_id` 隔离机制，易造成数据混淆与隐私风险；
- ❌ 不要为每个用户单独创建一个知识库——违背知识库“共享知识”的设计初衷，导致资源浪费与管理爆炸；
- ✅ **推荐组合模式**：知识库提供领域底座（What the world knows），长期记忆提供用户上下文（What *this user* knows/wants）；二者可在同一智能体中并行调用，由 Agentic 编排决策优先级。

## 技术选型参考（面向开发者）

| 评估维度 | 知识库 | 长期记忆（新） | 选型建议 |
|----------|--------|----------------|----------|
| **开发门槛** | 中高：需理解 RAG 流水线、配置切片/Meta/召回参数、调试检索质量 | 低：标准 REST API + SDK，`AddMemory`/`SearchMemory` 两步即可启用 | 快速验证用户状态记忆？→ 选长期记忆 |
| **运维复杂度** | 高：需监控索引状态、处理失败切片、定期更新文档、优化相似度阈值 | 低：无索引管理，无版本升级压力，仅需关注 `user_id` 生命周期 | 缺乏专职 AI Infra 团队？→ 优先长期记忆 |
| **扩展性** | 支持 15 个知识库联合检索，旗舰版支持万级 QPS；但单知识库元数据不可变 | 用户级隔离天然水平扩展；QPM 限流为账号级（3000 QPM 总量），适合高并发用户场景 | 百万级 C 端用户？→ 长期记忆更易伸缩 |
| **合规与审计** | 支持文件级权限控制、SLS 日志追踪 `pipeline_id`、完整召回链路审计 | 所有操作带 `user_id`，日志可关联业务主键；但当前不提供细粒度操作审计日志 | 金融/政务强审计需求？→ 知识库更成熟 |
| **成本敏感度** | 需权衡 Rerank 开启与否（影响精度与费用）、模型选型（`qwen-turbo` vs `qwen-plus`） | 当前无 Token 费用，仅调用计费；适合高频轻量查询场景 | 预算有限且查询频次高？→ 长期记忆成本优势明显 |

> 💡 **一句话决策树**：  
> **“这份信息是否属于‘所有人该知道’的常识/规则？” → 用知识库**  
> **“这份信息是否只对‘这个用户’有意义且会随对话变化？” → 用长期记忆（新）**
