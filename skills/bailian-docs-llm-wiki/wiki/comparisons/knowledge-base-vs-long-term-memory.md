# 知识库与[长期记忆](../concepts/memory.md)能力对比

本文旨在帮助开发者清晰区分百炼平台中两大核心数据增强能力：**知识库（Knowledge Base）** 与 **[长期记忆](../concepts/memory.md)（新）（Long Term Memory New）**。二者虽均支持语义检索与结构化信息管理，但设计目标、技术定位与适用边界存在本质差异。知识库面向**领域知识注入与问答增强**，是 RAG 架构的基础设施；而[长期记忆](../concepts/memory.md)面向**用户级状态建模与对话上下文沉淀**，是智能体（Agent）持续理解用户的“记忆中枢”。正确选型可显著降低开发复杂度、避免功能错配，并优化成本与性能。

以下从关键维度进行系统性对比，并提供面向生产落地的技术选型建议。

## 关键维度对比

| 维度 | 知识库（Knowledge Base） | 长期记忆（新）（Long Term Memory New） |
|------|--------------------------|----------------------------------------|
| **核心定位** | 面向**静态/半静态领域知识**的 RAG 基础设施，用于提升大模型在专业场景下的事实准确性与领域覆盖能力 | 面向**动态、个性化用户状态**的记忆管理服务，用于构建用户画像、沉淀对话意图与偏好，支撑多轮交互一致性 |
| **输入格式** | 支持多模态原始文件：PDF/Word/Excel/PPT/Markdown/TXT/图片（OCR）、音视频（ASR）、HTML 等；自动解析为文本切片（chunk），支持自定义分块策略 | 仅支持结构化文本输入：<br>• `messages`：最多 50 条对话记录（role/content 格式）<br>• `custom_content`：≤512 字符纯文本（优先级更高）<br>• 可附加 `meta_data`（键值对） |
| **输出格式** | • 检索结果：带原文引用、相似度得分、来源文档位置的文本切片列表<br>• 问答结果：自然语言回答 + 引用溯源标记（如 `[1][2]`）+ 原文高亮片段<br>• API 返回 JSON，含 `result`、`references`、`usage` 等字段 | • `SearchMemory`：按相似度排序的记忆片段列表，含 `id`、`content`、`score`、`meta_data`、`created_at`<br>• `ListMemory`：分页记忆列表（无重排序）<br>• `GetUserProfile`：基于模板生成的结构化用户画像 JSON |
| **支持模型** | 依赖外部大模型完成最终生成：<br>• **预置模型**：Qwen3/Qwen2.5/Qwen2/Long/Max/Plus/Turbo/Coder/Deep-Research/VL 系列、DeepSeek-R1、Llama3.1、Yi-Large 等<br>• **自定义模型**：基于上述基座微调的私有模型<br>• *所有模型必须部署于华北2（北京）地域* | **模型无关**：语义理解、信息抽取、重排序等均由平台专用服务完成，**不调用用户侧大模型**；开发者无需配置或计费 LLM 调用 |
| **API 端点** | • 控制台集成：通过应用工作流节点接入<br>• SDK/API：`POST /v1/knowledge_bases/{kb_id}/search`（检索）、`POST /v1/knowledge_bases/{kb_id}/chat`（问答）等，域名 `https://dashscope.aliyuncs.com/api/v1/`<br>• 独立服务：发布后获得专属 endpoint（如 `https://xxx.app.bailian.aliyuncs.com/rag-qa`） | 统一 RESTful API：<br>`POST /api/v2/apps/memory/add`<br>`POST /api/v2/apps/memory/search`<br>`GET /api/v2/apps/memory/list`<br>等，域名固定为 `https://dashscope.aliyuncs.com/api/v2/apps/memory/` |
| **计费方式** | **复合计费**：<br>• 知识库规格费（按存储量、RCU QPS 计费）<br>• 向量化费用（首次上传时按文档 [Token](../concepts/token.md) 计费）<br>• 排序费用（按初步召回切片总数 × 切片平均 [Token](../concepts/token.md) × 排序模型单价）<br>• 问答生成费用（按大模型实际输入/输出 [Token](../concepts/token.md) 计费） | **按调用量计费（无模型费用）**：<br>• `AddMemory`、`SearchMemory`、`ListMemory` 等接口按**成功调用次数**计费<br>• 无向量化/排序/生成等衍生费用<br>• 无存储容量费（底层按需弹性扩展） |
| **地域支持** | **仅限中国站华北2（北京）地域**；新加坡、法兰克福等国际地域不可用 | **全地域可用**（与 DashScope API 一致），支持中国站及国际站各 Region |
| **数据生命周期** | • 知识库内容为**静态资产**，更新需重新上传/同步<br>• 切片不可编辑，元数据不可变更<br>• 无自动过期机制，需人工维护 | • 记忆片段与用户画像**长期有效，永不自动过期**<br>• 支持完整 CRUD（增删改查）操作<br>• 业务方需自主管理生命周期（如定期清理过期提醒） |
| **典型场景** | • 客服知识库问答（产品手册、FAQ、工单归档）<br>• 法律/医疗/金融等专业文档辅助决策<br>• 内部 Wiki 或代码库语义搜索<br>• 多源异构数据（合同+表格+截图）联合分析 | • 用户个性化设置（“我的常用地址”、“偏好简体中文”）<br>• 对话中提取的任务项（“明天下午三点会议” → 提醒记忆）<br>• 用户画像构建（消费习惯、技术栈、沟通风格）<br>• 智能体跨会话状态保持（如购物车、待办清单） |

## 各方案的适用场景建议

### ✅ 选择知识库，当您需要：
- 将**大量、稳定、非个人化的专业资料**（如企业制度、产品文档、行业报告、历史合同）注入大模型；
- 要求回答具备**强事实依据与可追溯性**，且需明确标注信息来源；
- 场景对**时效性要求不高**（分钟级/小时级更新即可），但对**知识广度与深度**要求高；
- 已有成熟文档体系，希望零代码或低代码快速构建问答应用；
- 接受地域限制（必须部署在北京），并愿意为向量化、排序、生成等环节分别付费。

### ✅ 选择长期记忆（新），当您需要：
- 在**多轮对话中持续理解并记住用户个体特征**（如姓名、偏好、承诺事项、未完成任务）；
- 构建**轻量级用户画像**用于个性化响应（无需训练专属模型）；
- 实现**跨会话状态延续**（如用户中断后返回，仍记得上一步意图）；
- 输入数据**高度结构化、短文本为主**（如对话摘要、待办条目、标签化元数据）；
- 追求**低成本、低延迟、免模型运维**的记忆管理（不希望为每次记忆操作支付 LLM 费用）；
- 应用需部署在**国际地域**（如新加坡），或需与 DashScope 全域 API 统一鉴权。

### ⚠️ 不推荐混用或替代的情形：
- ❌ **勿用长期记忆替代知识库做领域问答**：其输入长度受限（512 字符）、无多模态支持、无法处理长文档，且缺乏引用溯源能力，无法满足专业问答的可信性要求。
- ❌ **勿用知识库管理用户个性化状态**：知识库无 `user_id` 隔离机制，无法天然支持千万级用户数据隔离；其更新成本高（需重传文档）、无细粒度 CRUD，不适合高频变更的用户状态。
- ❌ **勿期望长期记忆提供 RAG 级别知识覆盖**：它不替代文档解析、不支持表格/图片理解、不集成大模型生成，本质是“记忆”，而非“知识增强”。

## 面向开发者的技术选型参考

| 选型考量 | 推荐方案 | 说明 |
|----------|----------|------|
| **是否需要多模态文档支持？** | 知识库 | 长期记忆仅接受文本输入，无法处理 PDF/Excel/图片等原始文件 |
| **是否需严格引用溯源与拒答控制？** | 知识库 | 提供原文高亮、引用标记、防泄漏、拒答策略；长期记忆仅返回 content 字段，无来源锚点 |
| **是否需支持千万级用户数据隔离与独立查询？** | 长期记忆 | 原生 `user_id` 隔离，`SearchMemory` 默认按 user_id 过滤；知识库无用户维度抽象 |
| **是否追求最低记忆操作延迟与成本？** | 长期记忆 | 单次 `AddMemory`/`SearchMemory` 为毫秒级 HTTP 请求，无 LLM 调用开销；知识库涉及向量检索+排序+LLM 生成，端到端延迟通常 >1s |
| **是否需与现有 DashScope 应用统一鉴权与监控？** | 长期记忆 | 共享 `DASHSCOPE_API_KEY`，指标可纳入 DashScope 控制台统一观测；知识库使用 Bailian 专属 AK/SK 与配额体系 |
| **是否需在非北京地域部署？** | 长期记忆 | 知识库强制华北2，国际业务必须选长期记忆或自建 RAG |
| **是否已有大量结构化用户行为日志需沉淀？** | 长期记忆 | 可直接 `AddMemory` 批量写入；知识库需先转换为文档格式再上传，流程冗余 |

> **最佳实践提示**：  
> - **组合使用更强大**：在智能体架构中，可同时启用两者——用**知识库**提供领域知识底座（如“公司差旅政策”），用**长期记忆**管理用户状态（如“张三已申请过两次北京出差”），二者通过工作流编排协同输出。  
> - **冷热分离原则**：将变化缓慢的公共知识放入知识库，将高频变更的用户私有数据存入长期记忆，实现成本与性能最优平衡。  
> - **权限隔离建议**：知识库适用于团队/部门级共享知识；长期记忆天然按 `user_id` 隔离，适合 SaaS 多租户场景。  

如需进一步评估具体业务需求，建议结合[知识库效果优化指南](https://help.aliyun.com/zh/model-studio/rag-knowledge-base)与[长期记忆 API 参考](https://help.aliyun.com/zh/model-studio/long-term-memory-new)进行原型验证。
