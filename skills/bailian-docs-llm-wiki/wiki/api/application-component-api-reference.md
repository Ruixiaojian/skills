# application component api reference

本 API 参考文档面向开发者，系统性地描述百炼平台 Application Component（应用组件）层提供的核心 OpenAPI 能力，覆盖数据连接（原应用数据）、知识库（Index）及切片（Chunk）三大功能模块。所有接口均基于 `bailian/2023-12-29` 版本，采用 ROA 签名机制，支持多语言 SDK 封装调用。开发者需通过 RAM 子账号最小权限授权，并在指定业务空间内操作资源。

## 支持的模型/功能

Application Component API 主要提供三类能力：

- **数据连接管理**：用于组织和管理原始文件与结构化数据，包括类目（Category）、文件（File）、表格（Table）及连接器（Connector）的增删查改。例如，`AddCategory` 用于创建分类目录，`AddFilesFromAuthorizedOss` 支持从已授权 OSS Bucket 批量导入文件 [原文标题](../../raw/application-api-reference/application-component-api-reference/api-bailian-2023-12-29-dir/api-bailian-2023-12-29-dir-data-connection-original-application-data/api-bailian-2023-12-29-addfilesfromauthorizedoss.md)。
- **知识库（Index）生命周期管理**：覆盖知识库的创建、更新、删除、状态查询及监控。`CreateIndex` 初始化知识库，`SubmitIndexJob` 触发构建任务，`Retrieve` 提供检索能力；`GetIndexMonitor` 则用于获取存储与 QPS 监控指标 [原文标题](../../raw/application-api-reference/application-component-api-reference/api-bailian-2023-12-29-dir/api-bailian-2023-12-29-dir-knowledge-base/api-bailian-2023-12-29-getindexmonitor.md)。
- **文本切片（Chunk）精细化操作**：针对文档搜索类知识库，支持切片的新增（`AddChunk`）、查询（`ListChunks`）、修改（`UpdateChunk`）与删除（`DeleteChunk`）。注意：`UpdateChunk` 和 `DeleteChunk` 仅适用于文档搜索类知识库，不支持数据查询或图片问答类知识库 [原文标题](../../raw/application-api-reference/application-component-api-reference/api-bailian-2023-12-29-dir/api-bailian-2023-12-29-dir-knowledge-base/api-bailian-2023-12-29-updatechunk.md)。

> **注意**：部分文档存在矛盾。文档 36（`AddChunk`）称其支持 document/table/image 三类知识库，但文档 38（`UpdateChunk`）明确限定“仅支持文档搜索类知识库”，且文档 37（`ListChunks`）说明对 table/image 类知识库仅返回“全部文本切片的信息”。实际开发中，请以 `UpdateChunk` 和 `DeleteChunk` 的限制为准，table/image 类知识库的切片管理应通过数据源（如 Excel 表格）变更实现。

## 关键参数

- **`WorkspaceId`**：所有接口的必需路径参数，标识操作所属的业务空间。必须通过控制台或 `ListIndices` 等接口获取，不可猜测。
- **`CategoryId` / `FileId` / `IndexId` / `ChunkId`**：各类资源的唯一标识符，通常由上游接口（如 `AddCategory`, `AddFile`, `CreateIndex`, `ListChunks`）返回。`FileId` 在 `DescribeFile` 和 `DeleteFile` 中使用，而 `ChunkId` 位于 `ListChunks` 返回结果的 `Node.Metadata._id` 字段。
- **`Parser`**（`AddFile` 接口）：指定文档解析器类型，关键值包括 `DOCMIND`（智能文档解析）、`AUTO_SELECT`（自动选择）等。解析器能力与文件类型强相关，可通过 `GetAvailableParserTypes` 查询支持列表。
- **`DocumentStatus`**（`ListIndexDocuments` 等接口）：用于过滤知识库文件状态，常见值有 `FINISH`（索引构建成功）、`PARSE_FAILED`（解析失败）、`INSERT_ERROR`（导入索引失败）等，是判断文件是否可被 `Retrieve` 检索的关键依据。

## 使用方式

1. **环境准备**：创建具备 `AliyunBailianDataFullAccess` 或更细粒度权限（如 `sfm:AddCategory`, `sfm:Retrieve`）的 RAM 子账号，并将其加入目标业务空间。强烈建议遵循最小权限原则，避免使用主账号 AccessKey [原文标题](../../raw/application-api-reference/application-component-api-reference/api-bailian-2023-12-29-ram.md)。
2. **接入点配置**：根据地域选择公网或 VPC 接入地址，例如华北2（北京）的公网地址为 `bailian.cn-beijing.aliyuncs.com` [原文标题](../../raw/application-api-reference/application-component-api-reference/api-bailian-2023-12-29-endpoint.md)。
3. **调用流程**：
   - 数据接入：先调用 `ApplyFileUploadLease` 获取上传租约，再 `AddFile` 导入文件；或直接 `AddFilesFromAuthorizedOss` 从 OSS 导入。
   - 知识库构建：调用 `CreateIndex` 创建知识库 → `SubmitIndexJob` 启动构建 → 用 `GetIndexJobStatus` 轮询状态直至 `FINISH`。
   - 检索与管理：构建完成后，即可用 `Retrieve` 进行查询；用 `ListIndexDocuments` 查看文件列表，`DeleteIndexDocument` 删除特定文件。

## 限制和注意事项

- **幂等性**：`ListCategory`, `DescribeFile`, `ListFile`, `GetIndexJobStatus`, `ListIndices`, `ListIndexDocuments`, `ListIndexFileDetails`, `UpdateIndex`, `DeleteIndex`, `DeleteIndexDocument`, `ListChunks`, `UpdateChunk`, `DeleteChunk` 等接口具有幂等性；而 `AddCategory`, `AddFile`, `ApplyFileUploadLease`, `CreateIndex`, `SubmitIndexJob` 等不具备幂等性，重复调用可能产生冗余资源。
- **限流策略**：各接口有独立的 QPS 限制，例如 `AddCategory` 和 `ListCategory` 为 5 次/秒，`ApplyFileUploadLease` 和 `AddFile` 为 10 次/秒，`ListIndexDocuments` 为 15 次/秒。超限将返回错误，需实现客户端重试逻辑。
- **文件与知识库分离**：`DeleteFile` 仅删除应用数据中的文件，不影响已构建的知识库；反之，`DeleteIndexDocument` 仅删除知识库中的索引切片，不删除原始文件。二者操作互不影响。
- **安全要求**：所有请求必须携带有效的 AccessKey（推荐 RAM 子账号），且建议通过 HTTPS 发送。自签名对接复杂度高，官方强烈推荐使用封装好的 SDK [原文标题](../../raw/application-api-reference/application-component-api-reference/api-bailian-2023-12-29-overview.md)。
