# application component api reference

本 API 参考文档面向开发者，涵盖百炼平台应用组件的核心能力，包括数据连接（应用数据）、知识库、[Prompt 工程](../concepts/prompt-engineering.md)等模块的 OpenAPI。所有接口均基于 `bailian/2023-12-29` 版本，采用 ROA 签名机制，支持多语言 SDK 封装调用。开发者需通过 RAM 用户最小权限原则配置访问控制，并使用业务空间（Workspace）隔离资源。

## 支持的模型/功能

应用组件 API 主要支撑三类核心能力：

- **数据连接（原应用数据）**：提供类目管理（`AddCategory`/`ListCategory`/`DeleteCategory`）、文件全生命周期操作（`ApplyFileUploadLease` → `AddFile` → `DescribeFile` → `DeleteFile`）、OSS 批量导入（`AddFilesFromAuthorizedOss`）、标签管理（`UpdateFileTag`/`BatchUpdateFileTag`）及解析器配置（`GetParseSettings`/`ChangeParseSetting`/`GetAvailableParserTypes`）。注意：**不支持通过 API 新增或删除数据表**，该操作仅限控制台完成 [原文标题](../../raw/application-api-reference/application-component-api-reference/api-bailian-2023-12-29-dir/api-bailian-2023-12-29-dir-data-connection-original-application-data/api-bailian-2023-12-29-addcategory.md)。

- **知识库（Index）**：覆盖非结构化（文档/音视频）与结构化（数据查询/图片问答）两类知识库的创建（`CreateIndex`）、更新（`UpdateIndex`）、删除（`DeleteIndex`）、检索（`Retrieve`）、文件管理（`ListIndexDocuments`/`DeleteIndexDocument`）及底层切片操作（`ListChunks`/`AddChunk`/`UpdateChunk`/`DeleteChunk`）。需注意：`CreateIndex` 仅初始化作业，**必须后续调用 `SubmitIndexJob` 才能完成创建** [原文标题](../../raw/application-api-reference/application-component-api-reference/api-bailian-2023-12-29-dir/api-bailian-2023-12-29-dir-knowledge-base/api-bailian-2023-12-29-createindex.md)。

- **[Prompt 工程](../concepts/prompt-engineering.md)**：提供 Prompt 模板的完整 CRUD 能力（`CreatePromptTemplate`/`GetPromptTemplate`/`ListPromptTemplates`/`UpdatePromptTemplate`/`DeletePromptTemplate`），支持变量注入与类型区分（System/Custom）。**暂不支持文生图 Prompt 模板的创建** [原文标题](../../raw/application-api-reference/application-component-api-reference/api-bailian-2023-12-29-dir/api-bailian-2023-12-29-dir-prompt-engineering/api-bailian-2023-12-29-createprompttemplate.md)。

> **注意**：文档 4 中列出的 `CreateIndex` 和 `Retrieve` 接口在 2026-03-30 发生变更，但原始文档未明确说明变更细节是否影响当前行为；实际调用前请以最新版 OpenAPI Explorer 文档为准。

## 关键参数

- **通用路径参数**：几乎所有接口均要求 `WorkspaceId`（业务空间 ID），用于资源隔离与权限校验，获取方式见 [如何使用业务空间](https://help.aliyun.com/zh/model-studio/use-workspace)。

- **身份认证**：所有请求需携带阿里云 AccessKey（建议使用 RAM 子账号并遵循最小权限原则），签名方式为 ROA。自签名对接复杂度高，官方强烈推荐使用 SDK [原文标题](../../raw/application-api-reference/application-component-api-reference/api-bailian-2023-12-29-overview.md)。

- **幂等性控制**：`DeleteCategory`、`ListCategory`、`DescribeFile`、`GetParseSettings`、`GetIndexJobStatus`、`Retrieve`、`ListIndexDocuments`、`ListIndexFileDetails`、`UpdateIndex`、`DeleteIndexDocument`、`DeleteIndex`、`UpdateChunk`、`DeleteChunk` 等接口声明具备幂等性；而 `AddCategory`、`ApplyFileUploadLease`、`AddFile`、`AddFilesFromAuthorizedOss`、`CreateIndex`、`SubmitIndexAddDocumentsJob` 等则不具备，重复调用可能导致重复资源创建。

- **分页与令牌**：`ListCategory`、`ListFile`、`ListPromptTemplates` 等列表接口使用 `NextToken` + `MaxResults` 实现基于令牌的分页，而非传统 `PageNumber`/`PageSize`。

- **限流阈值**：多数接口限流为 5~10 次/秒，`ListIndexDocuments` 较宽松（15 次/秒）。超出将返回限流错误，需实现退避重试逻辑。

## 使用方式

1. **环境准备**：  
   - 创建 RAM 用户并授予 `AliyunBailianDataFullAccess`（读写）或 `AliyunBailianDataReadOnlyAccess`（只读）策略；  
   - 将 RAM 用户加入目标业务空间；  
   - 获取 `WorkspaceId`、`AccessKeyId`、`AccessKeySecret`。

2. **调用流程示例（文件上传）**：  
   ```text
   ApplyFileUploadLease → (获取 LeaseId) → AddFile → (获取 FileId) → DescribeFile
   ```  
   其中 `ApplyFileUploadLease` 需指定 `CategoryId`（或 `default`），`AddFile` 需传入 `LeaseId` 和 `Parser`（如 `DOCMIND`）。

3. **知识库构建流程**：  
   ```text
   CreateIndex → SubmitIndexJob → GetIndexJobStatus（轮询）→ Retrieve
   ```  
   追加文件时：`AddFile` → `SubmitIndexAddDocumentsJob` → `GetIndexJobStatus`。

4. **调试与生成代码**：所有接口均支持在 [OpenAPI Explorer](https://api.aliyun.com) 直接调试并自动生成各语言 SDK 示例代码。

## 限制和注意事项

- **安全要求**：严禁使用主账号 AccessKey；OSS Bucket 必须与百炼同属一主账号，且需按文档完成授权；开启 Referer 防盗链的 Bucket 需白名单 `*.console.aliyun.com`。

- **功能边界**：  
  - `DeleteFile` 仅删除应用数据中的文件，**不影响已构建的知识库内容**；删除知识库内文件需调用 `DeleteIndexDocument`。  
  - `DeleteIndex` 不会删除关联的应用数据文件，二者资源独立。  
  - `AddChunk`/`UpdateChunk`/`DeleteChunk` 对音视频搜索类知识库无效；`UpdateChunk` 仅支持文档搜索类知识库。

- **版本兼容性**：文档 4 明确记录了 `CreateIndex`、`Retrieve`、`UpdateIndex` 等接口在 2026 年存在多次变更（如入参、返回结构），**生产环境务必确认所用 SDK 或手动签名逻辑与当前服务端版本一致**。

- **错误处理**：各接口均定义了标准 HTTP 状态码与业务错误码（如 `PromptTemplate.ContentInvalid`、`Index.Forbidden`），建议捕获并解析 `Code` 字段进行精细化错误处理。
